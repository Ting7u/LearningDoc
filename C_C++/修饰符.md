**先建立三个概念**

| 概念                    | 含义                  | 回答的问题            |
| --------------------- | ------------------- | ---------------- |
| 作用域（scope）            | 名字在代码的哪个范围内可见       | 在哪能用这个名字？        |
| 链接性（linkage）          | 不同文件里的同名标识符是不是同一个东西 | 别的 `.c` 文件能不能访问？ |
| 存储期（storage duration） | 对象的生命周期             | 它什么时候创建、什么时候销毁？  |
**链接性有三种**
- **外部链接（external）**：整个程序共享同一个实体，多个 `.c` 文件可以互相访问
- **内部链接（internal）**：只在当前 `.c` 文件（翻译单元）内有效
- **无链接（none）**：局部变量，只在自己的代码块内有效

`static`、`extern` 等关键字，本质上就是在调整这三者

## 1. 存储类说明符一览

C 语言的存储类说明符有：`auto`、`register`、`static`、`extern`、`typedef`（语法上归为此类，实际是起别名）、`_Thread_local`（C11）

## 2. static 

`static` 在不同位置含义不同

### 2.1. 修饰局部变量（改变存储期）

```c
void counter(void) {
    static int n = 0;   // 只初始化一次
    n++;
    printf("%d\n", n);
}
// 连续调用三次：1, 2, 3
```

- 存储期变成静态存储期，放在全局区（.data 或 .bss），生命周期是整个程序
- 作用域不变，仍然只能在这个函数内访问
- 初始化只发生一次，初始值必须是常量表达式
- 不显式初始化时自动为 0

典型用途：记录函数被调用的次数、保存上一次的状态

### 2.2. 修饰全局变量（改变链接性）

```c
// a.c
static int g = 10;   // 只有 a.c 能访问
int h = 20;          // 其他文件可以通过 extern 访问
```

- 存储期本来就是静态的，不变。
- 链接性从外部变成内部：其他 `.c` 文件即使写了 `extern int g;` 也找不到它，链接时会报错。
- 作用：隐藏实现细节，避免不同文件的同名全局变量冲突
### 2.3. 修饰函数（改变链接性）

```c
// a.c
static void helper(void) { ... }   // 只有 a.c 内部能调用
void api(void) { helper(); }       // 对外提供的函数
```

- 和修饰全局变量一样，把函数变成内部链接
- 两个 `.c` 文件里可以各自有一个同名的 `static` 函数，互不冲突
- 写模块时的好习惯：不对外暴露的函数都加 `static`
### 2.4. static 总结

|修饰对象|改变了什么|效果|
|---|---|---|
|局部变量|存储期|生命周期延长到整个程序，值保留|
|全局变量|链接性|只限本文件使用|
|函数|链接性|只限本文件使用|
一句话记忆：**局部变量加 static 是"活得久"，全局变量和函数加 static 是"藏起来"**

## 3. extern：声明，不是定义

**先分清"声明"和"定义"**

```c
int a;          // 通常是定义（分配内存）
int a = 10;     // 一定是定义
extern int a;   // 声明：告诉编译器"这个变量在别处定义了"，不分配内存
```

- **定义**：分配内存，整个程序里只能有一次
- **声明**：只是告诉编译器名字和类型，可以有很多次

**典型用法：跨文件共享全局变量**

```c
// config.c
int g_score = 100;          // 定义（只在这里一次）

// main.c
#include <stdio.h>
extern int g_score;         // 声明：g_score 在别的文件里
int main(void) {
    printf("%d\n", g_score);   // 链接时会找到 config.c 里的那一个
    return 0;
}
```

**用于函数**

函数声明默认就带 `extern`，所以下面两行等价：

```c
void foo(void);
extern void foo(void);
```

**extern 的几个要点**
1. `extern int a = 10;` 虽然语法允许，但带了初始值就变成定义了，编译器可能给警告，不要这么写
2. 如果 `extern` 声明的变量在任何文件里都没有定义，编译能通过，链接时报错（`undefined reference` 或 `unresolved external symbol`）
3. 如果同一个变量在两个文件里都有定义，链接时报重复定义错误
4. 如果变量被另一个文件声明为 `static`，`extern` 找不到它（见上面 static 部分）
### 3.1 头文件的正确写法（经典坑）

```c
// ❌ 错误：在头文件里直接定义变量
// config.h
// 每个 include 它的 .c 文件都会生成一份定义 → 链接时重复定义
int g_score = 100;

// ✅ 正确：头文件只声明，.c 文件里定义
// config.h
extern int g_score;
// config.c
int g_score = 100;
```

**再看另一种情况**

```c
// config.h
// 不会报重复定义，但每个 .c 文件各有一份独立的副本！
static int g_score = 100;   
```

这不会报错，但各个文件修改的是各自的副本，互不影响，往往不是你想要的效果。所以：头文件里放 `extern` 声明，定义放在一个 `.c` 文件里

>补充：`static` 函数加上 `inline` 写在头文件里（`static inline`）是常见做法，不会冲突

## 4. extern 与 static 对比

|        | `static`（全局/函数） | `extern`   |
| ------ | --------------- | ---------- |
| 链接性    | 内部链接，仅本文件可见     | 外部链接，跨文件共享 |
| 作用     | 隐藏、避免命名冲突       | 引用别处定义的实体  |
| 是否分配内存 | 是（它是定义）         | 否（它只是声明）   |
## 5. auto

```c
auto int x = 10;   // 等价于 int x = 10;
```

- 局部变量默认就是 `auto`，所以几乎没人写，是历史遗留。
- 只能用于局部变量
- 补充：C23 标准里，`auto` 被赋予了新含义（类型推导，类似 C++11），但这取决于你的编译器是否支持 C23，学习阶段不用管
## 6. register

```c
register int i;
for (i = 0; i < 1000000; i++) { ... }
```

- 建议编译器把变量放进寄存器以提高速度
- 只是建议，现代编译器的优化做得比人好，基本无视这个关键字
- 有一个硬性限制：不能对 `register` 变量取地址（`&i` 会编译错误），因为寄存器没有内存地址
- 现代开发中几乎不用
## 7. const：只读修饰

```c
const int a = 10;
```

- 告诉编译器"不要通过这个名字修改它"。
- 它不属于存储类说明符，而是**类型限定符**，不决定存放区域（详见上一个问题中的 const 部分）。
- 可以与 `static`、`extern` 组合：

```c
static const int MAX = 100;   // 本文件内的只读常量
extern const int LIMIT;       // 声明别处定义的只读常量
```

**C 与 C++ 的差异：** C 里全局 `const` 默认是**外部链接**，C++ 里默认是**内部链接**。所以在 C++ 里跨文件共享 const 全局变量，需要写 `extern const int LIMIT = 10;` 来定义。这和 C 的行为不同，两门语言切换时要留意

## 8. volatile：禁止优化

```c
volatile int flag = 0;
while (flag == 0) { }   // 每次循环都会重新从内存读取 flag
```

- 告诉编译器"这个变量的值可能在你不知道的情况下被改变"，**每次都必须真正读写内存，不能优化缓存到寄存器里**
- 典型用途：硬件寄存器、中断服务函数中修改的变量、信号处理函数
- 常见误区：`volatile` 不能保证多线程下的线程安全，也不是原子操作。多线程要用互斥锁或 C11 的 `_Atomic`
- 做游戏、写应用层程序时，基本用不到
## 9. inline：建议内联

```c
static inline int max(int a, int b) { return a > b ? a : b; }
```

- C99 引入，建议编译器把函数调用直接展开成函数体，减少调用开销
- 同样只是建议，编译器可自行决定
- C 语言里 `inline` 的链接规则比较复杂（和 C++ 不同），初学阶段只需要记住：在头文件里写短小的工具函数，用 `static inline`，最不容易出问题
## 10. restrict：指针别名承诺

```c
void copy(int *restrict dst, const int *restrict src, int n);
```

- C99 引入，用在指针上，向编译器承诺"这块内存只会通过这个指针访问"，让编译器可以做更激进的优化
- 如果你违背承诺（两个指针实际指向重叠的内存），行为未定义
- 标准库的 `memcpy` 的参数就带 `restrict`，这也是为什么 `memcpy` 不能用于内存重叠的情况（重叠时应该用 `memmove`）
- 学习阶段了解即可
## 11. typedef：起别名

```c
typedef unsigned int uint;
typedef struct Student { ... } Student;
```

- 语法上属于存储类说明符，但它不创建变量、不影响存储，只是给类型起一个新名字
- 所以它不能和 `static`、`extern` 等同时使用，不能写 `static typedef`
## 12. `_Thread_local`（了解即可）

```c
_Thread_local int counter; // C11：每个线程各有一份独立的副本
```

- 线程存储期：每个线程有自己独立的一份变量
- 学到多线程时再接触
## 13. 汇总对照表

| 关键字             | 用于       | 作用              | 常用程度     |
| --------------- | -------- | --------------- | -------- |
| `static`（局部变量）  | 局部变量     | 生命周期延长到整个程序，值保留 | 常用       |
| `static`（全局/函数） | 全局变量、函数  | 内部链接，仅本文件可见     | 常用       |
| `extern`        | 变量、函数    | 声明在别处定义的实体      | 常用       |
| `const`         | 变量、指针、参数 | 禁止通过该名字修改       | 常用       |
| `auto`          | 局部变量     | 默认值，无实际作用       | 几乎不用     |
| `register`      | 局部变量     | 建议放寄存器，不能取地址    | 几乎不用     |
| `volatile`      | 变量       | 禁止编译器缓存优化       | 嵌入式 / 底层 |
| `inline`        | 函数       | 建议内联展开          | 偶尔       |
| `restrict`      | 指针       | 承诺无别名，便于优化      | 偶尔       |
| `typedef`       | 类型       | 起别名             | 常用       |
