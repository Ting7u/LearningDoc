# 第 9 章　权限、用户与常用系统工具

## 本章目标

- 理解 Linux/Unix 的权限模型，会用 `chmod`、`chown`、`umask`、`sudo`
- 会查看磁盘和系统资源：`df`、`du`、`free`
- 会用网络与传输工具：`curl`、`wget`、`ssh`、`scp`、`rsync`
- 会用 `cron` 设置定时任务
- 会用 `tar`、`gzip`、`zip` 压缩与归档

> 本章以 **Linux（GNU 工具）** 为主，凡是和 macOS（BSD 工具）不同的地方都会标出。
> 拿不准时以本机的 `man 命令名` 为准。

## 9.1 权限模型

### 回顾 `ls -l`

```
-rwxr-xr-- 1 alice staff 1234 Nov 22 10:00 run.sh
```

第一列 `-rwxr-xr--` 拆开：

```
-    rwx    r-x    r--
类型  属主    属组    其他人
      (u)    (g)    (o)
```

- 第 1 个字符：文件类型（`-` 普通文件，`d` 目录，`l` 符号链接）
- 后面 9 个字符分三组：**属主（user）**、**属组（group）**、**其他人（other）**
- 每组三位：`r` 读、`w` 写、`x` 执行，没有权限的位用 `-` 占位

系统判断一个进程对某个文件有什么权限时，**只用最先匹配到的那一组**：是属主就看属主位，否则是属组成员就看属组位，否则看其他人位。（`root` 用户基本不受这些限制。）

### 权限对文件和目录的含义不同

| 权限 | 对普通文件 | 对目录 |
|:---:|-----------|--------|
| `r` | 能读内容 | 能**列出**目录里的文件名（`ls`） |
| `w` | 能修改内容 | 能在目录里**创建、删除、重命名**文件（需要同时有 `x`） |
| `x` | 能作为程序执行 | 能**进入**目录（`cd`），能访问目录里的文件 |

两个容易被忽略的结论：

1. **删除一个文件，看的是它所在目录的 `w` 权限**，而不是文件本身的权限。
2. 一个目录没有 `x`，即使你知道里面文件的完整路径，也无法访问它们。

### 用数字表示权限（八进制）

`r=4`、`w=2`、`x=1`，把每一组的数字加起来，三组连写成三位数：

| 数字 | 二进制 | 含义 |
|:---:|:---:|:---:|
| 7 | 111 | rwx |
| 6 | 110 | rw- |
| 5 | 101 | r-x |
| 4 | 100 | r-- |
| 0 | 000 | --- |

常见组合：

| 数字 | 符号 | 典型用途 |
|:---:|:---:|---------|
| `644` | `rw-r--r--` | 普通文件 |
| `755` | `rwxr-xr-x` | 可执行文件、普通目录 |
| `600` | `rw-------` | 私密文件（如 SSH 私钥） |
| `700` | `rwx------` | 私密目录（如 `~/.ssh`） |

### 查看自己的身份

```bash
whoami                  # 当前用户名
id                      # uid、gid 和所属的所有组
groups                  # 所属的组
```

## 9.2 `chmod`：修改权限

### 数字方式

```bash
chmod 644 notes.txt     # rw-r--r--
chmod 755 run.sh        # rwxr-xr-x
chmod 600 secret.key    # rw-------
chmod -R 755 mydir      # -R：递归修改目录及其内容
```

### 符号方式：`谁 操作 权限`

- **谁**：`u` 属主、`g` 属组、`o` 其他人、`a` 所有人
- **操作**：`+` 添加、`-` 去掉、`=` 设置为恰好是
- **权限**：`r`、`w`、`x`

```bash
chmod u+x run.sh        # 给属主加执行权限
chmod go-w file         # 去掉属组和其他人的写权限
chmod a+r file          # 所有人可读
chmod u=rwx,go=rx file  # 等价于 755
chmod +x run.sh         # 没写"谁"时，相当于 a，但会受 umask 影响（见 9.4）
```

### 递归时区分文件和目录

对一棵目录树统一设成 `755` 会让所有普通文件都变成可执行，这通常不是你想要的。常见的做法：

```bash
find mydir -type d -exec chmod 755 {} +      # 目录 755
find mydir -type f -exec chmod 644 {} +      # 文件 644
```

另一种写法：`chmod -R u=rwX,go=rX mydir`，其中大写的 `X` 表示"只给目录（或已经有执行位的文件）加执行权限"。

### 用 `chmod +x` 运行脚本

回忆第 1 章：`./hello.sh` 报 `Permission denied`，就是因为没有执行权限：

```bash
chmod +x hello.sh
./hello.sh
```

## 9.3 `chown` 和 `chgrp`：修改属主和属组

```bash
sudo chown alice file             # 属主改为 alice
sudo chown alice:staff file       # 属主 alice，属组 staff
sudo chown :staff file            # 只改属组
sudo chown -R alice:staff mydir   # 递归
chgrp staff file                  # 只改属组（需要你是该组成员）
```

普通用户**不能**把文件送给别人（改属主），这通常需要 `root` 权限。

## 9.4 `umask`：新建文件的默认权限

新建文件时的权限不是随便定的，由 **umask** 决定：

- 新文件的最大默认权限是 `666`（`rw-rw-rw-`），新目录是 `777`
- 实际权限 = 最大默认权限 **去掉** umask 中为 1 的那些位

```bash
umask                   # 显示当前 umask，常见是 0022 或 022
```

umask 为 `022` 时：

- 新文件：`666` 去掉 `022` → `644`
- 新目录：`777` 去掉 `022` → `755`

```bash
umask 022
touch f1 && mkdir d1
stat -c '%a %n' f1 d1   # GNU stat：显示数字权限，输出 644 f1 / 755 d1
                        # macOS 用：stat -f '%Lp %N' f1 d1
```

umask 为 `077` 时，新建的文件只有自己能读写（`600`），目录是 `700`。在脚本里想让新创建的文件保持私密，可以先 `umask 077`。

## 9.5 特殊权限位（了解即可）

| 位 | 作用 | 例子 |
|----|------|------|
| setuid（`s`，在属主的 `x` 位） | 程序运行时拥有**文件属主**的身份 | `passwd` 命令需要修改系统密码文件，靠它实现 |
| setgid（`s`，在属组的 `x` 位） | 程序以文件属组身份运行；对目录：新文件继承目录的属组 | 共享目录 |
| sticky（`t`，在其他人的 `x` 位） | 目录里的文件只有属主（或目录属主、root）才能删除 | `/tmp` |

```bash
ls -ld /tmp             # 通常显示 drwxrwxrwt，末尾的 t 就是 sticky 位
```

`/tmp` 对所有人都是 `rwx`，如果没有 sticky 位，任何人都能删别人的文件；有了它，你只能删自己的。

## 9.6 `sudo` 与 `su`

### `sudo`：以另一个用户（默认是 root）身份运行一条命令

```bash
sudo apt update                  # 以 root 身份运行（apt 是 Debian/Ubuntu 的包管理器，仅举例）
sudo -u alice whoami             # 以 alice 身份运行
sudo -l                          # 列出你被允许用 sudo 执行什么
sudo !!                          # 用 sudo 重新执行上一条命令（第 2 章）
```

使用原则：

- 只在**确实需要**的那一条命令前加 `sudo`，不要图省事一直用 root
- 对不熟悉的命令，尤其是带 `rm`、`chmod -R`、`chown -R` 的，先搞清楚路径再执行
- **重定向不受 `sudo` 影响**：`sudo echo x > /etc/foo` 的 `>` 是你自己的 Shell 做的（第 3 章讲过），应该写成 `echo x | sudo tee /etc/foo`
- 编辑 sudo 配置要用 `visudo`，它会在保存前检查语法，避免把自己锁在外面

### `su`

`su - alice` 切换成另一个用户（`-` 表示同时加载该用户的登录环境）。日常更常用 `sudo`。

## 9.7 磁盘与资源：`df`、`du`、`free`

### `df`：各文件系统的空间

```bash
df -h                   # -h：用 K/M/G 显示
df -h .                 # 当前目录所在的文件系统
df -i                   # 看 inode 使用情况（小文件特别多时可能 inode 先用完）
```

输出常见的列：`Filesystem`（设备）、`Size`、`Used`、`Avail`、`Use%`、`Mounted on`。

### `du`：目录或文件占了多少空间

```bash
du -sh mydir            # -s：只显示总计；-h：易读单位
du -h -d 1 .            # 只看一层子目录的占用（-d 1）
du -h -d 1 . | sort -h  # 再按大小排序（sort -h 能理解 K/M/G）
du -sh *                # 当前目录下每一项的大小（注意隐藏文件不会被 * 匹配）
```

> `-d 1` 在较新的 GNU du 和 BSD du 上都能用；老版本 GNU du 用 `--max-depth=1`。
> `sort -h` 在 GNU sort 上可用，较老的 BSD sort 可能没有，遇到时以本机为准。

`df` 说"满了"，下一步通常是用 `du` 找出是谁占的：

```bash
du -h -d 1 /var 2>/dev/null | sort -h | tail -n 5     # 看 /var 下占用最大的 5 项
```

### `free`：内存使用（Linux）

```bash
free -h                 # 内存和交换分区的使用情况
```

关注 `available` 这一列：它估算的是"不用换页就能给新程序用的内存"，比 `free` 列更有参考价值，因为系统会把空闲内存用作文件缓存。

> macOS **没有** `free`，可用 `vm_stat`、`top -l 1`（输出格式不同）。

### 其他常用的资源命令

```bash
uptime                  # 运行时长和平均负载
nproc                   # CPU 核心数（Linux；macOS 用 sysctl -n hw.ncpu）
```

## 9.8 网络与传输

### `curl`：命令行 HTTP 客户端

```bash
curl https://example.com                      # 输出响应内容到屏幕
curl -o page.html https://example.com         # 保存到指定文件名
curl -O https://example.com/file.zip          # 保存成远程的文件名
curl -L https://example.com                   # -L：跟随重定向
curl -I https://example.com                   # -I：只看响应头
curl -s https://example.com                   # -s：安静模式，不显示进度条
curl -fsSL https://example.com/x.sh -o x.sh   # 脚本里的常见组合，见下
```

脚本里常用 `-fsSL` 组合：

| 选项 | 作用 |
|:---:|------|
| `-f` | 服务器返回 4xx/5xx 时让 `curl` **以失败状态退出**（否则它只管下载，错误页面也算"成功"） |
| `-s` | 不显示进度条 |
| `-S` | 配合 `-s`：出错时仍然显示错误信息 |
| `-L` | 跟随重定向 |

发送请求与取状态码：

```bash
curl -X POST -H "Content-Type: application/json" \
     -d '{"name":"alice"}' https://example.com/api

code=$(curl -s -o /dev/null -w '%{http_code}' https://example.com)
echo "HTTP 状态码: $code"
```

其他常用：`--retry 3`（失败重试）、`--connect-timeout 5`、`-m 30`（总超时 30 秒）。

> ⚠️ 不要养成 `curl 某网址 | bash` 的习惯：你在直接执行一段来自网络的、没看过的代码。更稳妥的做法是先下载到文件，看过再运行。

### `wget`

```bash
wget https://example.com/file.zip             # 下载
wget -c https://example.com/big.iso           # -c：断点续传
wget -O out.html https://example.com          # -O：指定输出文件名
```

`wget` 不是每个系统都预装（macOS 默认没有），`curl` 更普遍。

### `ssh`：安全地登录远程机器

```bash
ssh alice@192.168.1.10                  # 登录
ssh -p 2222 alice@host                  # 指定端口（小写 p）
ssh -i ~/.ssh/mykey alice@host          # 指定私钥
ssh alice@host 'df -h'                  # 在远程执行一条命令，输出回到本地
ssh alice@host 'cd /var/log && tail -n 3 syslog'
```

用**密钥**代替密码登录：

```bash
ssh-keygen -t ed25519                   # 生成密钥对：~/.ssh/id_ed25519（私钥）和 .pub（公钥）
ssh-copy-id alice@host                  # 把公钥装到远程的 ~/.ssh/authorized_keys
ssh alice@host                          # 之后免密码登录
```

这里就用到了本章的权限知识：SSH 对权限很挑剔，私钥必须只有你自己能读：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
```

权限太宽松时 `ssh` 会拒绝使用私钥（报 `UNPROTECTED PRIVATE KEY FILE`）。

**私钥绝不能发给别人、不要提交到代码仓库**；公钥（`.pub`）才是可以分享的。

给常用主机起别名，写进 `~/.ssh/config`：

```
Host dev
    HostName 192.168.1.10
    User alice
    Port 2222
    IdentityFile ~/.ssh/id_ed25519
```

之后只需要 `ssh dev`。

### `scp`：基于 ssh 的文件复制

```bash
scp file.txt alice@host:/tmp/                 # 本地 → 远程
scp alice@host:/var/log/app.log .             # 远程 → 本地
scp -r mydir alice@host:/tmp/                 # -r：复制目录
scp -P 2222 file.txt alice@host:/tmp/         # 指定端口：注意是大写 P（和 ssh 的小写 p 相反）
```

### `rsync`：增量同步（更推荐）

`rsync` 只传输**有变化**的部分，适合备份和同步。

```bash
rsync -av src/ dest/                          # 本地同步
rsync -avz src/ alice@host:/backup/           # 同步到远程，-z 压缩传输
rsync -avn src/ dest/                         # -n：只演示不执行（dry run），先看会做什么
rsync -av --delete src/ dest/                 # 让 dest 和 src 完全一致，多余的文件会被删掉
rsync -av --exclude='*.log' src/ dest/        # 排除某些文件
```

常用选项：`-a` 归档模式（递归并保留权限、时间等属性），`-v` 显示过程，`-z` 压缩，`-P` 显示进度并支持续传。

⚠️ **尾部斜杠（`/`）的含义非常重要**：

```bash
rsync -av src  dest/       # 把目录 src 本身放进 dest：得到 dest/src/...
rsync -av src/ dest/       # 把 src 里的内容放进 dest：得到 dest/...
```

⚠️ `--delete` 会删除目标里多余的文件：**先加 `-n` 看一遍**，确认无误再去掉 `-n` 执行。

## 9.9 `cron`：定时任务

`cron` 是按时间表周期性运行命令的服务，用 `crontab` 命令管理你自己的定时任务。

```bash
crontab -l              # 列出你当前的定时任务
crontab -e              # 用编辑器编辑
crontab -r              # ⚠️ 删除全部定时任务，没有确认提示
```

### 时间表的格式

每行一个任务，前 5 个字段是时间，后面是要运行的命令：

```
┌──────── 分钟 (0-59)
│ ┌────── 小时 (0-23)
│ │ ┌──── 日 (1-31)
│ │ │ ┌── 月 (1-12)
│ │ │ │ ┌ 星期 (0-7，0 和 7 都是周日)
│ │ │ │ │
* * * * *  命令
```

| 写法 | 含义 |
|------|------|
| `*` | 每一个 |
| `*/5` | 每隔 5 个单位 |
| `1,15` | 列表：第 1 和第 15 |
| `1-5` | 范围：1 到 5 |

例子：

```
0 2 * * *      /home/alice/backup.sh        # 每天凌晨 2:00
*/10 * * * *   /home/alice/check.sh         # 每 10 分钟
30 8 * * 1-5   /home/alice/report.sh        # 工作日（周一到周五）8:30
0 0 1 * *      /home/alice/monthly.sh       # 每月 1 日零点
@reboot        /home/alice/on_boot.sh       # 开机时（@reboot 等简写在常见的 cron 实现里可用，不是所有版本都支持）
```

### 使用 cron 的注意事项（新手最容易踩坑）

1. **cron 的环境很干净**：`PATH` 通常只有很短的几个目录，没有你登录后 `.bashrc` 里设置的东西。
   - 脚本里用**绝对路径**，或在脚本开头设置 `PATH`
   - 脚本要有执行权限，并写好 shebang
2. **命令的输出**：cron 默认会把输出邮寄给用户（多数系统上没人看）。建议自己重定向到日志（第 3 章）：

   ```
   0 2 * * *  /home/alice/backup.sh >> /home/alice/backup.log 2>&1
   ```
3. **`%` 在 crontab 里是特殊字符**（表示换行），命令中的 `%` 要写成 `\%`：

   ```
   0 2 * * *  tar -czf /backup/data-$(date +\%F).tar.gz /data
   ```
4. **防止重复运行**：任务执行时间可能超过间隔，用第 8 章的锁文件或 `flock`。
5. **先手动运行一遍脚本**，确认脚本本身没问题，再放进 crontab。
6. 在 macOS 上 cron 仍然可用，但系统更推荐用 `launchd`；Linux 上除了 cron，还有 systemd timer 这类替代方案（本教程不展开）。

## 9.10 压缩与归档：`tar`、`gzip`、`zip`

先区分两个概念：

- **归档**：把多个文件/目录打包成**一个文件**（不一定压缩），`tar` 干这个
- **压缩**：减小文件体积，`gzip`、`xz`、`zip` 等

### `tar`

常用选项：

| 选项 | 含义 |
|:---:|------|
| `-c` | 创建归档（create） |
| `-x` | 解开归档（extract） |
| `-t` | 列出归档内容（list） |
| `-f 文件` | 指定归档文件名（**必须紧跟文件名**） |
| `-z` | 用 gzip 压缩/解压 |
| `-v` | 显示过程 |
| `-C 目录` | 切换到目录再操作 |

```bash
tar -czf backup.tar.gz mydir/                 # 打包并 gzip 压缩
tar -tzf backup.tar.gz                        # 查看内容（不解开）
tar -xzf backup.tar.gz                        # 解压到当前目录
tar -xzf backup.tar.gz -C /tmp/restore        # 解压到指定目录（目录要先存在）
tar -czf logs.tar.gz --exclude='*.tmp' logs/  # 排除某些文件
```

记忆：**c**reate / e**x**tract / lis**t**；`z` 是 gzip；`f` 后面接文件名。

⚠️ 几点注意：

- **解压前先用 `-t` 看一眼**：不明来源的归档可能有大量文件，或者带有指向意外位置的路径。
- `tar` 默认会把你给的路径原样放进归档。想让归档里只有 `mydir/...` 而不带上层路径，用 `-C`：

  ```bash
  tar -czf backup.tar.gz -C /home/alice mydir       # 归档内路径是 mydir/...，而不是 home/alice/mydir/...
  ```
- 较新的 GNU tar 解压时能自动识别压缩格式，`tar -xf backup.tar.gz` 就行；为了兼容，写上 `z` 也没问题。
- 其他压缩格式：`-j`（bzip2，`.tar.bz2`）、`-J`（xz，`.tar.xz`）。

### `gzip` / `gunzip`

`gzip` 只压缩**单个文件**，并且默认会**替换**原文件：

```bash
gzip notes.txt              # 得到 notes.txt.gz，原文件被删除
gunzip notes.txt.gz         # 还原，.gz 被删除
gzip -k notes.txt           # -k：保留原文件（需要较新版本的 gzip）
zcat notes.txt.gz           # 不解压，直接输出内容；也可配合 grep、less 使用
gzip -9 notes.txt           # 最高压缩率（-1 最快，-9 最小）
```

### `zip` / `unzip`

```bash
zip -r project.zip project/       # 压缩目录
unzip project.zip                 # 解压
unzip -l project.zip              # 列出内容
unzip project.zip -d /tmp/out     # 解压到指定目录
```

`zip`/`unzip` 不是所有 Linux 系统都预装；`.zip` 的好处是 Windows 用户能直接打开。

### 怎么选？

| 场景 | 选择 |
|------|------|
| Linux/macOS 间传输整个目录 | `tar -czf` |
| 需要和 Windows 用户共享 | `zip` |
| 只压缩一个文件 | `gzip` |

## 9.11 综合例子：带保留策略的备份脚本

`backup_dir.sh`：把一个目录打包到备份目录，并删除超过指定天数的旧备份。

```bash
#!/usr/bin/env bash
#
# backup_dir.sh - 备份目录并清理旧备份
# 用法: backup_dir.sh 源目录 备份目录 [保留天数，默认 7]

src="${1:?用法: $0 源目录 备份目录 [保留天数]}"
dest="${2:?用法: $0 源目录 备份目录 [保留天数]}"
keep="${3:-7}"

[ -d "$src" ] || { echo "源目录不存在: $src" >&2; exit 1; }
mkdir -p -- "$dest" || exit 1

name="$(basename -- "$src")"
stamp="$(date +%Y%m%d-%H%M%S)"
out="$dest/${name}-${stamp}.tar.gz"
tmp="$out.part"

# 出错或被中断时，删掉没写完的半成品（第 8 章的 trap）
trap 'rm -f -- "$tmp"' EXIT
trap 'exit 130' INT
trap 'exit 143' TERM

# 先写到临时文件，成功后再改名，避免留下损坏的备份
tar -czf "$tmp" -C "$(dirname -- "$src")" -- "$name" || {
    echo "打包失败" >&2
    exit 1
}
mv -- "$tmp" "$out"
echo "已创建: $out ($(du -h "$out" | cut -f1))"

# 删除超过 keep 天的旧备份
find "$dest" -maxdepth 1 -name "${name}-*.tar.gz" -mtime +"$keep" -print -delete
```

配合 cron，每天凌晨 2 点运行：

```
0 2 * * *  /home/alice/bin/backup_dir.sh /home/alice/docs /home/alice/backups 14 >> /home/alice/backup.log 2>&1
```

这个脚本用到了前面很多章节：参数默认值与 `${1:?...}`（第 5 章）、`trap` 与 `wait`/信号（第 8 章）、`find -delete`（第 4 章）、重定向（第 3 章）。

> 想了解更多的 `set -e`、`mktemp` 等健壮性手段，第 10 章会讲。

## 本章小结

- 权限三组 `rwx`：属主/属组/其他人；数字 `r=4 w=2 x=1`；目录的 `x` 表示能进入、`w` 表示能增删里面的文件。
- `chmod`（数字或符号方式）、`chown`、`umask`（新文件默认权限 = 666/777 去掉 umask）、`sudo`（只对需要的命令用，重定向不受它影响）。
- 资源：`df -h`（文件系统）、`du -sh`（目录占用）、`free -h`（Linux 内存）。
- 网络：`curl -fsSL`、`ssh`（密钥 + 正确的权限）、`scp`（端口用 `-P`）、`rsync -av`（注意尾部斜杠，`--delete` 前先 `-n`）。
- `cron`：5 个时间字段 + 命令；环境干净，用绝对路径、重定向日志、`%` 要转义。
- `tar -czf` / `-xzf` / `-tzf`；`gzip` 默认替换原文件；`zip -r` 便于和 Windows 互通。

## 练习

在一个练习目录（如 `~/shell-lab/ch09`）里完成：

1. 创建文件 `a.txt`，分别用数字方式和符号方式把权限设置为 `640`，用 `ls -l` 验证。
2. 创建脚本 `hello.sh`，先尝试直接 `./hello.sh`，观察错误，再用 `chmod` 修复。
3. 用 `umask 077` 后新建一个文件和一个目录，查看它们的权限，解释结果；然后把 `umask` 恢复为原值。
4. 创建目录 `d`，去掉它的 `x` 权限（`chmod a-x d`），尝试 `cd d` 和 `ls d`，观察结果；然后恢复权限。（注意：用 `root` 用户测试会看不出效果，因为 root 基本不受权限限制。）
5. 用 `df -h .` 查看当前文件系统的剩余空间；用 `du -h -d 1 ~ | sort -h | tail` 找出主目录下占用最大的几项。
6. 创建 `data/` 目录和几个文件，用 `tar` 打成 `data.tar.gz`，列出内容，再解压到另一个目录，用 `diff -r` 对比两个目录。
7. 用 `rsync -avn` 演示把 `data/` 同步到 `backup/`，再真正同步一次；然后修改 `data/` 里的一个文件，再同步一次，观察输出里只有变化的文件。
8. 写出 crontab 行：每周日凌晨 3:30 运行 `/home/alice/weekly.sh`，输出追加到 `/home/alice/weekly.log`。
9. 用 `curl -s -o /dev/null -w '%{http_code}\n' URL` 查看某个网址的 HTTP 状态码（需要联网）。
10. 解释：`rsync -av src dest/` 和 `rsync -av src/ dest/` 的区别。

### 参考答案要点

```bash
# 1
touch a.txt
chmod 640 a.txt            # 数字方式
chmod u=rw,g=r,o= a.txt    # 符号方式
ls -l a.txt                # -rw-r-----

# 2
printf '#!/usr/bin/env bash\necho hi\n' > hello.sh
./hello.sh                 # Permission denied
chmod u+x hello.sh
./hello.sh

# 3
old=$(umask)
umask 077
touch f && mkdir d
ls -ld f d                 # f 是 -rw-------，d 是 drwx------
umask "$old"

# 6
tar -czf data.tar.gz data/
tar -tzf data.tar.gz
mkdir restore
tar -xzf data.tar.gz -C restore
diff -r data restore/data && echo "一致"

# 7
rsync -avn data/ backup/
rsync -av data/ backup/

# 8
30 3 * * 0  /home/alice/weekly.sh >> /home/alice/weekly.log 2>&1
```

- 第 3 题：`666` 去掉 `077` 得 `600`；`777` 去掉 `077` 得 `700`，所以只有你自己能访问。
- 第 4 题：没有 `x` 时无法 `cd` 进入目录（`Permission denied`）；`ls d` 能否列出名字取决于 `r` 权限，但访问里面文件的详细信息会失败。
- 第 10 题：没有尾斜杠时，目录 `src` 本身被放进 `dest`，结果是 `dest/src/...`；有尾斜杠时只同步 `src` 的内容，结果是 `dest/...`。

## 常见问题速查

| 现象 | 原因 |
|------|------|
| `Permission denied`（执行脚本） | 没有执行权限：`chmod +x` |
| `Permission denied`（写文件） | 目录或文件无 `w` 权限；注意重定向不受 `sudo` 影响，用 `tee` |
| `rm` 删不掉别人在 `/tmp` 里的文件 | `/tmp` 有 sticky 位，只能删自己的 |
| `ssh` 报 `UNPROTECTED PRIVATE KEY FILE` | 私钥权限太宽，`chmod 600` |
| `scp` 指定端口无效 | 用的是小写 `-p`，应为大写 `-P` |
| `rsync` 目标里多出一层目录 | 源路径没有加尾部斜杠 |
| cron 里命令找不到 | cron 的 `PATH` 很短，用绝对路径 |
| cron 命令里的日期格式没生效 | `%` 要写成 `\%` |
| ``tar: Removing leading `/' from member names`` | 这是提示（引号样式因版本而异）：`tar` 去掉了路径开头的 `/`（出于安全），通常无需处理 |
| `gzip` 之后原文件没了 | 默认就是替换，想保留用 `-k` 或先复制 |
| `df` 显示还有空间但写不进去 | 可能是 inode 用完，用 `df -i` 检查 |
