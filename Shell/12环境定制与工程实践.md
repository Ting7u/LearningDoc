## 12.1 启动文件：什么时候读哪个文件

### 两个维度：登录/非登录，交互/非交互

| 维度 | 含义 | 例子 |
|------|------|------|
| **登录 Shell**（login） | 你"登录"系统时启动的 Shell | SSH 登录、`bash -l`、macOS 的终端 App 默认打开的 Shell、Linux 的 tty 登录 |
| **非登录 Shell** | 在已登录的会话里再启动的 Shell | 图形桌面里打开的终端窗口（多数 Linux 发行版）、在 Shell 里输入 `bash` |
| **交互式** | 接收键盘输入，显示提示符 | 平时敲命令的 Shell |
| **非交互式** | 运行脚本或 `bash -c '...'` | `./script.sh`、cron 里的命令 |

检查当前 Shell 的类型：

```bash
shopt -q login_shell && echo "登录 Shell" || echo "非登录 Shell"
case $- in *i*) echo "交互式";; *) echo "非交互式";; esac     # $- 是当前生效的 Shell 选项，含 i 表示交互式
```

### bash 读取哪些文件

| 场景 | 读取的文件 |
|------|-----------|
| **登录** Shell | 先 `/etc/profile`，再按顺序找 `~/.bash_profile`、`~/.bash_login`、`~/.profile`，**读到第一个存在的就停止** |
| **交互式非登录** Shell | `~/.bashrc`（以及系统级的 rc 文件，具体因发行版而异） |
| **非交互式** Shell（脚本） | 默认**不读**任何启动文件；若设置了环境变量 `BASH_ENV`，会读它指向的文件 |
| 登录 Shell 退出时 | `~/.bash_logout` |

注意两点：

1. **登录 Shell 默认不读 `~/.bashrc`**。所以惯例是在 `~/.bash_profile` 里手动加载它（见下）。
2. 有一个特例：据我所知，bash 在被远程服务（如 `sshd`）用于执行远程命令时，即使是非交互式的，也可能会读 `~/.bashrc`。所以 `.bashrc` 里不能无条件地输出内容，否则会破坏 `scp`、`rsync` 等依赖干净输出的工具。

### 验证：用一个假的 HOME 观察

下面用一个临时目录当 `HOME`，在每个文件里放一行标记，看哪些会被读取：

```bash
fake=$(mktemp -d)
echo 'echo "[.bash_profile]"' > "$fake/.bash_profile"
echo 'echo "[.bashrc]"'       > "$fake/.bashrc"
echo 'echo "[.profile]"'      > "$fake/.profile"

echo "--- 登录 Shell："
env -i HOME="$fake" PATH="$PATH" bash -l -c 'true'
echo "--- 交互式非登录 Shell："
env -i HOME="$fake" PATH="$PATH" bash -i -c 'true' 2>/dev/null
echo "--- 非交互式："
env -i HOME="$fake" PATH="$PATH" bash -c 'true' < /dev/null
echo "--- 非交互式，但设置了 BASH_ENV："
env -i HOME="$fake" PATH="$PATH" BASH_ENV="$fake/.bashrc" bash -c 'true' < /dev/null
```

预期结果：

| 场景 | 输出 |
|------|------|
| 登录 Shell | `[.bash_profile]`（读到第一个存在的就停止，不再读 `.profile`，也不会自动读 `.bashrc`） |
| 交互式非登录 | `[.bashrc]` |
| 非交互式 | 什么都不输出 |
| 非交互式 + `BASH_ENV` | `[.bashrc]`（读的是 `BASH_ENV` 指向的文件） |

（`env -i` 清空环境，避免外部变量干扰。系统级的 `/etc/profile`、`/etc/bash.bashrc` 也会被读取，但不会输出这些标记。）

> **为什么非交互式的命令要加 `< /dev/null`？** 我第一次测试时没有加，结果非交互式的 `bash -c 'true'` 也读了 `.bashrc`。
> 原因是我的测试环境里，Shell 的标准输入是一个 socket，bash 看到标准输入连着网络连接，就按"远程 Shell 守护进程启动"的特例处理，去读 `~/.bashrc`
> （就是上面提到的 `sshd` 特例）。把标准输入重定向到 `/dev/null` 后，结果就和表里一致了。
> 所以在实际使用中，通过 SSH 远程执行命令时，`.bashrc` 里不加交互式判断，输出就可能干扰 `scp`/`rsync`。

### 标准写法：让登录 Shell 也加载 `.bashrc`

`~/.bash_profile`：

```bash
# ~/.bash_profile —— 登录 Shell 读取
if [ -f "$HOME/.bashrc" ]; then
    . "$HOME/.bashrc"
fi
```

这样不论是登录还是非登录的交互式 Shell，最终都会读到 `.bashrc`，配置只需维护一份。

### `.bashrc` 开头：非交互式就直接退出

```bash
# ~/.bashrc
case $- in
    *i*) ;;                  # 交互式：继续往下
    *)   return ;;           # 非交互式：不做任何事，避免干扰 scp/rsync/脚本
esac
```

### 什么设置放在哪里

| 内容 | 位置 | 原因 |
|------|------|------|
| 环境变量（`PATH`、`EDITOR`、`LANG` 等） | `~/.profile` / `~/.bash_profile`（登录时一次） | 子进程继承，只需要设置一次 |
| 别名、函数、提示符、补全、`shopt`、`set -o` | `~/.bashrc` | 每个交互式 Shell 都需要，且它们不会被继承 |

但是有个现实问题：如果你的终端是**非登录**的（很多 Linux 桌面），放在 `.bash_profile` 里的 `PATH` 就不会生效。常见的折中：把环境变量也放进 `.bashrc`，并写成**可以重复执行而不出错**的形式（见 12.2 的 `pathadd`）。

### zsh 的启动文件

| 文件 | 何时读取 |
|------|----------|
| `~/.zshenv` | **所有** zsh（包括脚本、非交互式） |
| `~/.zprofile` | 登录 Shell |
| `~/.zshrc` | 交互式 Shell |
| `~/.zlogin` | 登录 Shell，在 `.zshrc` 之后 |

zsh 的习惯：环境变量放 `.zprofile`（或谨慎地放 `.zshenv`），别名、提示符、补全放 `.zshrc`。macOS 的终端默认打开登录 Shell，所以 `.zprofile` 和 `.zshrc` 都会被读到。

### 修改后让它生效

```bash
source ~/.bashrc            # 在当前 Shell 重新加载（第 1 章：source 在当前 Shell 执行）
exec bash                   # 或用一个全新的 bash 替换当前 Shell
```

## 12.2 `alias`、`PATH`、`PS1`

### `alias`：命令别名

```bash
alias ll='ls -lah'
alias grep='grep --color=auto'
alias ..='cd ..'
alias gs='git status'

alias                       # 列出所有别名
type ll                     # ll is aliased to `ls -lah'
unalias ll                  # 删除别名
\ls                         # 反斜杠：这一次绕过别名
command ls                  # 同样绕过别名（也绕过函数）
```

要点：

- 别名**只在交互式 Shell 里展开**。脚本（非交互式）里默认不展开别名，所以别名不会影响你的脚本，也不能在脚本里依赖别名
- 别名只是**文本替换**，不能带参数的灵活处理；需要参数、逻辑时用**函数**：

  ```bash
  mkcd() { mkdir -p -- "$1" && cd -- "$1"; }       # 创建目录并进入
  ```
- 同一行里先定义别名再使用，在这一行是不生效的（别名在读取下一行时才生效）
- 给 `rm` 之类危险命令加别名（如 `alias rm='rm -i'`）可能让你产生"到哪都有保护"的错觉，换一台机器或在脚本里并没有这个别名，所以要保持警惕的习惯

### `PATH`：命令查找路径

```bash
echo "$PATH"
export PATH="$HOME/bin:$PATH"           # 把 ~/bin 放到最前面（优先级最高）
export PATH="$PATH:$HOME/tools"         # 放到最后面（优先级最低）
```

问题：`.bashrc` 每次加载都会再追加一遍，`PATH` 会越来越长、有重复。用一个小函数避免重复：

```bash
pathadd() {
    case ":$PATH:" in
        *":$1:"*) ;;                     # 已经在 PATH 里了：什么都不做
        *) PATH="$1:$PATH" ;;
    esac
}
pathadd "$HOME/bin"
pathadd "$HOME/.local/bin"
export PATH
```

`":$PATH:"` 两边加冒号，是为了精确匹配"整段"（避免 `/usr/bin` 误匹配 `/usr/bin2`）。

排查命令来自哪里：

```bash
type -a python3             # 列出 PATH 里所有匹配的位置，以及别名/函数
which python3               # 只显示第一个外部命令
hash -r                     # 清除 bash 对命令路径的缓存（刚装了新命令却找不到时试试）
```

⚠️ **不要把 `.`（当前目录）放进 `PATH`**：进入别人给你的目录后，只要敲一个和常用命令同名的文件名，就会执行那个文件。

### `PS1`：命令提示符

`PS1` 是主提示符，里面可以使用转义序列：

| 序列 | 含义 |
|------|------|
| `\u` | 用户名 |
| `\h` | 主机名（到第一个 `.` 为止） |
| `\w` | 当前目录（完整，主目录显示为 `~`） |
| `\W` | 当前目录的最后一级 |
| `\$` | 普通用户显示 `$`，root 显示 `#` |
| `\t` | 24 小时制时间 |
| `\n` | 换行 |
| `\[` … `\]` | 包住**不占宽度**的字符（如颜色代码） |

```bash
PS1='\u@\h:\w\$ '                       # alice@host:~/project$
```

加颜色（`\e[...m` 是终端的颜色转义序列）：

```bash
PS1='\[\e[32m\]\u@\h\[\e[0m\]:\[\e[34m\]\w\[\e[0m\]\$ '
```

- `\e[32m` 绿色，`\e[34m` 蓝色，`\e[0m` 恢复默认
- **不可见的转义序列必须用 `\[` `\]` 括起来**，否则 bash 会算错提示符的宽度，导致输入长命令时光标错位、换行混乱

想在写入前"预览"一个 `PS1` 的显示效果（bash 4.4+）：

```bash
PS1='\u@\h:\w\$ '
echo "${PS1@P}"                          # 展开后的样子
```

显示 git 分支（`PROMPT_COMMAND` 在每次显示提示符之前运行）：

```bash
git_branch() { git branch --show-current 2>/dev/null; }    # 需要较新的 git（2.22+）
PS1='\w $(git_branch)\$ '                # 注意：单引号，让 $(...) 在每次显示提示符时才执行
```

> 提示符里调用外部命令会拖慢每次回车的响应；复杂的需求可以用第三方的提示符工具（如 starship，它支持多种 Shell），安装和配置请以其官方文档为准。

### 其他值得设置的

```bash
# 历史记录
HISTSIZE=10000                          # 内存里保留的条数
HISTFILESIZE=20000                      # 文件里保留的条数
HISTCONTROL=ignoreboth                  # 忽略重复的和以空格开头的命令
shopt -s histappend                     # 退出时追加到历史文件，而不是覆盖

export EDITOR=vim                       # 默认编辑器（换成你习惯的）
shopt -s globstar nocaseglob            # 第 11 章讲过的 shopt 选项
set -o vi                               # 命令行用 vi 的按键方式（默认是 emacs 风格）
```

## 12.3 zsh 及其生态

### 为什么要了解 zsh

macOS 从 Catalina（10.15）起，默认的登录 Shell 是 zsh。你在 Mac 上敲命令时，多半就在用 zsh。zsh 和 bash 的交互体验相近，但**语法有若干不同**。

查看自己在用哪个：

```bash
echo "$SHELL"          # 默认登录 Shell
echo "$0"              # 当前 Shell
echo "$ZSH_VERSION"    # zsh 里有值，bash 里为空
```

### 与 bash 的主要差异

| 方面 | bash | zsh |
|------|------|-----|
| 数组下标 | 从 **0** 开始 | 默认从 **1** 开始 |
| 未加引号的变量 | 会**单词拆分** | 默认**不拆分**（和 bash 行为不同，写 `$var` 就是一个词） |
| 通配符没有匹配 | 保留原样传给命令 | 默认**报错** `no matches found` |
| 配置选项 | `shopt`、`set -o` | `setopt`、`unsetopt` |
| `read -p "提示"` | 提示语 | `-p` 的含义不同；zsh 用 `read "var?提示"` |
| 补全、主题、插件 | 较基础 | 非常强大，生态丰富 |

> 以上差异来自我对两种 Shell 的了解；本章的沙箱里没有安装 zsh，没有运行验证，请在你的 Mac 上试一试。

### 关于脚本

**即使你日常用 zsh，写脚本仍然建议写 `#!/usr/bin/env bash`**（或 `#!/bin/sh` 写 POSIX 脚本）。脚本由 shebang 指定的解释器运行，和你的登录 Shell 是谁无关；而你从本教程学到的语法都是 bash/POSIX 的。

### 常见的 zsh 生态（了解名字即可）

| 名称 | 作用 |
|------|------|
| Oh My Zsh | 流行的 zsh 配置框架，带大量插件和主题 |
| zsh-autosuggestions | 根据历史命令给出灰色的补全建议 |
| zsh-syntax-highlighting | 命令行输入时语法高亮 |
| starship | 跨 Shell 的提示符工具 |

它们都是第三方项目，**安装方式会变，以各自官方文档为准**，这里不给命令。给自己的 `.zshrc` 加东西时，建议一次只加一个，确认启动速度和行为没问题再加下一个。

### 兼容 bash 习惯的小贴士

zsh 的 `.zshrc` 里：

```zsh
setopt HIST_IGNORE_DUPS SHARE_HISTORY        # 历史记录相关选项
autoload -Uz compinit && compinit            # 启用补全系统
```

## 12.4 dotfiles 管理

**dotfiles** 指你的各种以 `.` 开头的配置文件（`.bashrc`、`.gitconfig`、`.vimrc`、`.ssh/config` 等）。把它们放进一个 git 仓库管理，可以：

- 在多台机器间保持一致
- 换新电脑时几分钟恢复环境
- 有版本历史，改坏了能回退

### 方案一：仓库 + 符号链接 + 安装脚本（推荐入门）

仓库结构：

```
dotfiles/
├── bash/
│   ├── bashrc
│   └── bash_profile
├── git/
│   └── gitconfig
└── install.sh
```

`install.sh`：把仓库里的文件用符号链接放到 `$HOME`，已存在的先备份，可以重复运行：

```bash
#!/usr/bin/env bash
set -euo pipefail

repo="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
backup="$HOME/.dotfiles_backup/$(date +%Y%m%d-%H%M%S)"

link() {
    local src="$repo/$1" dst="$HOME/$2"

    # 已经是正确的链接：什么都不做（保证可以重复运行）
    if [ -L "$dst" ] && [ "$(readlink "$dst")" = "$src" ]; then
        echo "ok:      $dst"
        return 0
    fi

    # 目标已存在（文件或别的链接）：先备份
    if [ -e "$dst" ] || [ -L "$dst" ]; then
        mkdir -p "$backup"
        mv -- "$dst" "$backup/"
        echo "backup:  $dst -> $backup/"
    fi

    mkdir -p "$(dirname "$dst")"
    ln -s "$src" "$dst"
    echo "link:    $dst -> $src"
}

link bash/bashrc       .bashrc
link bash/bash_profile .bash_profile
link git/gitconfig     .gitconfig
```

这个脚本用到了：`set -euo pipefail`、`BASH_SOURCE`（第 7 章）、函数与 `local`、`case`/`if` 判断、`ln -s`、`readlink`（读取符号链接指向的路径）。

### 方案二：现成工具

- **GNU Stow**：把目录里的文件批量做符号链接，用法很简洁
- **chezmoi**、**yadm** 等：专门的 dotfiles 管理工具，支持模板、加密、多机器差异

这些都是第三方工具，用法和安装方式请以官方文档为准。

### 方案三：裸仓库（bare repository）

```bash
git init --bare "$HOME/.dotfiles"
alias dot='git --git-dir="$HOME/.dotfiles" --work-tree="$HOME"'
dot config status.showUntrackedFiles no        # 不显示主目录里其他无关文件
dot add ~/.bashrc
dot commit -m "add bashrc"
```

不需要符号链接，文件原地被 git 跟踪，但新手容易在主目录里误操作，建议理解后再使用。

### 实用建议

1. **不要把机密提交进仓库**：SSH 私钥、令牌、密码、API key 一律不要放。仓库即使是私有的，也要养成习惯
2. **机器差异用"本地覆盖文件"处理**：在 `.bashrc` 末尾加上：

   ```bash
   if [ -r "$HOME/.bashrc.local" ]; then
       . "$HOME/.bashrc.local"                # 本机特有的设置，不提交进仓库
   fi
   ```

   然后把 `.bashrc.local` 写进仓库的 `.gitignore`
3. **install 脚本要幂等**（运行一次和运行多次结果相同），并且**先备份再覆盖**
4. 在新机器上先检查依赖（`command -v git`、`command -v vim`），缺什么给出明确提示
5. 用 `bash -n` 和 ShellCheck（第 10 章）检查自己的配置文件

## 12.5 Shell 在 Makefile、CI/CD、Docker 中的使用

### Makefile 里的 Shell

`make` 的每一个配方（recipe）都是一段交给 Shell 执行的命令。几个关键点：

1. **每一行是独立的 Shell 进程**，所以 `cd` 和变量不会延续到下一行：

   ```make
   demo:
   	cd /tmp
   	pwd                     # 仍然是原来的目录
   	cd /tmp && pwd          # 要写在同一行（或用 \ 续行）
   ```
2. **配方行必须以 Tab 开头**（不能是空格）
3. 默认使用 `/bin/sh`。想用 bash 特性，需要声明：

   ```make
   SHELL := /bin/bash
   .SHELLFLAGS := -eu -o pipefail -c       # 较新的 GNU make 支持，给每行命令加严格模式
   ```
4. **Shell 变量的 `$` 要写成 `$$`**（单个 `$` 是 make 自己的变量）：

   ```make
   show:
   	@for f in a b c; do echo "$$f"; done
   ```
5. 行首的 `@` 不回显命令本身，`-` 忽略这一行的失败
6. 不产生同名文件的目标要声明 `.PHONY`
7. 想让整个配方在**同一个 Shell** 里运行，可以用 `.ONESHELL:`（较新的 GNU make 支持）

一个检查脚本的 Makefile：

```make
SHELL := /bin/bash
.SHELLFLAGS := -eu -o pipefail -c
SCRIPTS := $(wildcard bin/*.sh)

.PHONY: check test

check:
	@for f in $(SCRIPTS); do bash -n "$$f" || exit 1; done
	@if command -v shellcheck >/dev/null 2>&1; then \
	    shellcheck $(SCRIPTS); \
	else \
	    echo "shellcheck 未安装，跳过"; \
	fi

test:
	@bash test/run.sh
```

注意 `if ...; then \` 的写法：因为每一行是独立的 Shell，一个 `if` 必须连成一行（用 `\` 续行并且用 `;` 分隔）。

### CI/CD 里的 Shell 脚本

CI（持续集成）服务器上，脚本在**非交互式、无人值守**的环境里运行。要点：

- **退出码决定成败**：CI 通常以"命令返回非 0"判定步骤失败。所以脚本里该失败的地方要真的让退出码非 0（第 10 章）
- **显式写严格模式**：不同 CI 平台的默认 Shell 和默认选项各不相同（有的默认带 `-e`，有的不带），所以在脚本开头自己写 `set -euo pipefail`，不要依赖平台的默认值
- **不要依赖交互式环境**：没有终端、没有 `~/.bashrc` 里的别名和 `PATH` 设置；需要的环境变量要在脚本或 CI 配置里明确设置
- **日志里不要泄露机密**：不要 `set -x` 后处理密钥；不要 `echo` 密钥
- **脚本能在本地运行**：把真正的逻辑写进仓库里的脚本（如 `scripts/ci.sh`），CI 配置只负责调用它，这样可以在本地复现 CI 的行为
- 在 CI 里加入 `bash -n` 和 ShellCheck 检查，问题在合并之前就能被发现

一个典型的 CI 入口脚本：

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "== 语法检查 =="
for f in bin/*.sh; do bash -n "$f"; done

echo "== ShellCheck =="
if command -v shellcheck >/dev/null 2>&1; then
    shellcheck bin/*.sh
else
    echo "未安装 shellcheck，跳过" >&2
fi

echo "== 测试 =="
bash test/run.sh
```

### Docker 里的 Shell

Dockerfile 里和 Shell 相关的几个要点（以下内容来自我对 Docker 的了解，本章的沙箱没有实际构建镜像，没有运行验证）：

**1. `RUN` 有两种写法**

```dockerfile
RUN echo "hello" && ls            # shell 形式：通过 /bin/sh -c 运行，支持 && 、管道、变量展开
RUN ["bash", "-c", "echo hi"]     # exec 形式：直接运行程序，不经过 Shell
```

默认的 shell 形式用的是 `/bin/sh -c`，不是 bash，也不会开启 `pipefail`。要换成 bash 并开启 `pipefail`：

```dockerfile
SHELL ["/bin/bash", "-o", "pipefail", "-c"]
```

**2. 精简镜像里可能没有 bash**

Alpine 等精简镜像默认没有 bash，只有 busybox 的 `sh`。这是第 10 章"POSIX sh 写法"派上用场的地方：容器里的脚本要么写 POSIX sh，要么在镜像里显式安装 bash。

**3. `CMD`/`ENTRYPOINT` 优先用 exec 形式，并在入口脚本里用 `exec`**

`docker stop` 会向容器的 1 号进程发送 `SIGTERM`（等一段时间后再发 `SIGKILL`）。回忆第 8 章：信号只会发给进程，如果 1 号进程是一个 Shell，而真正的应用是它的子进程，应用就可能收不到 `SIGTERM`。解决办法是入口脚本最后用 `exec`，让应用**替换** Shell 成为 1 号进程：

```bash
#!/bin/sh
set -e
echo "初始化..."
# ... 准备工作：生成配置、等待依赖 ...
exec "$@"                         # 用传给脚本的命令替换当前进程；之后收到的信号直接到达应用
```

```dockerfile
COPY entrypoint.sh /usr/local/bin/entrypoint.sh
ENTRYPOINT ["/usr/local/bin/entrypoint.sh"]
CMD ["myapp", "--serve"]
```

`exec "$@"` 的效果可以在本地验证：脚本里 `exec` 之后，进程的 PID 保持不变，被替换成了新程序。

**4. 减少层数、清理缓存**：多条命令用 `&&` 和 `\` 连起来写在同一个 `RUN` 里，并在同一条 `RUN` 里清理安装缓存。

## 12.6 综合例子：一个小型脚本项目的骨架

```
mytool/
├── bin/
│   └── mytool.sh          # 主程序
├── lib/
│   └── strings.sh         # 公共函数库
├── test/
│   └── run.sh             # 测试脚本
├── Makefile
└── README.md
```

`lib/strings.sh`：

```bash
# 被 source 的函数库：没有 shebang，不设置 set -e（由调用者决定）

trim() {
    local s="$1"
    s="${s#"${s%%[![:space:]]*}"}"
    s="${s%"${s##*[![:space:]]}"}"
    printf '%s' "$s"
}

to_upper() {
    printf '%s' "${1^^}"                  # 需要 bash 4+
}
```

`bin/mytool.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
# shellcheck source=../lib/strings.sh
. "$SCRIPT_DIR/../lib/strings.sh"

main() {
    local input="${1:-}"
    [ -n "$input" ] || { echo "用法: ${0##*/} 文本" >&2; return 2; }
    to_upper "$(trim "$input")"
    echo
}

main "$@"
```

`test/run.sh`：一个最小的测试框架：

```bash
#!/usr/bin/env bash
set -u

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
. "$SCRIPT_DIR/../lib/strings.sh"

total=0
failed=0

assert_eq() {                              # 用法: assert_eq 期望值 实际值 描述
    total=$((total + 1))
    if [ "$1" = "$2" ]; then
        printf 'ok   - %s\n' "$3"
    else
        printf 'FAIL - %s\n       期望: [%s]\n       实际: [%s]\n' "$3" "$1" "$2"
        failed=$((failed + 1))
    fi
}

assert_eq "hello"  "$(trim '  hello  ')"        "trim 去掉首尾空白"
assert_eq ""       "$(trim '    ')"              "trim 全空白得到空串"
assert_eq "A B"    "$(to_upper 'a b')"           "to_upper 转大写"
assert_eq "HELLO"  "$("$SCRIPT_DIR/../bin/mytool.sh" '  hello ')" "主程序端到端"

printf '\n%d 个测试，%d 个失败\n' "$total" "$failed"
[ "$failed" -eq 0 ]
```

`Makefile` 就用 12.5 里那个：`make check` 做语法和静态检查，`make test` 跑测试。

这个骨架把第 5～12 章几乎所有的内容串了起来：函数、模块拆分与 `source`、严格模式、`BASH_SOURCE` 定位、参数展开、命令替换、测试脚本、Makefile。

## 本章小结

- 启动文件：登录 Shell 读 `~/.bash_profile`（或 `~/.profile`），交互式非登录读 `~/.bashrc`；脚本默认都不读。惯例是 `.bash_profile` 里 `source ~/.bashrc`，`.bashrc` 开头判断交互式。
- `alias` 只在交互式生效、需要参数时用函数；`PATH` 追加要去重，不要放 `.`；`PS1` 里的颜色序列用 `\[ \]` 括起来。
- zsh：数组从 1 开始、不自动拆分、通配符无匹配报错；脚本仍然写 bash/POSIX 的 shebang。
- dotfiles：仓库 + 符号链接 + 幂等的安装脚本，先备份，不提交机密，用 `.local` 文件处理机器差异。
- Makefile：每行独立的 Shell，`$$`，`SHELL`/`.SHELLFLAGS`；CI：显式写严格模式，退出码决定成败，逻辑放脚本里；Docker：注意 `/bin/sh`，入口脚本以 `exec "$@"` 结束让信号到达应用。

### 参考答案要点

```bash
# 1 的预期（系统级文件不输出标记）：
#   登录 Shell：只输出 [.bash_profile]（读到第一个存在的就停止，不读 .profile，也不自动读 .bashrc）
#   交互式非登录：输出 [.bashrc]
#   非交互式：什么都不输出（要把标准输入重定向到 /dev/null，原因见 12.1 的说明）

# 3
PS1='\[\e[32m\]\u@\h\[\e[0m\] \[\e[34m\]\w\[\e[0m\]\$ '
echo "${PS1@P}"

# 4
pathadd() { case ":$PATH:" in *":$1:"*) ;; *) PATH="$1:$PATH";; esac; }
pathadd /tmp/x; pathadd /tmp/x
echo "$PATH" | tr ':' '\n' | grep -c '^/tmp/x$'        # 1

# 7
cat > entrypoint.sh <<'EOF'
#!/bin/sh
echo "PID before exec: $$"
exec sleep 30
EOF
chmod +x entrypoint.sh
./entrypoint.sh &
ps -p $! -o pid,comm                                     # PID 与上面打印的相同，命令是 sleep
```

- 第 8 题：默认的 shell 形式用 `/bin/sh -c`，没有 `pipefail`，管道的状态只取最后一个命令；改用 `SHELL ["/bin/bash", "-o", "pipefail", "-c"]`。
- 第 9 题：bash 输出 `b`（下标从 0 开始），zsh 默认输出 `a`（下标从 1 开始）。

## 常见问题速查

| 现象 | 原因 |
|------|------|
| 改了 `.bashrc`，新开登录 Shell 没生效 | 登录 Shell 不读 `.bashrc`，要在 `.bash_profile` 里 `source` 它 |
| 改了 `.bash_profile` 里的 `PATH`，新开的终端没生效 | 终端是非登录 Shell，没有读 `.bash_profile` |
| `scp`/`rsync` 连接后报协议错误或乱码 | `.bashrc` 里无条件地输出了内容；开头加交互式判断 |
| 别名在脚本里不生效 | 别名只在交互式 Shell 展开；改用函数 |
| 提示符里输入长命令时光标错位、换行混乱 | 颜色转义序列没有用 `\[ \]` 括起来 |
| `PATH` 越来越长、有大量重复 | `.bashrc` 重复追加；用 `pathadd` 去重 |
| zsh 里 `for f in *.txt` 没有文件时直接报错 | zsh 默认通配符无匹配就报错（`nomatch`） |
| Makefile 里 `cd` 之后命令还在原目录执行 | 每行是独立的 Shell，需写在同一行或用 `.ONESHELL:` |
| Makefile 里 Shell 变量 `$f` 是空的 | `$` 需要写成 `$$` |
| Makefile 报 `missing separator` | 配方行不是以 Tab 开头 |
| 容器 `docker stop` 要等很久才停止 | 应用不是 1 号进程，没收到 `SIGTERM`；入口脚本用 `exec "$@"` |
