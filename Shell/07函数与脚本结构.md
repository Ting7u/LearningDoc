## 7.1 函数

### 定义与调用

```bash
greet() {
    echo "Hello, $1!"
}

greet Alice          # 调用时不加括号，参数用空格分隔
greet "Bob Smith"    # 含空格的参数要加引号
```

输出：

```
Hello, Alice!
Hello, Bob Smith!
```

要点：

- 定义格式 `name() { 命令...; }`。bash 还允许 `function name { ...; }`，但前者可移植性更好。
- **函数必须先定义、后调用**（Shell 是逐行解释执行的）。
- 函数内的 `$1`、`$2`、`$#`、`$@` 指的是**函数的参数**，而不是脚本的参数（`$0` 仍然是脚本名）。

> **对比 C 语言**：Shell 函数没有参数列表和类型声明；参数通过 `$1 $2 ...` 获取，
> 类似于 C 的 `argv`；调用时也不写括号和逗号。

### 返回值：`return` 与输出是两回事

Shell 函数有**两种**"返回"结果的方式，用途完全不同：

| 方式 | 作用 | 取值方法 |
|------|------|---------|
| `return n`（0~255） | 返回**退出状态**，表示成功/失败 | `$?` 或直接放在 `if` 里 |
| `echo` 输出 | 返回**数据** | `result=$(func)` |

```bash
# 用法 1：return 表示成功/失败，配合 if 使用
is_even() {
    [ $(( $1 % 2 )) -eq 0 ]        # 函数的退出状态 = 最后一条命令的状态
}

if is_even 4; then echo "偶数"; fi

# 用法 2：echo 输出数据，用命令替换捕获
add() {
    echo $(( $1 + $2 ))
}
sum=$(add 3 4)
echo "$sum"                        # 7
```

> ⚠️ `return` 只能返回 0~255 的整数，**不能**用来返回字符串或大数值。
> 要返回数据，就 `echo`，由调用方用 `$(...)` 捕获。
> 因此函数里**不要随便 echo 调试信息**到 stdout，会混进返回数据里；调试信息输出到 stderr（`echo "..." >&2`）。

`return` 和 `exit` 的区别：

- `return`：结束**函数**（也可用于被 `source` 的脚本）
- `exit`：结束**整个脚本**（在函数里调用 `exit` 同样会终止整个脚本）

### 递归（和 C 一样可以）

```bash
factorial() {
    local n=$1
    if [ "$n" -le 1 ]; then
        echo 1
        return
    fi
    local prev
    prev=$(factorial $((n - 1)))
    echo $((n * prev))
}

factorial 5          # 120
```

> 每一层 `$(...)` 都会创建子 Shell，递归较深时会很慢，Shell 不适合做重计算。这里只是用来说明语法。

### 变量作用域与 `local`

**Shell 函数里的变量默认是全局的。** 用 `local` 声明局部变量：

```bash
x=1

f() {
    x=2             # 修改了全局变量
    local y=3       # 局部变量，函数结束后消失
}

f
echo "$x"           # 2
echo "${y:-未设置}"  # 未设置
```

> **对比 C 语言**：C 的函数内变量默认是局部的；Shell 刚好相反，默认是全局，需要 `local` 才是局部。
> 这是很多 Bug 的来源，**函数里的临时变量一律加 `local`**。
> （`local` 不是 POSIX 标准，但 bash、dash、zsh 等主流 Shell 都支持。）
> 另外，bash 的 `local` 是"动态作用域"：函数 A 的局部变量，对 A 所调用的函数 B 也是可见的。

### ⚠️ `local` 的坑：会掩盖命令的退出状态

```bash
f() {
    local out=$(some_command)       # ❌ $? 是 local 的状态（几乎总是 0），some_command 的失败被吞掉
}

f() {
    local out
    out=$(some_command) || return 1   # ✅ 声明和赋值分开
}
```

## 7.2 位置参数

运行 `./script.sh a "b c" d` 时：

| 变量 | 含义 | 本例的值 |
|------|------|---------|
| `$0` | 脚本名 | `./script.sh` |
| `$1`、`$2`、`$3` | 第 1、2、3 个参数 | `a`、`b c`、`d` |
| `${10}` | 第 10 个参数（两位数要用花括号） | |
| `$#` | 参数个数（不含 `$0`） | `3` |
| `$@` | 所有参数 | |
| `$*` | 所有参数 | |
| `$?` | 上一条命令的退出状态 | |
| `$$` | 当前 Shell 进程号 | |

> **对比 C 语言**：`$0` ↔ `argv[0]`，`$1` ↔ `argv[1]`，`$#` ↔ `argc - 1`。

### `"$@"` 与 `"$*"` 的区别（重点）

新建 `p.sh`：

```bash
#!/usr/bin/env bash
echo "参数个数: $#"

echo '--- "$@" ---'
for a in "$@"; do echo "[$a]"; done

echo '--- "$*" ---'
for a in "$*"; do echo "[$a]"; done

echo '--- $@（不加引号）---'
for a in $@; do echo "[$a]"; done
```

运行 `./p.sh "a b" c`：

```
参数个数: 2
--- "$@" ---
[a b]
[c]
--- "$*" ---
[a b c]
--- $@（不加引号）---
[a]
[b]
[c]
```

| 写法 | 效果 |
|------|------|
| `"$@"` | 每个参数**保持独立**（含空格的参数不会被拆开）。**转发参数时用这个** |
| `"$*"` | 所有参数合并成**一个**字符串（以 `IFS` 的第一个字符连接，默认是空格） |
| `$@`、`$*`（不加引号） | 各自被再次拆分，含空格的参数会被拆坏 |

典型用法：把脚本收到的参数原封不动传给另一个命令：

```bash
./wrapper.sh --flag "my file.txt"
# wrapper.sh 内部
exec real_program "$@"
```

### 默认值与参数检查

```bash
target="${1:-.}"                   # 没给参数就用当前目录

if [ $# -lt 1 ]; then
    echo "用法: $0 <文件>" >&2
    exit 2
fi
```

### `shift`：移走第一个参数

`shift` 把 `$2` 变成 `$1`、`$3` 变成 `$2`……同时 `$#` 减 1：

```bash
# 处理所有参数
while [ $# -gt 0 ]; do
    echo "处理: $1"
    shift
done

# shift 2：一次移走两个
```

## 7.3 `getopts`：解析命令行选项

很多脚本需要支持 `-v`、`-n 名字` 这样的选项。`getopts` 是 Shell 内建的、符合 POSIX 的解析工具。

### 基本写法

新建 `greet.sh`：

```bash
#!/usr/bin/env bash

usage() {
    echo "用法: $0 [-v] [-n 名字] [-h] [文件...]" >&2
}

verbose=0
name="World"

while getopts ":vn:h" opt; do
    case "$opt" in
        v)  verbose=1 ;;
        n)  name="$OPTARG" ;;
        h)  usage; exit 0 ;;
        :)  echo "选项 -$OPTARG 需要参数" >&2; usage; exit 2 ;;
        \?) echo "未知选项: -$OPTARG" >&2; usage; exit 2 ;;
    esac
done
shift $((OPTIND - 1))              # 去掉已处理的选项，剩下的是位置参数

echo "Hello, $name!"
if [ "$verbose" -eq 1 ]; then
    echo "剩余参数个数: $#"
fi
for f in "$@"; do
    echo "文件: $f"
done
```

运行：

```bash
./greet.sh -v -n Alice a.txt b.txt
```

```
Hello, Alice!
剩余参数个数: 2
文件: a.txt
文件: b.txt
```

### 选项字符串 `":vn:h"` 的含义

- **开头的冒号 `:`**：启用"静默模式"，由脚本自己处理错误（不让 getopts 打印默认报错）
- `v`：选项 `-v`，**不带**参数
- `n:`：选项 `-n`，字母后的冒号表示**必须带参数**，参数值放在 `$OPTARG`
- `h`：选项 `-h`，不带参数

### 相关变量

| 变量 | 含义 |
|------|------|
| `opt`（变量名自定） | 本轮解析到的选项字母 |
| `OPTARG` | 当前选项的参数值 |
| `OPTIND` | 下一个要处理的参数下标，处理完后用 `shift $((OPTIND-1))` 丢掉选项部分 |

静默模式下的错误情形：

- 遇到未知选项：`opt` 被设为 `?`，`OPTARG` 是该选项字符
- 选项缺少必需的参数：`opt` 被设为 `:`，`OPTARG` 是该选项字符

### 注意事项

- `getopts` 只支持**短选项**（`-v`），不支持长选项（`--verbose`）。长选项需要手写 `case` 解析或用外部 `getopt` 命令（不同系统版本差异较大，这里不展开）。
- 选项必须写在位置参数**前面**：`./greet.sh -v file` 可以，`./greet.sh file -v` 则 `-v` 会被当作普通参数。
- 短选项可以合并：`-vn Alice` 等价于 `-v -n Alice`。

## 7.4 `source` 与脚本拆分

当脚本变大，可以把公共函数放进单独的文件，用 `source`（或 `.`）引入：

`lib.sh`：

```bash
greet() {
    echo "Hello, $1"
}
```

`main.sh`：

```bash
#!/usr/bin/env bash
source ./lib.sh          # 等价于 . ./lib.sh
greet Alice
```

### 路径问题：让脚本从任何目录都能找到 lib.sh

`source ./lib.sh` 里的 `./` 是相对于**当前工作目录**的，不是相对于脚本所在目录。从别的目录运行脚本就会找不到。
常用的解决写法（bash）：

```bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$SCRIPT_DIR/lib.sh"
```

- `${BASH_SOURCE[0]}`：当前脚本文件的路径（bash 特性；被 `source` 时它也比 `$0` 更可靠）
- `dirname`：取目录部分
- `cd ... && pwd`：转成绝对路径

> 与第 1 章对应：`source` 是在**当前 Shell** 里执行文件，所以其中定义的函数和变量都会保留下来；
> 而 `bash lib.sh` 会开子进程，函数和变量随子进程结束而消失。

## 7.5 子 Shell 与变量作用域

**子 Shell**是当前 Shell 的一个**拷贝进程**（类似 `fork()` 出来的子进程）：
它继承了父 Shell 的变量，但在子 Shell 里做的修改**不会影响父 Shell**。

### 哪些情况会创建子 Shell

| 写法 | 说明 |
|------|------|
| `( 命令... )` | 圆括号：显式创建子 Shell |
| `$( 命令 )` | 命令替换 |
| `cmd1 \| cmd2` | **管道的每一段**通常都在子 Shell 里运行（bash 默认如此） |
| `cmd &` | 放到后台执行 |
| 运行外部脚本 `./a.sh` | 新进程 |

### `( )` 与 `{ }` 的区别

```bash
x=1

( x=2; cd /tmp )        # 在子 Shell 里执行
echo "$x"               # 1，没有变化
pwd                     # 目录也没变

{ x=3; cd /tmp; }       # 在当前 Shell 里执行，只是把命令分组
echo "$x"               # 3
pwd                     # /tmp（已改变）
```

实用技巧：用圆括号包住一组命令，让 `cd` 等副作用不影响当前 Shell：

```bash
(cd /some/dir && make)  # make 结束后，当前目录没有变化
```

### ⚠️ 经典陷阱：管道里的 `while` 循环

```bash
count=0
printf 'a\nb\nc\n' | while read -r line; do
    count=$((count + 1))
done
echo "$count"           # 输出 0 ！（循环在子 Shell 里，count 的修改丢失了）
```

解决：不要用管道，改用**输入重定向**：

```bash
count=0
while read -r line; do
    count=$((count + 1))
done < file.txt
echo "$count"           # 正确

# 输入来自命令输出时，可用 Here String（bash）：
data="$(some_command)"
while read -r line; do
    count=$((count + 1))
done <<< "$data"
echo "$count"
```

（第 11 章会介绍另一种解法：进程替换 `< <(...)`。）

### `exit` 在子 Shell 里的行为

```bash
( exit 3 )
echo $?                 # 3：只是退出了子 Shell，主脚本继续执行
```

## 7.6 退出状态码约定

脚本和函数都应该用合适的退出状态码告诉调用方结果：

| 状态码 | 常见含义 |
|:---:|------|
| `0` | 成功 |
| `1` | 一般性错误 |
| `2` | 用法错误（命令行参数不对）；许多命令也这样约定 |
| `126` | 命令存在但不可执行（如权限问题） |
| `127` | 命令未找到 |
| `128 + n` | 被信号 n 终止，如 `130` 表示被 Ctrl+C（SIGINT，信号 2）终止 |

自己写脚本时，用 `0` 表示成功，其余用 `1`~`125` 内的值区分错误类型，并在注释或帮助信息中说明。

## 7.7 脚本结构模板

一个结构清晰的脚本通常长这样：

```bash
#!/usr/bin/env bash
#
# 脚本说明：做什么、怎么用
#

# ---------- 全局变量 ----------
verbose=0

# ---------- 函数 ----------
usage() {
    cat >&2 <<EOF
用法: $0 [选项] 参数...
  -v    显示详细信息
  -h    显示帮助
EOF
}

log() {
    if [ "$verbose" -eq 1 ]; then
        echo "[INFO] $*" >&2
    fi
}

# ---------- 主逻辑 ----------
main() {
    local opt
    while getopts ":vh" opt; do
        case "$opt" in
            v)  verbose=1 ;;
            h)  usage; return 0 ;;
            \?) echo "未知选项: -$OPTARG" >&2; usage; return 2 ;;
        esac
    done
    shift $((OPTIND - 1))

    if [ $# -lt 1 ]; then
        usage
        return 2
    fi

    # ... 实际工作 ...
}

main "$@"
```

好处：

- 所有逻辑都在函数里，变量不容易污染全局
- `main "$@"` 把参数转发过去；脚本的退出状态就是 `main` 的返回值
- 和 C 程序的 `main` 结构相似，便于阅读

> 如果脚本既要能被执行、又要能被 `source` 复用，可以用 bash 的判断
> `if [[ "${BASH_SOURCE[0]}" == "$0" ]]; then main "$@"; fi` 来区分，这里仅作了解。

## 7.8 综合例子：备份脚本

`backup.sh`：把若干文件或目录复制到备份目录。

```bash
#!/usr/bin/env bash
#
# backup.sh - 把文件或目录复制到备份目录

verbose=0

usage() {
    cat >&2 <<EOF
用法: $0 [-d 目标目录] [-v] 文件或目录...
  -d DIR   备份到 DIR（默认 ./backup）
  -v       显示详细信息
  -h       显示帮助
EOF
}

log() {
    if [ "$verbose" -eq 1 ]; then
        echo "[INFO] $*"
    fi
}

backup_one() {
    local src="$1"
    local dest="$2"

    if [ ! -e "$src" ]; then
        echo "跳过: $src 不存在" >&2
        return 1
    fi
    cp -r -- "$src" "$dest/"
    log "已备份: $src"
}

main() {
    local dest="./backup"
    local opt f
    local failed=0

    while getopts ":d:vh" opt; do
        case "$opt" in
            d)  dest="$OPTARG" ;;
            v)  verbose=1 ;;
            h)  usage; return 0 ;;
            :)  echo "选项 -$OPTARG 需要参数" >&2; usage; return 2 ;;
            \?) echo "未知选项: -$OPTARG" >&2; usage; return 2 ;;
        esac
    done
    shift $((OPTIND - 1))

    if [ $# -lt 1 ]; then
        usage
        return 2
    fi

    mkdir -p -- "$dest" || return 1

    for f in "$@"; do
        backup_one "$f" "$dest" || failed=$((failed + 1))
    done

    log "完成，失败 $failed 个"
    [ "$failed" -eq 0 ]            # 全部成功才返回 0
}

main "$@"
```

运行：

```bash
chmod +x backup.sh
./backup.sh -v -d /tmp/bk a.txt docs nofile
```

可能的输出：

```
[INFO] 已备份: a.txt
[INFO] 已备份: docs
跳过: nofile 不存在
[INFO] 完成，失败 1 个
```

最后用 `echo $?` 查看，状态码是 1（有一个失败）。

这个脚本用到了前面所有章节的知识：参数展开、引号、`if`/`case`/`for`、函数、`local`、`getopts`、`shift`、重定向到 stderr、退出状态码。

## 本章小结

- 函数：`name() { ...; }`；函数内的 `$1` 是函数参数；**变量默认全局，务必用 `local`**；`local x=$(cmd)` 要拆成两行。
- `return n` 返回状态（0~255），`echo` 输出数据并用 `$(...)` 捕获；`exit` 结束整个脚本。
- 位置参数：`$0 $1 ... $# $@ $*`；转发参数用 `"$@"`；`shift` 移走参数。
- `getopts ":vn:h" opt`：处理短选项，配合 `OPTARG`、`OPTIND` 和 `shift $((OPTIND-1))`。
- `source` 在当前 Shell 执行；用 `$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)` 定位脚本目录。
- 子 Shell 里的变量修改不会回到父 Shell；管道里的 `while` 是子 Shell，要用 `done < file`。
- 脚本结构：函数 + `main "$@"`，用退出状态码表达结果。

## 常见问题速查

| 现象 | 原因 |
|------|------|
| `command not found`（调用自己写的函数） | 函数定义在调用之后，或在另一个文件中未 `source` |
| 函数里改了变量，意外影响了外面 | 变量默认是全局的，加 `local` |
| `local out=$(cmd)` 吞掉了失败状态 | 分成 `local out` 与 `out=$(cmd)` 两行 |
| 参数含空格被拆开 | 转发时没写成 `"$@"` |
| `getopts` 读不到后面的选项 | 选项写在了位置参数之后 |
| 管道里的循环结束后变量没变化 | 管道右侧在子 Shell 中，改用 `done < file` |
| 从别的目录运行脚本时 `source` 失败 | 路径是相对工作目录，改用 `$SCRIPT_DIR` |
