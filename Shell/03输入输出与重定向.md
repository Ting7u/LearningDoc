# 第 3 章　输入输出、重定向与管道

## 本章目标

- 理解标准输入、标准输出、标准错误以及文件描述符 0 / 1 / 2
- 掌握重定向：`>`、`>>`、`<`、`2>`、`2>&1`、`&>`
- 会用管道 `|` 把多个小命令组合起来
- 会用 `tee`、Here Document、Here String

> 这一章是 Shell 的灵魂：**每个命令只做一件事，用管道和重定向把它们拼起来**。
> 第 4 章的文本处理工具全都建立在这一章的基础上。

## 3.1 三个标准流

每个进程启动时，默认打开三个「文件」：

| 名称 | 文件描述符（fd） | 默认连接到 | 用途 |
|------|:---:|-----------|------|
| 标准输入 stdin | 0 | 键盘 | 命令从这里读数据 |
| 标准输出 stdout | 1 | 终端屏幕 | 命令的正常输出 |
| 标准错误 stderr | 2 | 终端屏幕 | 命令的错误信息 |

```
            ┌──────────┐
 键盘 ─0──▶ │   命令   │ ─1──▶ 屏幕（正常输出）
            │          │ ─2──▶ 屏幕（错误输出）
            └──────────┘
```

> **C 语言类比**：这三个就是 C 里的 `stdin`、`stdout`、`stderr`。
> `printf` 写到 fd 1，`fprintf(stderr, ...)` 写到 fd 2；
> 底层的 `read(0, ...)` / `write(1, ...)` 用的就是这些数字。
> Shell 的重定向，本质上就是在启动程序前，用类似 `dup2()` 的方式把这些 fd 指向别的文件。

### 为什么要把输出和错误分开？

看一个例子：

```bash
ls /tmp /nonexistent
```

会同时出现 `/tmp` 的内容（stdout）和一条 `No such file or directory` 的报错（stderr）。
它们都显示在屏幕上，看起来混在一起，但其实是两个不同的流，可以**分别处理**。

## 3.2 输出重定向

### `>`：把 stdout 写入文件（覆盖）

```bash
echo "hello" > a.txt        # a.txt 内容变成 hello（文件不存在则创建）
echo "world" > a.txt        # 覆盖！a.txt 内容变成 world
ls /tmp > list.txt          # 把目录列表保存到文件
```

### `>>`：追加

```bash
echo "line1" >> log.txt
echo "line2" >> log.txt     # log.txt 里有两行
```

### `2>`：把 stderr 写入文件

```bash
ls /nonexistent 2> err.txt          # 错误信息进 err.txt，屏幕上什么都不显示
ls /tmp /nonexistent > out.txt 2> err.txt   # 正常输出和错误分别存两个文件
ls /nonexistent 2>> err.txt         # 追加错误
```

`>` 其实是 `1>` 的简写；`2>` 中的 `2` 是 fd 号。

### 合并两个流：`2>&1` 和 `&>`

`2>&1` 的意思是「让 fd 2 指向 fd 1 当前指向的地方」：

```bash
ls /tmp /nonexistent > all.txt 2>&1     # stdout 和 stderr 都写进 all.txt
```

bash 里还有更简洁的写法（**非 POSIX**，sh/dash 里可能不支持）：

```bash
ls /tmp /nonexistent &> all.txt         # 等价于 > all.txt 2>&1
ls /tmp /nonexistent &>> all.txt        # 追加版本（bash 4 及以上）
```

### ⚠️ 顺序很重要

重定向是**从左到右依次处理**的：

```bash
ls /nonexistent > out.txt 2>&1    # ✅ 先让 stdout 指向文件，再让 stderr 跟着 stdout → 都进文件
ls /nonexistent 2>&1 > out.txt    # ❌ 先让 stderr 跟着 stdout（此时还指向屏幕），再改 stdout → 错误仍显示在屏幕上
```

记忆口诀：**`> 文件 2>&1`，先指文件，再合并。**

### `/dev/null`：黑洞

写入 `/dev/null` 的内容会被直接丢弃：

```bash
ls /nonexistent 2> /dev/null            # 丢掉错误信息
command > /dev/null 2>&1                # 丢掉所有输出（只关心是否成功时常用）
```

### 向 stderr 输出自己的信息

写脚本时，错误提示应该输出到 stderr：

```bash
echo "Error: file not found" >&2        # 把 stdout 重定向到 fd 2
```

`>&2` 的意思是「让这条命令的 stdout 指向 stderr」。

### ⚠️ 经典陷阱：读写同一个文件

```bash
sort data.txt > data.txt      # ❌ 文件被清空！
```

原因：Shell 在**启动 sort 之前**就先执行了 `> data.txt`，把文件清空（截断），
sort 读到的已经是空文件。

正确做法：

```bash
sort data.txt > tmp.txt && mv tmp.txt data.txt    # 用临时文件
sort -o data.txt data.txt                          # sort 自带 -o 选项，可以安全地原地输出
```

### 防止误覆盖

```bash
set -o noclobber       # 开启后，> 不能覆盖已存在的文件
echo x > a.txt         # 如果 a.txt 已存在会报错
echo x >| a.txt        # >| 强制覆盖
set +o noclobber       # 关闭
```

## 3.3 输入重定向

### `<`：把文件内容作为 stdin

```bash
wc -l < a.txt          # 输出行数（只有数字）
wc -l a.txt            # 输出行数和文件名（命令自己打开文件）
```

两者的区别：用 `<` 时，`wc` 并不知道文件名，它只是从 stdin 读数据，所以只输出数字。
这个特点在脚本里取行数时很有用。

很多命令在**不给文件参数**时，默认从 stdin 读：

```bash
cat                    # 不带参数：读取键盘输入，原样输出（按 Ctrl+D 结束输入）
sort                   # 同理，输入若干行后按 Ctrl+D，会输出排序结果
```

### 一个常见误区：不是所有命令都读 stdin

```bash
echo "abc" | echo      # 什么也不输出：echo 只打印参数，不读 stdin
echo "abc" | cat       # 输出 abc：cat 会读 stdin
```

命令分两类：

- **读 stdin 的过滤器**：`cat`、`grep`、`sort`、`wc`、`head`、`tr`、`sed`、`awk` 等
- **只看参数、不读 stdin 的**：`echo`、`ls`、`rm`、`cp`、`cd` 等

要把 stdin 的内容变成「参数」，需要用 `xargs`（第 4 章讲）。

## 3.4 管道 `|`

管道把**左边命令的 stdout** 接到**右边命令的 stdin**：

```
命令1 ──stdout──▶ │管道│ ──stdin──▶ 命令2
```

### 基础例子

```bash
ls /usr/bin | wc -l              # 统计 /usr/bin 里有多少个文件
history | tail -n 5              # 最近 5 条历史命令
cat /etc/passwd | head -n 3      # 前 3 行
ls -l | less                     # 输出太长时分页查看
```

### 多级管道：统计出现次数最多的词

准备一个文件 `words.txt`：

```
apple
banana
apple
cherry
banana
apple
```

```bash
sort words.txt | uniq -c | sort -rn
```

输出：

```
      3 apple
      2 banana
      1 cherry
```

逐级解释：

1. `sort words.txt`：排序，让相同的行相邻
2. `uniq -c`：合并相邻的重复行并计数
3. `sort -rn`：按数字（`-n`）倒序（`-r`）排列

> 这就是 Unix 哲学：每个工具只做一件小事，用管道拼成强大的功能。

### 管道的几个要点

1. **只传递 stdout，不传 stderr**。错误信息仍会直接显示在屏幕上：

   ```bash
   ls /nonexistent | wc -l      # 屏幕出现报错，wc 输出 0
   ```

   想让 stderr 也进管道：

   ```bash
   ls /nonexistent 2>&1 | wc -l
   ls /nonexistent |& wc -l      # bash 的简写（非 POSIX）
   ```

2. **管道两端的命令是并发运行的**，不是先跑完左边再跑右边。
   数据一边产生一边被消费，所以处理很大的文件也不会占用大量内存。

3. **管道的退出状态**默认是**最后一个命令**的退出状态，前面的命令失败不会被发现。
   这是第 10 章要讲的 `set -o pipefail` 的由来。

> **C 语言类比**：管道对应 `pipe()` + `fork()` + `dup2()`。
> 另外一个与 C 相关的细节：C 程序的 `stdout` 在连接终端时通常是**行缓冲**，
> 而连接到管道或文件时通常是**全缓冲**，所以 `./a.out | head` 这类场景下，
> 输出可能不会实时出现；`stderr` 默认不缓冲。如果你在测试自己的 C 程序时遇到这种现象，
> 可以用 `fflush(stdout)` 或 `setvbuf` 调整。

## 3.5 `tee`：分流

管道只能「一进一出」。如果想**既保存到文件，又继续传给下一个命令（或显示在屏幕上）**，用 `tee`：

```
命令 ──▶ tee ──▶ 继续往下传
          └──▶ 同时写入文件
```

```bash
ls /usr/bin | tee list.txt | wc -l      # 保存完整列表到 list.txt，同时统计行数
make 2>&1 | tee build.log               # 一边在屏幕显示编译输出，一边存日志
echo "new line" | tee -a log.txt        # -a：追加，不覆盖
```

### `tee` 与 `sudo` 的配合

下面这样写会失败：

```bash
sudo echo "x" > /etc/some.conf      # ❌ sudo 只提升了 echo 的权限，重定向是你当前的 Shell 做的
```

因为 `>` 是由**你当前的 Shell**执行的，不属于 `sudo` 的范围。正确写法：

```bash
echo "x" | sudo tee /etc/some.conf > /dev/null      # ✅ 由 sudo 运行的 tee 来写文件
echo "x" | sudo tee -a /etc/some.conf > /dev/null   # 追加
```

## 3.6 Here Document 和 Here String

### Here Document（`<<`）：多行输入

直接在脚本里写多行文本，作为命令的 stdin：

```bash
cat <<EOF
Hello, $USER
Today is $(date +%F)
EOF
```

- `EOF` 是自己约定的结束标记（可以换成别的单词，如 `END`）
- 结束标记必须**单独占一行**，而且前面不能有空格
- 默认会做**变量替换**和**命令替换**（`$USER`、`$(date)` 会被展开）

### 禁止展开：给标记加引号

```bash
cat <<'EOF'
这里的 $USER 和 $(date) 不会被展开，原样输出
EOF
```

### 写入文件

```bash
cat > config.txt <<EOF
name=demo
version=1.0
EOF
```

### `<<-`：去掉行首的 Tab

```bash
if true; then
	cat <<-EOF
	缩进的 Tab 会被去掉
	EOF
fi
```

注意：只能去掉 **Tab**，不能去掉空格。

### Here String（`<<<`）：一个字符串作为 stdin

```bash
grep "an" <<< "banana"          # 输出 banana
wc -c <<< "abc"                 # 输出 4（here string 会在末尾自动加一个换行）
```

> `<<<` 是 bash / zsh 的特性，不是 POSIX。需要兼容 sh 时，用 `echo "abc" | grep ...` 代替。

## 本章小结

| 语法 | 作用 |
|------|------|
| `cmd > f` | stdout 写入文件（覆盖） |
| `cmd >> f` | stdout 追加到文件 |
| `cmd < f` | 从文件读 stdin |
| `cmd 2> f` | stderr 写入文件 |
| `cmd > f 2>&1` / `cmd &> f` | stdout 和 stderr 都写入文件 |
| `cmd > /dev/null 2>&1` | 丢弃所有输出 |
| `cmd1 \| cmd2` | cmd1 的 stdout → cmd2 的 stdin |
| `cmd1 2>&1 \| cmd2` | 连 stderr 一起传给 cmd2 |
| `cmd \| tee f` | 分流：写文件的同时继续往下传 |
| `cmd <<EOF ... EOF` | Here Document，多行 stdin |
| `cmd <<< "str"` | Here String，字符串作 stdin |

三个要点：

1. 重定向顺序是从左到右，`> file 2>&1` 不能写反。
2. `sort a > a` 会先清空 a；读写同一个文件要用临时文件或工具自带的原地选项。
3. 管道默认只传 stdout，并且不是所有命令都读 stdin。

## 练习

1. 执行 `ls /tmp /nonexistent`，然后分别做到：① 只保存正常输出到 `out.txt`；② 只保存错误到 `err.txt`；③ 两者都存进 `all.txt`；④ 屏幕上什么都不显示。
2. 解释 `ls /nonexistent 2>&1 > out.txt` 为什么屏幕上仍有错误信息。
3. 用 `echo` 和 `>>` 向 `log.txt` 追加三行内容，然后用 `wc -l < log.txt` 和 `wc -l log.txt` 对比输出差异。
4. 创建 `words.txt`（可以用 Here Document），然后用管道统计每个单词出现的次数，按次数倒序。
5. 用 `ls /usr/bin | tee list.txt | wc -l` 同时保存列表并统计数量。
6. 用 Here Document 生成一个三行的 `config.txt`，其中一行包含 `$HOME` 的展开值；再做一份不展开的版本，对比结果。
7. 思考：`echo hello | echo` 为什么没有输出？
8. 思考：为什么 `sudo echo x > /etc/foo` 会报权限错误，而 `echo x | sudo tee /etc/foo` 可以？

### 参考答案要点

```bash
# 1
ls /tmp /nonexistent > out.txt
ls /tmp /nonexistent 2> err.txt
ls /tmp /nonexistent > all.txt 2>&1
ls /tmp /nonexistent > /dev/null 2>&1

# 3
echo a >> log.txt; echo b >> log.txt; echo c >> log.txt
wc -l < log.txt      # 3
wc -l log.txt        # 3 log.txt

# 4
cat > words.txt <<EOF
apple
banana
apple
EOF
sort words.txt | uniq -c | sort -rn

# 6
cat > config1.txt <<EOF
home=$HOME
EOF
cat > config2.txt <<'EOF'
home=$HOME
EOF
```

- 第 2 题：`2>&1` 执行时，stdout 还指向屏幕，所以 stderr 也指向屏幕；之后 stdout 才被改到文件。
- 第 7 题：`echo` 不读 stdin。
- 第 8 题：重定向由当前 Shell 完成，没有 sudo 权限；`tee` 是由 sudo 启动的进程，有权限写文件。
