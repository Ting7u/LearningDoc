# 第 11 章　高级特性

## 本章目标

- 掌握进程替换 `<(...)`、`>(...)`，以及 `mapfile`、`coproc`
- 会做并行处理：`xargs -P`、`wait -n` 作业池、GNU parallel
- 会用 `[[ =~ ]]` 做正则匹配并取出捕获组
- 掌握高级参数展开：间接引用、nameref、`${var@Q}`、去空白等
- 理解 `eval` 的风险和替代方案；会用 `shopt` 调整行为、自定义文件描述符
- 彻底理清子 Shell 与管道里的变量作用域陷阱

> 本章以 **bash 4.x / 5.x** 为准。macOS 自带的 `/bin/bash` 是 3.2，很多特性（`mapfile`、`coproc`、`wait -n`、关联数组、`${var^^}`、`lastpipe` 等）在那里不可用。

## 11.1 进程替换：`<(...)` 与 `>(...)`

### `<(cmd)`：把命令的输出当作"文件"

```bash
diff <(sort a.txt) <(sort b.txt)          # 比较两个文件排序后的内容，不需要临时文件
comm -12 <(sort a.txt) <(sort b.txt)      # 两个文件的共同行
```

原理：bash 会把 `cmd` 的输出接到一个管道上，并把管道的**路径**（形如 `/dev/fd/63`）代替 `<(...)` 传给外层命令。外层命令以为自己拿到的是一个普通文件名：

```bash
echo <(true)                              # 输出类似 /dev/fd/63
```

这解决了"管道只能有一个输入"的限制：`diff` 需要两个文件，而管道只能提供一个 stdin。

### 解决第 7 章留下的问题：管道里的 `while` 是子 Shell

```bash
count=0
printf 'a\nb\nc\n' | while read -r line; do count=$((count + 1)); done
echo "$count"                             # 0（循环在子 Shell 里，修改丢失）

count=0
while read -r line; do
    count=$((count + 1))
done < <(printf 'a\nb\nc\n')              # 注意两个 <：前一个是重定向，后一个是进程替换
echo "$count"                             # 3
```

写法 `done < <(命令)` 的含义：把"命令的输出"当作文件，重定向给 `while` 循环；`while` 本身在**当前 Shell** 里运行，所以变量修改能保留。

### `>(cmd)`：把命令的输入当作"文件"

```bash
echo "hello" | tee >(tr a-z A-Z > upper.txt) > lower.txt
```

`tee` 把数据同时写给 `lower.txt` 和 `>(...)`。⚠️ bash 通常**不会等待** `>(...)` 里的进程结束，所以外层命令返回时，`upper.txt` 可能还没写完。需要同步时要自己设法等待，所以在脚本里 `>(...)` 比 `<(...)` 更容易出问题。

### 进程替换与 POSIX

进程替换是 bash/zsh 的特性，不是 POSIX，`dash` 里没有。也要求系统支持 `/dev/fd` 或命名管道。

## 11.2 `mapfile`（`readarray`）：把多行读入数组

bash 4.0+：

```bash
mapfile -t lines < file.txt               # 每行一个数组元素；-t 去掉行尾换行符
echo "${#lines[@]}"                       # 行数
echo "${lines[0]}"                        # 第一行
for l in "${lines[@]}"; do echo "[$l]"; done
```

配合进程替换读取命令的输出：

```bash
mapfile -t files < <(find . -name '*.txt' | sort)
echo "找到 ${#files[@]} 个文件"
```

> 注意：`find ... | sort` 这种按"行"切分的写法，文件名里含换行时会出错。需要完全安全地处理文件名，用 `-print0`，并配合 `mapfile -d ''`（bash 4.4+）：
> `mapfile -d '' -t files < <(find . -name '*.txt' -print0)`

和 `while read` 的对比：

| | `while read` 循环 | `mapfile` |
|---|---|---|
| 一次性读入 | 否，逐行处理 | 是，全部进数组 |
| 适合 | 流式处理大文件 | 需要多次访问、需要知道总行数 |
| 可用版本 | 所有 Shell | bash 4.0+ |

## 11.3 `coproc`：协同进程

`coproc` 启动一个后台进程，并给你两个文件描述符：一个用来**写入**它的标准输入，一个用来**读取**它的标准输出。bash 4.0+。

```bash
coproc UPPER { while IFS= read -r line; do printf '%s\n' "${line^^}"; done; }

echo "hello" >&"${UPPER[1]}"              # 写给协同进程（${UPPER[1]} 是写入用的 fd 号）
IFS= read -r reply <&"${UPPER[0]}"        # 读取它的输出（${UPPER[0]} 是读取用的 fd 号）
echo "$reply"                             # HELLO

exec {UPPER[1]}>&-                        # 关闭写端，让协同进程读到 EOF 后结束
wait "$UPPER_PID"                         # ${NAME}_PID 是协同进程的 PID
```

要点：

- `coproc 名字 { 命令; }`：名字用于生成数组 `名字[0]`（读）、`名字[1]`（写）和变量 `名字_PID`
- 不给名字时，数组固定叫 `COPROC`
- 要注意**缓冲**：协同进程如果是普通命令（如 `sort`），可能要读到 EOF 才输出，对话式交互会卡住
- 限制较多（例如同时存在多个协同进程时的行为），实际使用频率不高，**了解即可**；多数场景用管道、临时文件或 `xargs` 就够了

## 11.4 并行处理

### `xargs -P`：同时运行多个进程

```bash
printf '%s\n' 1 2 3 4 | xargs -P 4 -I{} sh -c 'sleep {}; echo done {}'
```

- `-P 4`：最多同时运行 4 个
- 输出顺序取决于**谁先完成**，不是输入顺序
- `-P 0`（GNU xargs）表示尽可能多地并行；一般用 `nproc` 的值：`-P "$(nproc)"`

处理文件，配合 `find -print0`（第 4 章）：

```bash
find . -name '*.log' -print0 | xargs -0 -n 1 -P 4 gzip
```

### 让 xargs 调用 bash 函数

函数不是外部命令，xargs 看不见。需要 `export -f` 导出，并用 `bash -c` 调用：

```bash
work() {
    echo "处理 $1"
    sleep 1
}
export -f work

printf '%s\n' a b c d | xargs -n 1 -P 4 bash -c 'work "$1"' _
```

写法解释：`bash -c '脚本' _ 参数`，`_` 占位 `$0`，后面的参数依次成为 `$1`、`$2`…；用 `"$1"` 而不是把 `{}` 拼进字符串，可以避免命令注入。

### 用 `wait -n` 实现作业池（bash 4.3+）

限制最多同时运行 N 个任务：

```bash
#!/usr/bin/env bash
max=3

task() {
    sleep 1
    echo "任务 $1 完成"
}

for i in {1..8}; do
    while [ "$(jobs -rp | wc -l)" -ge "$max" ]; do
        wait -n                           # 等任意一个后台任务结束
    done
    task "$i" &
done
wait                                      # 等剩下的全部结束
```

8 个各耗时 1 秒的任务，同时最多 3 个，总耗时约 3 批 ≈ 3 秒。`jobs -rp` 列出仍在运行的后台作业 PID。

### GNU parallel

比 `xargs -P` 功能更强（保持输出不交错、进度显示、远程执行等），但**不是预装的**，需要自己安装。常见用法（按我的了解；本章的沙箱里没有安装它，没有运行验证）：

```bash
parallel echo ::: a b c                   # 对每个参数并行执行 echo
parallel -j 4 gzip ::: *.log              # 最多 4 个并行
parallel --dry-run echo ::: a b c         # 只打印将要执行的命令
```

### 并行的注意事项

- 多个进程同时写同一个文件或同时输出，内容可能交错；让每个任务写自己的文件，最后再合并
- 任务之间不能有依赖
- 并行度不是越高越好，受 CPU、磁盘、网络、对方服务器限制

## 11.5 正则匹配：`[[ string =~ regex ]]`

bash 的 `[[ ]]` 支持**扩展正则（ERE）**匹配，并把捕获的内容放进数组 `BASH_REMATCH`：

```bash
date="2026-11-26"
re='^([0-9]{4})-([0-9]{2})-([0-9]{2})$'

if [[ $date =~ $re ]]; then
    echo "整体: ${BASH_REMATCH[0]}"        # 2026-11-26
    echo "年:   ${BASH_REMATCH[1]}"        # 2026
    echo "月:   ${BASH_REMATCH[2]}"        # 11
    echo "日:   ${BASH_REMATCH[3]}"        # 26
fi
```

规则：

- **正则放在变量里，使用时不加引号**：`[[ $s =~ $re ]]`。如果把正则直接写在 `=~` 右边并加引号，bash 会把它当作**字面字符串**而不是正则
- 用的是 ERE：写 `[0-9]`、`[[:digit:]]`，**不要**用 `\d`（`\d` 不是 ERE 的标准写法，在 bash 里不会表示数字）
- `BASH_REMATCH[0]` 是整个匹配，`[1]`、`[2]`… 是各个括号分组
- 匹配失败时 `BASH_REMATCH` 会被清空

结合第 5 章的前导 0 问题：从日期里取出的月份 `08` 做算术运算前，要用 `10#` 前缀：

```bash
month=$((10#${BASH_REMATCH[2]}))
```

忽略大小写：

```bash
shopt -s nocasematch
[[ "HELLO" =~ ^hello$ ]] && echo "匹配"
shopt -u nocasematch
```

校验输入的例子：

```bash
is_int() { [[ $1 =~ ^-?[0-9]+$ ]]; }
is_int 42 && echo "整数"
is_int 4.2 || echo "不是整数"
```

## 11.6 高级参数展开

### 间接引用：变量里放着另一个变量的名字

```bash
name="HOME"
echo "${!name}"                           # 输出 $HOME 的值
```

列出以某个前缀开头的变量名：

```bash
MY_A=1; MY_B=2
echo "${!MY_@}"                           # MY_A MY_B
```

### nameref：给变量起别名（bash 4.3+）

```bash
target="hello"
declare -n ref=target                     # ref 是 target 的别名
echo "$ref"                               # hello
ref="world"                               # 修改 ref 就是修改 target
echo "$target"                            # world
```

函数里用 nameref 可以"通过名字返回结果"，不需要 `$(...)`，也就不会因为子 Shell 丢失变量：

```bash
get_info() {
    local -n out=$1                       # out 指向调用者传来的变量名
    out="some value"
}
get_info result
echo "$result"                            # some value
```

### `${var@Q}` 与 `printf %q`：生成可安全重用的引用形式

```bash
s="it's a test; rm -rf /"
echo "${s@Q}"                             # bash 4.4+：加上引号，可以安全地粘贴回命令行
printf '%q\n' "$s"                        # 另一种转义形式，更早的 bash 也有
```

### 去掉首尾空白

```bash
trim() {
    local s="$1"
    s="${s#"${s%%[![:space:]]*}"}"        # 去掉开头的空白
    s="${s%"${s##*[![:space:]]}"}"        # 去掉结尾的空白
    printf '%s' "$s"
}
trim "   hello  world   "                 # 输出 hello  world
```

解读第一行：`${s%%[![:space:]]*}` 取出"开头那段连续空白"（删掉从第一个非空白字符开始的最长后缀），再用 `${s#...}` 把这段空白从开头删掉。不需要 `sed`，也没有子 Shell。

### 其他常用

```bash
printf -v padded '%05d' 42                # 把格式化结果存进变量，不输出：padded=00042
IFS=: read -ra parts <<< "a:b:c"          # 按 : 切成数组 parts
echo "${parts[1]}"                        # b

declare -i n=5                            # 整数属性：赋值时自动做算术
n+=2; echo "$n"                           # 7
declare -r K=1                            # 只读（等价 readonly）

arr=(apple banana cherry)
echo "${arr[@]/a/A}"                      # 对每个元素做替换：Apple bAnana cherry
echo "${#arr[1]}"                         # 第 2 个元素的长度：6
declare -p arr                            # 查看变量的完整定义和属性
```

## 11.7 `shopt`：调整 bash 的行为

`shopt -s 选项` 开启，`shopt -u 选项` 关闭，`shopt 选项` 查看当前状态。

| 选项 | 作用 |
|------|------|
| `nullglob` | 通配符没有匹配时展开为**空**（而不是保留原样）。解决第 5、6 章里 `for f in *.txt` 的问题 |
| `failglob` | 通配符没有匹配时报错 |
| `dotglob` | 让 `*` 也匹配以 `.` 开头的隐藏文件 |
| `nocaseglob` | 通配符忽略大小写 |
| `globstar` | `**` 递归匹配多层目录（bash 4.0+） |
| `extglob` | 扩展通配符：`+(...)`、`!(...)`、`@(...)`、`*(...)`、`?(...)` |
| `nocasematch` | `case`、`[[ ]]` 的匹配忽略大小写 |
| `lastpipe` | 管道最后一个命令在**当前 Shell** 里运行（bash 4.2+，仅在作业控制关闭时有效，脚本中默认满足） |

```bash
shopt -s nullglob
files=(*.nonexistent)
echo "${#files[@]}"                       # 0（而不是 1）

shopt -s globstar
echo **/*.txt                             # 当前目录下所有层级的 .txt 文件

shopt -s extglob
echo !(*.log)                             # 所有不以 .log 结尾的文件
```

⚠️ `extglob` 要在使用它的那一行**被解析之前**开启：`shopt -s extglob` 和用到 `!(...)` 的命令要写在不同的行（不能用 `;` 连在同一行，也不能放在同一个复合命令里）。

## 11.8 自定义文件描述符与 `exec`

第 3 章讲了 0/1/2。你可以用 `exec` 打开更多的 fd（3 以上），或者永久改变脚本自身的标准流。

### 保存、重定向、恢复标准输出

```bash
exec 3>&1                                 # 把 fd 3 指向当前的 stdout（保存）
exec >log.txt                             # 之后脚本的 stdout 都写入 log.txt
echo "这行进入 log.txt"
exec 1>&3 3>&-                            # 恢复 stdout，并关闭 fd 3
echo "这行回到屏幕"
```

### 打开文件供多次读写

```bash
exec 4< input.txt                         # 以读方式打开，fd 4
read -r first <&4                         # 从 fd 4 读一行
read -r second <&4                        # 接着读下一行（位置保留）
exec 4<&-                                 # 关闭
```

### 让 bash 自动分配 fd 号（bash 4.1+）

```bash
exec {fd}< input.txt                      # fd 号存进变量 $fd
read -r line <&"$fd"
exec {fd}<&-
```

### `read` 的几个实用选项

```bash
read -r -t 5 -p "5 秒内输入: " ans         # -t 超时秒数，超时返回状态 > 128
read -r -s -p "密码: " pw; echo           # -s 不回显
read -r -n 1 -p "按任意键继续" _; echo     # -n 1 只读一个字符
read -r -d '' content < file.txt          # -d '' 以 NUL 为结束符（可一次读入整个文件）
```

## 11.9 `eval`：风险与替代方案

`eval` 把它的参数**当作一行 Shell 代码再解析并执行一次**：

```bash
cmd='echo hello'
eval "$cmd"                               # hello
```

### 危险：注入

```bash
input='x; echo INJECTED'
eval "echo $input"                        # 输出 x 和 INJECTED —— 分号后的内容被当成了命令
```

只要有一点不可信的数据进入 `eval`，就等于让对方执行任意命令。所以：

> **原则：能不用 `eval` 就不用；必须用时，只能喂给它完全由你控制的内容。**

### 常见需求的安全替代

**动态变量名**（"有一个变量，名字是拼出来的"）：

```bash
# ✗ eval "var_$i=$i"
printf -v "var_$i" '%s' "$i"              # ✓ 给名字叫 var_N 的变量赋值
echo "${var_2}"
```

用 `printf -v` 之前，如果变量名来自外部输入，先校验名字：

```bash
[[ $name =~ ^[A-Za-z_][A-Za-z0-9_]*$ ]] || die "非法变量名"
```

**读取"名字存在变量里的变量"**：用间接引用 `${!name}` 或 nameref（11.6），不要 `eval "echo \$$name"`。

**按键存取**：用**关联数组**（第 5 章），而不是拼出一堆变量名。

**拼装命令**：用**数组**（第 10 章 10.9），而不是把命令拼成字符串再 `eval`。

### 可以接受的用法

对**来自可信程序**的输出执行 `eval` 是常见做法，例如启动 ssh-agent 时的 `eval "$(ssh-agent -s)"`：这个程序的输出就是一段设置环境变量的 Shell 代码。但是前提是你信任这个程序，并且它的输出不含外部可控的内容。

## 11.10 子 Shell 与变量作用域陷阱（汇总）

第 7 章讲了基本概念，这里把常见的陷阱和解法放在一起。

### 陷阱 1：管道里的循环

```bash
count=0
printf 'a\nb\n' | while read -r l; do count=$((count + 1)); done
echo "$count"                             # 0
```

**解法**：

| 解法 | 写法 | 要求 |
|------|------|------|
| 输入重定向 | `while ...; done < file` | 所有 Shell |
| 进程替换 | `while ...; done < <(cmd)` | bash/zsh |
| Here String | `while ...; done <<< "$data"` | bash/zsh |
| `lastpipe` | `shopt -s lastpipe` 后管道最后一段在当前 Shell 运行 | bash 4.2+，脚本中有效 |
| 同一个子 Shell 里完成 | `printf ... \| { count=0; while ...; done; echo "$count"; }` | 所有 Shell |

### 陷阱 2：命令替换里的赋值也会丢

```bash
x=$(y=5; echo hi)
echo "[$y]"                               # []  y 是在子 Shell 里设置的
```

函数如果用 `$(func)` 调用，函数内部对全局变量的修改也会丢失。需要同时得到输出和修改时，用 nameref（11.6）、`printf -v`，或者把结果写到约定的全局变量里并直接调用（不用 `$(...)`）。

### 陷阱 3：管道里的 `exit` 只退出子 Shell

```bash
printf 'a\n' | while read -r l; do exit 3; done
echo "脚本还在继续，状态=$?"
```

在管道里的循环中想要终止整个脚本，需要先把循环改成不在子 Shell 里运行（见陷阱 1 的解法），或者让循环以某个状态结束，脚本再检查这个状态。

### 陷阱 4：后台任务也是子 Shell

```bash
x=1
{ x=2; } &
wait
echo "$x"                                 # 1
```

### 陷阱 5：`$$` 在子 Shell 里不变

```bash
echo "$$"
( echo "$$" "$BASHPID" )                  # $$ 仍是父 Shell 的 PID，$BASHPID 才是当前子 Shell 的 PID
```

和第 8 章对照：`$$` 永远是**最初那个 Shell** 的 PID。要拿子 Shell 自己的 PID 用 `$BASHPID`（bash 特有）。

## 11.11 综合例子：并行校验文件

对目录下所有 `.txt` 文件并行计算校验和，限制并发数，结果合并输出。

```bash
#!/usr/bin/env bash
set -euo pipefail
shopt -s nullglob

jobs_max="${JOBS:-4}"
outdir="$(mktemp -d "${TMPDIR:-/tmp}/sums.XXXXXX")"
trap 'rm -rf -- "$outdir"' EXIT

files=(./*.txt)
[ "${#files[@]}" -gt 0 ] || { echo "没有 .txt 文件" >&2; exit 1; }

sum_one() {
    local f=$1
    sha256sum -- "$f" > "$outdir/${f##*/}.sum"
}

for f in "${files[@]}"; do
    while [ "$(jobs -rp | wc -l)" -ge "$jobs_max" ]; do
        wait -n
    done
    sum_one "$f" &
done
wait

cat -- "$outdir"/*.sum | sort -k2
```

用到了：`nullglob`（11.7）、数组、`wait -n` 作业池（11.4）、每个任务写自己的文件避免输出交错、`mktemp` + `trap`（第 10 章）。
`sha256sum` 是 GNU coreutils 里的命令；macOS 上对应的是 `shasum -a 256`。

## 本章小结

- `<(cmd)` 把命令输出当文件用，`done < <(cmd)` 解决管道里的循环变量丢失；`mapfile` 一次读多行进数组。
- 并行：`xargs -P`、`export -f` 配合 `bash -c`、`wait -n` 作业池（bash 4.3+）、GNU parallel（需另装）。
- `[[ $s =~ $re ]]`：正则放变量里且不加引号，捕获在 `BASH_REMATCH`，不要用 `\d`。
- 高级展开：`${!name}`、`declare -n`、`${var@Q}`、`printf -v`、`IFS=: read -ra`。
- `shopt`：`nullglob`、`globstar`、`extglob`、`lastpipe` 等；`exec` 可以重定向脚本自身的输出、打开自定义 fd。
- `eval` 能不用就不用；动态变量名用 `printf -v`、间接引用、关联数组；拼命令用数组。
- 子 Shell 里的变量修改不会回到父 Shell：管道、`$(...)`、`&`、`( )` 都是子 Shell。

## 练习

1. 用 `diff <(...) <(...)` 比较两个目录各自的文件名列表（`ls` 的输出），找出差异。
2. 用 `while read ... done < <(...)` 统计 `/etc/passwd` 中登录 Shell 为 `/bin/bash` 的用户数，并确保统计结果在循环结束后仍然可用。
3. 用 `mapfile -t` 把一个文件读入数组，输出行数和最后一行。
4. 用 `xargs -P 4` 并行执行 8 个 `sleep 1`，用 `date +%s` 验证总耗时约 2 秒（8 个任务，每批 4 个）。
5. 用 `wait -n` 实现最大并发数为 2 的作业池，运行 6 个耗时 1 秒的任务，验证总耗时约 3 秒。
6. 用 `[[ =~ ]]` 校验形如 `192.168.1.10` 的字符串（四段 1~3 位数字，不要求每段 ≤ 255），并取出每一段。
7. 写一个 `trim` 函数（11.6），测试首尾带空格、全是空格、空字符串三种输入。
8. 用 `declare -n` 写一个函数 `set_greeting`，通过变量名参数给调用者的变量赋值。
9. 演示 `eval "echo $input"` 的注入问题，然后用安全的方式达到"动态创建变量 `var_1 var_2 var_3`"的目的。
10. 分别用三种方式修复"管道里的 `while` 循环计数丢失"的问题。

### 参考答案要点

# 2

while IFS=: read -r user _ _ _ _ _ shell; do
    [ "$shell" = "/bin/bash" ] && count=$((count + 1))
done < <(cat /etc/passwd)
echo "$count"
# 注意：[ ... ] && ... 作为循环体最后一条命令，条件为假时循环状态为 1；

# 4

## 常见问题速查

| 现象 | 原因 |
|------|------|
| `syntax error near unexpected token '('`（用 `<(...)`） | 在 sh/dash 里运行，进程替换不被支持；用 `bash` |
| `mapfile: command not found` | bash 版本低于 4.0（如 macOS 自带的 3.2） |
| `wait: -n: invalid option` | bash 版本低于 4.3 |
| `[[ $s =~ "regex" ]]` 匹配不到 | 加了引号，正则被当作字面字符串；把正则放进变量，使用时不加引号 |
| `\d` 匹配不到数字 | ERE 里没有 `\d`，用 `[0-9]` 或 `[[:digit:]]` |
| `xargs` 里调用函数提示 `command not found` | 函数没有 `export -f`，或没有通过 `bash -c` 调用 |
| 并行任务的输出混在一起 | 多个进程同时写同一个输出；让每个任务写独立的文件，再合并 |
| `!(...)` 报语法错误 | `extglob` 没有开启，或开启和使用写在了同一行/同一个复合命令里 |
| `declare -n` 报错 | bash 版本低于 4.3 |
| 管道里的 `exit` 没有结束脚本 | 管道里的循环在子 Shell 里运行，`exit` 只结束子 Shell |
