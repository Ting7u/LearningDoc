# 第 8 章　进程与作业管理

## 本章目标

- 理解进程、PID、父子进程，会用 `ps`、`top`、`pgrep` 查看进程
- 理解信号机制，会用 `kill`、`pkill` 正确地结束进程
- 掌握前台与后台：`&`、`jobs`、`fg`、`bg`、`nohup`、`wait`
- 会用 `trap` 捕获信号，写出能清理现场、优雅退出的脚本

> **C 语言类比**：这一章几乎每个概念都能在 C 里找到对应：
> `fork()` / `exec()` / `waitpid()` ↔ Shell 启动命令、`wait`；
> `kill()` ↔ `kill` 命令；`signal()` / `sigaction()` ↔ `trap`。
> 你学过 C，理解这一章会比较快。

## 8.1 进程基础

**进程**是一个正在运行的程序实例。每个进程有：

| 属性 | 含义 |
|------|------|
| PID | 进程号，系统分配的唯一编号 |
| PPID | 父进程的 PID |
| 状态 | 运行、睡眠、停止、僵尸等 |
| 退出状态码 | 结束时返回给父进程的 0~255 的整数（第 6 章讲过） |

在 Shell 里运行任何外部命令，Shell 都会 `fork` 出一个子进程，再在子进程里 `exec` 那个程序，父进程（Shell）等它结束。所以：

- 你的 Shell 是命令的**父进程**
- 命令运行时有自己的 PID，结束后 Shell 用 `$?` 拿到它的退出状态

### 与进程相关的特殊变量

| 变量 | 含义 |
|------|------|
| `$$` | **当前 Shell** 的 PID |
| `$PPID` | 当前 Shell 的**父进程** PID |
| `$!` | **最近一个放到后台**的命令的 PID |
| `$?` | 最近一个前台命令的退出状态 |

```bash
echo "我的 PID: $$，父进程: $PPID"
sleep 30 &                      # 放到后台
echo "后台进程的 PID: $!"
```

### 父子进程与孤儿、僵尸

- **孤儿进程**：父进程先结束了，子进程还在运行。它会被系统的 1 号进程（init / systemd 等）收养。
- **僵尸进程**：子进程已经结束，但父进程还没调用 `wait` 取走它的退出状态，所以进程表里还留着一条记录，`ps` 里状态显示为 `Z`。父进程调用 `wait` 或自己退出后，僵尸就会被清掉。

> 僵尸进程**已经死了**，对它 `kill` 没有用；要处理的是它的父进程。

## 8.2 查看进程

### `ps`：某一时刻的进程快照

```bash
ps                      # 只显示当前终端里属于你的进程
ps aux                  # 所有用户的所有进程（BSD 风格选项，没有横线）
ps -ef                  # 所有进程（POSIX / System V 风格），多一列 PPID
ps -p 1234              # 只看某个 PID
ps -o pid,ppid,stat,etime,comm -p $$      # 自定义要显示的列
```

`ps aux` 常见的列：

| 列 | 含义 |
|----|------|
| USER | 属主 |
| PID | 进程号 |
| %CPU / %MEM | CPU、内存占用百分比 |
| VSZ / RSS | 虚拟内存 / 常驻内存大小（单位通常是 KB） |
| TTY | 所属终端，`?` 表示没有终端（常是后台服务） |
| STAT | 状态码，见下表 |
| START / TIME | 启动时间 / 累计占用的 CPU 时间 |
| COMMAND | 命令行 |

`STAT` 的第一个字母常见取值：

| 字符 | 含义 |
|:---:|------|
| `R` | 正在运行或可运行 |
| `S` | 可中断睡眠（在等待某个事件） |
| `D` | 不可中断睡眠（通常在等磁盘 I/O，`kill` 不掉） |
| `T` | 已停止（如被 Ctrl+Z 暂停） |
| `Z` | 僵尸 |

后面的附加字符（如 `+` 表示在前台进程组、`s` 表示会话首进程）不用背，遇到查 `man ps` 即可。

> ⚠️ **平台差异**：`ps` 的选项在 Linux（procps）和 macOS（BSD）上不完全相同。
> 例如列名 `cmd` 在 Linux 上可用，macOS 上要写 `command`；
> `ps --forest` 这种长选项只有 Linux 才有。上面的 `ps aux`、`ps -ef`、`ps -p PID -o pid,ppid,stat,comm` 两边通常都能用。拿不准时以本机 `man ps` 为准。

### 按名字找进程：`pgrep`

```bash
pgrep sleep             # 输出名字里含 sleep 的进程 PID
pgrep -x sleep          # -x：名字必须完全匹配
pgrep -f "backup.sh"    # -f：匹配完整命令行（而不只是进程名）
pgrep -u alice          # 只看某个用户的进程
```

常见的错误写法是 `ps aux | grep sleep`：结果里会包含 `grep sleep` 这个进程自己。用 `pgrep` 就没有这个问题。

### `top`：实时监视

```bash
top
```

进入后常用按键（具体按键因版本而异，按 `h` 看帮助）：

| 按键 | 作用 |
|:---:|------|
| `q` | 退出 |
| `k` | 输入 PID 来结束进程 |
| `P` / `M` | 按 CPU / 内存排序（Linux 版 top） |
| `1` | 显示每个 CPU 核心的占用（Linux 版 top） |

`htop` 比 `top` 更直观，但不是每个系统都预装。

### 用 `/proc` 看进程（仅 Linux）

Linux 把进程信息暴露成文件，每个进程一个目录 `/proc/PID/`：

```bash
cat /proc/$$/cmdline | tr '\0' ' '; echo     # 当前 Shell 的命令行
ls -l /proc/$$/fd                            # 当前 Shell 打开的文件描述符（0 1 2 ...）
```

这和第 3 章的文件描述符能对上：你可以直接看到 0、1、2 指向哪里。macOS 没有 `/proc`。

## 8.3 信号与 `kill`

**信号**是内核（或别的进程）发给进程的一个异步通知。进程可以：

- 执行默认动作（多数信号的默认动作是终止进程）
- 捕获信号，自己处理（对应 C 的 `signal()` / `sigaction()`，Shell 里用 `trap`）
- 忽略信号

### 常用信号

| 信号 | 编号 | 默认动作 | 常见来源 / 用途 |
|------|:---:|---------|-----------------|
| `SIGHUP` | 1 | 终止 | 终端关闭；很多服务把它当作"重新加载配置" |
| `SIGINT` | 2 | 终止 | 键盘 `Ctrl+C` |
| `SIGQUIT` | 3 | 终止并转储 | 键盘 `Ctrl+\` |
| `SIGKILL` | 9 | 终止 | **不能被捕获或忽略**，强制杀死 |
| `SIGTERM` | 15 | 终止 | `kill` 的默认信号，礼貌地要求进程退出 |
| `SIGSTOP` | — | 暂停 | **不能被捕获或忽略** |
| `SIGTSTP` | — | 暂停 | 键盘 `Ctrl+Z` |
| `SIGCONT` | — | 继续 | 让暂停的进程继续运行 |

> `SIGSTOP`、`SIGTSTP`、`SIGCONT` 的编号在 Linux 和 macOS 上**不一样**，所以表里没写数字。
> 写脚本时**用信号名**（`kill -STOP`），不要用这几个信号的数字。

用 `kill -l` 可以列出本机支持的所有信号。

### `kill`：发送信号

```bash
kill 1234               # 发送 SIGTERM（默认）
kill -TERM 1234         # 同上，显式写信号名
kill -15 1234           # 同上，用编号
kill -HUP 1234          # 发送 SIGHUP
kill -KILL 1234         # 发送 SIGKILL（等价于 kill -9）
kill -0 1234            # 不发送信号，只检查进程是否存在，且你有权限给它发信号
```

`kill -0` 在脚本里很实用：

```bash
if kill -0 "$pid" 2>/dev/null; then
    echo "进程还活着"
else
    echo "进程不存在（或无权限）"
fi
```

名字虽叫 `kill`，它只是"发信号"，不一定杀死进程。

### `pkill`：按名字发信号

```bash
pkill sleep             # 向名字含 sleep 的进程发 SIGTERM
pkill -x myapp          # 名字完全匹配
pkill -f "backup.sh"    # 按完整命令行匹配
pkill -HUP nginx        # 发送指定信号
```

⚠️ `pkill` 的模式默认是**子串匹配**，可能误杀别的进程。动手前先用同样的参数跑一遍 `pgrep`（加 `-l` 可显示名字），确认匹配到的是你想要的。

### 正确地结束一个进程

推荐顺序：

1. 先发 `SIGTERM`（`kill PID`），给进程机会清理现场、保存数据
2. 等几秒，用 `kill -0` 检查它是否退出了
3. 仍然不退出，才用 `SIGKILL`（`kill -9 PID`）

```bash
kill "$pid"
sleep 3
if kill -0 "$pid" 2>/dev/null; then
    echo "没退出，强制杀死" >&2
    kill -KILL "$pid"
fi
```

> `kill -9` 是最后手段：进程来不及做任何清理（临时文件、锁文件、未写盘的数据都会留下）。

### 被信号杀死的进程，退出状态是 `128 + 信号编号`

```bash
sleep 30 &
pid=$!
kill "$pid"
wait "$pid"
echo $?                 # 143 = 128 + 15（SIGTERM）
```

这解释了第 7 章表里 `130` 表示被 `Ctrl+C`（SIGINT，信号 2）终止。

## 8.4 前台与后台

### 前台与后台的区别

- **前台**：命令占着终端，直到结束才出现下一个提示符；键盘输入（包括 `Ctrl+C`）发给它
- **后台**：命令在后台运行，提示符立刻回来，你可以继续敲别的命令

### `&`：直接放到后台运行

```bash
sleep 60 &              # 放到后台，终端立刻可用
# 输出类似：[1] 12345    （[1] 是作业号，12345 是 PID）
```

### `Ctrl+Z`、`jobs`、`fg`、`bg`：交互式作业控制

| 操作 | 作用 |
|------|------|
| `Ctrl+Z` | 把前台进程**暂停**（发 SIGTSTP），放到后台 |
| `jobs` | 列出当前 Shell 的作业；`jobs -l` 同时显示 PID |
| `bg` | 让暂停的作业在后台**继续运行** |
| `fg` | 把后台作业**拉回前台** |
| `%1` | 指代作业号 1，如 `fg %1`、`bg %2`、`kill %1` |

典型流程：

```bash
vim notes.txt           # 编辑到一半，想先执行别的命令
# 按 Ctrl+Z
jobs                    # [1]+  Stopped   vim notes.txt
ls                      # 做别的事
fg                      # 回到 vim

sleep 100               # 一个耗时命令忘了加 &
# 按 Ctrl+Z
bg                      # 让它转到后台继续跑
jobs                    # [1]+  Running   sleep 100 &
```

> 作业控制（`jobs`、`fg`、`bg`、`Ctrl+Z`）是**交互式 Shell** 的功能。
> 在脚本里，`&` 和 `wait` 可用，但 `fg`、`bg` 一般用不上。

### 关闭终端后，后台进程会怎样？

终端关闭时，Shell 会向它的作业发送 `SIGHUP`，默认会让它们退出。想让进程在你退出登录后继续运行：

**方法一：`nohup`**（忽略 SIGHUP）

```bash
nohup ./long_task.sh > task.log 2>&1 &
```

- 不重定向输出时，`nohup` 会把输出写到当前目录的 `nohup.out`
- 上面的 `> task.log 2>&1`（第 3 章）把标准输出和错误都写进日志文件，更清晰

**方法二：`disown`**（bash 内建，把作业从 Shell 的作业表里移除）

```bash
./long_task.sh > task.log 2>&1 &
disown                  # 之后关闭终端，Shell 就不会再给它发 SIGHUP
```

**方法三：`setsid`**（在新会话中启动，常见于 Linux，macOS 默认没有这个命令）

```bash
setsid ./long_task.sh > task.log 2>&1 &
```

需要长期运行的服务，更规范的做法是交给 systemd 之类的服务管理器，这超出本教程范围。

### `wait`：等待后台进程结束

```bash
sleep 2 &
pid=$!
wait "$pid"             # 等这个进程结束
echo "它的退出状态: $?"   # wait 返回被等待进程的退出状态

wait                    # 不带参数：等待所有后台子进程结束
```

例子：并发执行，全部做完再继续。

```bash
#!/usr/bin/env bash

task() {
    echo "任务 $1 开始"
    sleep "$1"
    echo "任务 $1 完成"
}

task 3 &
task 1 &
task 2 &

wait                    # 等三个任务都结束
echo "全部完成"
```

总耗时约 3 秒（并发），而不是 6 秒（顺序）。

收集每个任务的结果：

```bash
pids=()
for n in 1 2 3; do
    sleep "$n" &
    pids+=("$!")
done

failed=0
for pid in "${pids[@]}"; do
    wait "$pid" || failed=$((failed + 1))
done
echo "失败 $failed 个"
```

`wait -n`（等待**任意一个**后台作业结束）需要 bash 4.3 及以上，老版本（如 macOS 自带的 bash 3.2）没有，用之前请先 `bash --version` 确认。

> ⚠️ `$!` 要**紧接着 `&` 之后**取，否则后面又启动了别的后台任务，`$!` 就变了。
> 另外，管道 `a | b &` 里 `$!` 是管道里**最后一个命令**的 PID。

## 8.5 `trap`：捕获信号与清理现场

`trap` 让脚本在收到信号、或在脚本退出时执行指定的命令。对应 C 里的 `signal(SIGINT, handler)` 和 `atexit()`。

### 基本语法

```bash
trap '命令' 信号1 信号2 ...
```

```bash
trap 'echo "收到 Ctrl+C，但我不退出"' INT
trap -p                 # 列出当前已设置的 trap
trap - INT              # 把 INT 恢复为默认行为
trap '' INT             # 忽略 INT（空命令）
```

要点：

- 信号名可以带 `SIG` 前缀，也可以不带：`INT` 和 `SIGINT` 等价
- `SIGKILL` 和 `SIGSTOP` **不能**被捕获
- 命令用**单引号**括起来：这样变量在 trap **触发时**才展开；用双引号的话，变量在**设置 trap 时**就展开了

### 伪信号 `EXIT`

`trap '命令' EXIT` 表示脚本**退出时**执行命令（不论是正常结束、`exit`，还是 `set -e` 导致的退出）。这是做清理最常用的办法：

```bash
#!/usr/bin/env bash

tmpfile=$(mktemp)                     # 创建临时文件（第 10 章会详细讲 mktemp）
cleanup() {
    rm -f -- "$tmpfile"
    echo "已清理 $tmpfile" >&2
}
trap cleanup EXIT

echo "工作中..." > "$tmpfile"
sleep 1
echo "完成"
# 脚本结束时，cleanup 自动执行
```

### 让 Ctrl+C 和 kill 也能触发清理

为了不依赖"被信号杀死时 EXIT 陷阱是否执行"这类默认行为，推荐显式把信号转成 `exit`，再由 `EXIT` 陷阱统一清理：

```bash
#!/usr/bin/env bash

tmpdir=$(mktemp -d)
cleanup() {
    rm -rf -- "$tmpdir"
    echo "清理完毕" >&2
}
trap cleanup EXIT
trap 'exit 130' INT        # Ctrl+C：按惯例退出码是 128 + 2
trap 'exit 143' TERM       # kill：按惯例退出码是 128 + 15

echo "临时目录: $tmpdir"
sleep 60                   # 模拟长时间工作，期间被中断也能清理
```

### 优雅退出：收到信号后，把当前这一轮做完

```bash
#!/usr/bin/env bash

running=1
trap 'running=0' INT TERM

while [ "$running" -eq 1 ]; do
    echo "处理一批数据..."
    sleep 1 &              # 用后台 sleep + wait，信号到来时 wait 会被打断，响应更快
    wait $!
done

echo "收到信号，已优雅退出"
```

> bash 在前台命令运行期间收到信号，会**等这个命令结束后**才执行 trap 的命令。
> 所以上面把 `sleep 1` 放到后台再 `wait`：`wait` 内建命令会被已捕获的信号立即打断，响应更及时。
> 被打断后后台那个 `sleep 1` 会留着自己跑完，只是一个很短的残留。

### 其他常见用途

```bash
trap 'echo "第 $LINENO 行出错" >&2' ERR     # 命令失败时触发（bash 特性，第 10 章会和 set -e 一起讲）
trap 'rm -f "$lockfile"' EXIT                # 释放锁文件
```

### 一个带锁文件的"防重复运行"例子

```bash
#!/usr/bin/env bash

lockfile=/tmp/myjob.lock

if ! ( set -o noclobber; echo "$$" > "$lockfile" ) 2>/dev/null; then
    echo "已有实例在运行（PID $(cat "$lockfile")）" >&2
    exit 1
fi
trap 'rm -f "$lockfile"' EXIT

echo "开始工作..."
sleep 5
```

这里利用了第 3 章的 `noclobber`：文件已存在时重定向会失败，从而判断出已经有实例在运行。
（这个办法在遇到 `kill -9` 时锁文件会残留；简单场景够用，严格场景可用 `flock`，它不是所有系统都有。）

## 8.6 综合例子：简易任务监控脚本

`watch_proc.sh`：监控某个进程，消失后输出提示并退出；收到 Ctrl+C 时清理退出。

```bash
#!/usr/bin/env bash
#
# watch_proc.sh - 等待某个 PID 结束
# 用法: watch_proc.sh PID

pid="${1:?用法: $0 PID}"

if ! kill -0 "$pid" 2>/dev/null; then
    echo "进程 $pid 不存在" >&2
    exit 1
fi

start=$(date +%s)
cleanup() { echo "监控结束" >&2; }
trap cleanup EXIT
trap 'exit 130' INT
trap 'exit 143' TERM

echo "开始监控 PID $pid"
while kill -0 "$pid" 2>/dev/null; do
    sleep 1
done

echo "进程 $pid 已结束，历时 $(( $(date +%s) - start )) 秒"
```

试一试：

```bash
sleep 5 &
./watch_proc.sh $!
```

## 本章小结

- 进程有 PID、PPID；`$$` 是当前 Shell 的 PID，`$!` 是最近后台进程的 PID。
- 查看进程：`ps aux` / `ps -ef`、`pgrep`、`top`；不要用 `ps | grep` 找自己。
- 信号：`kill` 默认发 `SIGTERM`；先 TERM 后 KILL；`kill -0` 检查进程是否存在；被信号杀死的退出状态是 `128 + 信号编号`。
- 后台：`&`、`jobs`、`fg`、`bg`、`wait`；让进程在关闭终端后继续运行用 `nohup` 或 `disown`。
- `trap '命令' 信号`：`EXIT` 用于清理；把 `INT`、`TERM` 转成 `exit` 让清理总能执行；`SIGKILL` 不可捕获。

2. 在后台运行 `sleep 100`，打印它的 PID，用 `ps -p` 查看它，然后用 `kill` 结束它，再用 `kill -0` 确认它已经不存在。
3. 在后台运行 `sleep 100`，结束它，用 `wait` 取得退出状态，解释这个数字的含义。

5. 写一个脚本：创建临时文件，用 `trap ... EXIT` 保证脚本无论正常结束还是被 `kill` 都会删除这个文件，然后在另一个终端（或后台运行后）用 `kill` 验证。
6. 写脚本循环输出时间，每秒一次，收到 `SIGTERM` 或 `SIGINT` 时打印"再见"并退出。
7. 用 `nohup` 运行一个会持续输出的命令，并把输出写进日志文件，然后用 `tail -f` 观察。
8. 解释：为什么 `kill -9` 不应该是你的第一选择？为什么 `trap` 不能捕获 `SIGKILL`？
9. 思考：`ps aux | grep sleep` 的结果里，为什么常常多出一行？怎样避免？

### 参考答案要点

```bash
# 1

# 2

ps -p "$pid"
kill "$pid"
sleep 0.2                  # 给信号一点时间生效
kill -0 "$pid" 2>/dev/null || echo "已经不存在"

# 3
sleep 100 &
pid=$!
kill "$pid"
wait "$pid"
echo $?                    # 143 = 128 + 15

# 4
start=$(date +%s)
sleep 3 & sleep 1 & sleep 2 &
wait
echo "耗时 $(( $(date +%s) - start )) 秒"

# 5
tmp=$(mktemp)
trap 'rm -f -- "$tmp"' EXIT
trap 'exit 143' TERM
trap 'exit 130' INT
sleep 60

# 6
trap 'echo 再见; exit 0' INT TERM
while true; do date; sleep 1; done

# 7
nohup sh -c 'while true; do date; sleep 1; done' > out.log 2>&1 &
tail -f out.log
```

- 第 8 题：`SIGKILL` 由内核直接终止进程，进程来不及做任何清理；`SIGKILL` 和 `SIGSTOP` 之所以不能被捕获，是为了保证系统管理员总有办法终止或暂停失控的进程。
- 第 9 题：`grep sleep` 自己的命令行里也含有 `sleep`，所以它也被列出来；用 `pgrep sleep`，或 `ps aux | grep '[s]leep'`（方括号技巧使 grep 自己的命令行不再匹配模式）。

## 常见问题速查

| 现象 | 原因 |
|------|------|
| `kill` 之后进程还在 | 进程捕获或忽略了 SIGTERM；或在 `D` 状态等 I/O；先确认再决定是否 `kill -9` |
| `kill: (123) - No such process` | PID 已不存在，或写错了 |
| `kill: Operation not permitted` | 这个进程不属于你，需要 `sudo` |
| 关闭终端后后台任务也没了 | 收到了 SIGHUP；用 `nohup` 或 `disown` |
| `nohup: ignoring input and appending output to 'nohup.out'` | 没有重定向输出；改写成 `nohup cmd > log 2>&1 &` |
| `$!` 为空 | 还没有启动过后台命令，或取得太晚被覆盖 |
| trap 里的变量值不对 | trap 命令用了双引号，变量在设置时就展开了，改用单引号 |
| `fg: no job control` | 在脚本里（非交互式 Shell）不能用作业控制 |
