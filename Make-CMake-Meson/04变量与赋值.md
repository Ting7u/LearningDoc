# 第 4 章 变量与赋值

> 本章目标:掌握 Makefile 变量的所有赋值方式及其展开时机,理解变量的来源与优先级,学会使用目标特定变量、多行变量、约定变量和替换引用。变量是写出"不重复、可配置"的 Makefile 的基础。
>
> **最重要的一个概念**:make 变量有"**递归展开**"与"**立即展开**"两种风味,二者的区别决定了许多行为,务必弄清。

**本章结构**

1. 变量的定义与引用
2. 变量的两种风味与五种赋值运算符
3. 变量的来源与优先级
4. `override`、`export`、`unexport`
5. 目标特定变量与模式特定变量
6. 多行变量 `define ... endef`
7. 约定变量与内置变量
8. 变量替换引用
9. 其他细节与常见陷阱
10. 小结与练习

## 4.1 变量的定义与引用

### 4.1.1 定义

```makefile
CC = gcc
CFLAGS = -Wall -O2
SRCS = main.c mathutils.c
```

- 变量名**区分大小写**,几乎可以包含任意字符(除了 `:`、`#`、`=`、空格),惯例用**大写 + 下划线**。
- 变量的值本质是**字符串**,make 没有数字/列表类型(列表就是空格分隔的字符串)。
- 等号两边的空格被忽略;**值的末尾空格会保留**(见 4.9.1)。

### 4.1.2 引用

```makefile
$(VAR)         # 推荐
${VAR}         # 等价
$V             # 单字符变量名可省括号(不推荐,易出错)
```

```makefile
app: main.o mathutils.o
	$(CC) $(CFLAGS) $^ -o $@
```

### 4.1.3 变量可用在任何地方

make 在读取 Makefile 时,变量引用可出现于:目标、依赖、命令、其他变量的值、指令(`ifeq`、`include`)甚至变量名里(嵌套引用):

```makefile
MODE = debug
CFLAGS_debug   = -g -O0
CFLAGS_release = -O2
CFLAGS = $(CFLAGS_$(MODE))        # 嵌套:先展开 $(MODE) 得 debug,再取 CFLAGS_debug
```

### 4.1.4 引用未定义的变量 → 空字符串

```makefile
$(NOT_DEFINED)    # 展开为空,不报错
```

用 `make --warn-undefined-variables` 可在引用未定义变量时给出警告。

### 4.1.5 `$` 的转义

- 要输出字面 `$`,写 `$$`。
- 命令里要给 shell 传 `$VAR`,写 `$$VAR`(第 3 章已讲)。

## 4.2 两种风味与五种赋值运算符

### 4.2.1 运算符总览

| 运算符 | 名称 | 展开时机 | 说明 |
|---|---|---|---|
| `=` | 递归展开(recursive) | **使用时**展开 | 延迟求值 |
| `:=` 或 `::=` | 立即展开(simple) | **定义时**展开 | 类似普通编程语言的赋值 |
| `:::=` | 立即展开(转义后) | 定义时展开,并把结果中的 `$` 转义 | GNU make 4.4+ |
| `?=` | 条件赋值 | 若变量未定义才赋值 | 风味同 `=` |
| `+=` | 追加 | 取决于变量原有风味 | 追加时自动加一个空格 |
| `!=` | shell 赋值 | 定义时执行 shell 命令,结果赋给变量 | GNU make 4.0+ |

### 4.2.2 递归展开 `=`:延迟求值

```makefile
A = $(B)
B = hello

all:
	@echo $(A)        # 输出 hello
```

`A` 的值保存为字符串 `$(B)`,每次**使用** `A` 时才展开。因此即使 `B` 在 `A` 之后才定义,结果仍然正确。

**优点**:可以先用后定义,便于写"可被覆盖"的配置。
**缺点**:

1. 每次使用都重新展开,**性能开销**,尤其是含 `$(shell ...)` 时每次都执行 shell:

```makefile
FILES = $(shell find . -name '*.c')     # 每次引用 $(FILES) 都会执行一次 find!
```

2. **无限递归**:

```makefile
CFLAGS = $(CFLAGS) -O2          # 错误:Recursive variable 'CFLAGS' references itself
```

### 4.2.3 立即展开 `:=`(或 `::=`):定义时求值

```makefile
A := $(B)
B := hello

all:
	@echo "A=[$(A)]"      # A=[]  因为定义 A 时 B 还未定义
```

与程序语言的赋值一致:**右边在定义这一行就被完全展开,存成结果字符串**。

```makefile
CFLAGS := -Wall
CFLAGS := $(CFLAGS) -O2        # ✔ 合法,等价 CFLAGS += -O2
```

```makefile
FILES := $(shell find . -name '*.c')    # 只执行一次
```

> `::=` 是 POSIX 标准写法,`:=` 是 GNU 的老写法,二者在 GNU make 中完全等价。**推荐优先使用 `:=`**,除非有意需要延迟求值。

### 4.2.4 对比实验

```makefile
x  = a
y  = $(x) b          # 递归:保存 "$(x) b"
z := $(x) b          # 立即:保存 "a b"
x  = c

all:
	@echo "y=[$(y)]"     # y=[c b]
	@echo "z=[$(z)]"     # z=[a b]
```

### 4.2.5 何时用哪个?

| 情形 | 推荐 |
|---|---|
| 普通配置变量(编译器、选项、文件列表) | `:=` |
| 含 `$(shell ...)` 且不想重复执行 | `:=` |
| 需要引用"稍后才定义或会被改动的变量" | `=` |
| 自动变量 `$@ $<` 用在变量值里 | `=`(因为自动变量在规则执行时才有值) |
| 作为可被用户/环境覆盖的默认值 | `?=` |
| 多行命令序列(`define`) | 默认递归展开 |

自动变量必须延迟展开:

```makefile
COMPILE = $(CC) $(CFLAGS) -c $< -o $@     # 用 = (默认):使用时才展开 $< $@
# COMPILE := ... 会在定义时把 $< $@ 展开为空,出错

%.o: %.c
	$(COMPILE)
```

### 4.2.6 条件赋值 `?=`

**仅当变量尚未定义时才赋值**,常用于提供可覆盖的默认值:

```makefile
CC ?= gcc
PREFIX ?= /usr/local
BUILD_DIR ?= build
```

```bash
make                    # 用默认值
make PREFIX=/opt/foo    # 命令行覆盖
PREFIX=/opt/foo make    # 环境变量也能覆盖
```

等价写法:

```makefile
ifndef PREFIX
  PREFIX = /usr/local
endif
```

> 注意:`CC` 在 make 中有**内置默认值**(`cc`),所以 `CC ?= gcc` **不会生效**(CC 已有定义)!要改 CC 需用 `CC := gcc` 或 `ifeq ($(origin CC),default)`(见 4.3.5)。

### 4.2.7 追加 `+=`

```makefile
CFLAGS  = -Wall
CFLAGS += -O2          # CFLAGS 变为 "-Wall -O2"(自动在中间加一个空格)
```

追加后**风味保持不变**:

- 原变量是 `:=` → 追加的内容**立即展开**;
- 原变量是 `=` → 追加的内容**延迟展开**;
- 原变量未定义 → 按 `=` 处理。

```makefile
CFLAGS += -Iinclude         # 若 CFLAGS 未定义,则等于 -Iinclude
```

常用于分模块累加:

```makefile
SRCS :=
SRCS += main.c
SRCS += mathutils.c
```

### 4.2.8 shell 赋值 `!=`

```makefile
GIT_REV != git rev-parse --short HEAD
NPROC   != nproc
```

- 等价于 `GIT_REV := $(shell git rev-parse --short HEAD)`,但**值之后会被当作递归展开变量**,若含 `$` 要小心(转义)。
- 为兼容旧 make,**更推荐 `:= $(shell ...)`**。

### 4.2.9 变量值里的空格处理

```makefile
EMPTY :=
SPACE := $(EMPTY) $(EMPTY)       # 构造一个空格
COMMA := ,
LIST  := a b c
JOINED := $(subst $(SPACE),$(COMMA),$(LIST))     # a,b,c
```

## 4.3 变量的来源与优先级

### 4.3.1 变量的 6 种来源

1. **Makefile 内定义**
2. **命令行**:`make VAR=value`
3. **环境变量**:make 启动时,所有环境变量自动变为 make 变量
4. **内置默认值**:`CC`、`CXX`、`RM`、`AR`、`MAKE` 等
5. **自动变量**:`$@ $<` 等(第 5 章)
6. **`override` 指令定义**

### 4.3.2 优先级(从高到低)

| 优先级 | 来源 |
|---|---|
| 1(最高) | Makefile 中带 `override` 的赋值 |
| 2 | **命令行**变量(`make VAR=x`) |
| 3 | Makefile 中的普通赋值 |
| 4 | 环境变量 |
| 5(最低) | make 内置默认值 |

**要点**:

- 命令行变量会**覆盖** Makefile 里的普通赋值(除非用 `override`)。
- Makefile 里的赋值**覆盖**环境变量(除非用 `make -e`)。

### 4.3.3 实验

```makefile
# Makefile
V = from_makefile

all:
	@echo "V = $(V)"
```

```bash
$ make
V = from_makefile
$ V=from_env make
V = from_makefile           # 环境变量输给 Makefile
$ V=from_env make -e
V = from_env                # -e 让环境变量胜出
$ make V=from_cmd
V = from_cmd                # 命令行胜出
$ V=from_env make V=from_cmd -e
V = from_cmd                # 命令行 > 环境
```

### 4.3.4 如何设计"可覆盖"的配置

**推荐**:Makefile 里用 `?=` 提供默认值,既可由环境变量、也可由命令行覆盖:

```makefile
CC       ?= gcc
CFLAGS   ?= -O2 -Wall
PREFIX   ?= /usr/local
```

**如果用 `=` 或 `:=`**,环境变量就不能覆盖了(命令行仍可)。

**命令行覆盖一个变量,会连带覆盖 Makefile 里对它的 `+=`**:

```makefile
CFLAGS = -Wall
CFLAGS += -Iinclude          # 命令行 make CFLAGS=-O3 时,这些赋值全部被忽略!
```

此时若想在命令行值基础上追加,使用 `override`(见 4.4.1)。

### 4.3.5 判断变量来源:`origin` 函数

```makefile
$(origin CC)
```

| 返回值 | 含义 |
|---|---|
| `undefined` | 未定义 |
| `default` | make 内置默认 |
| `environment` | 来自环境变量 |
| `environment override` | 环境变量(且使用了 `-e`) |
| `file` | Makefile 中定义 |
| `command line` | 命令行 |
| `override` | `override` 指令 |
| `automatic` | 自动变量 |

**典型用法:只在 CC 是内置默认时才改**

```makefile
ifeq ($(origin CC),default)
  CC := gcc
endif
```

### 4.3.6 查看变量的值与来源

```bash
make -p | grep -E '^(CC|CFLAGS)'      # 打印数据库中的变量
make -n --warn-undefined-variables
```

在 Makefile 里调试:

```makefile
$(info CC=$(CC), origin=$(origin CC), flavor=$(flavor CC))
```

`flavor` 返回 `undefined`、`recursive`、`simple`。

## 4.4 `override`、`export`、`unexport`

### 4.4.1 `override`:让 Makefile 的赋值压过命令行

```makefile
override CFLAGS += -Wall        # 即使用户 make CFLAGS=-O3,仍会追加 -Wall

override CC := gcc              # 强制使用 gcc,无视命令行
```

实际使用:想在用户给定的 `CFLAGS` 之上**强制追加**必须的选项(如 `-Iinclude`、`-std=c11`)。

```makefile
override CFLAGS += -Iinclude -std=c11
```

> 用户通过命令行传来的 `CFLAGS=-O3`,最终得 `-O3 -Iinclude -std=c11`。

### 4.4.2 `export` / `unexport`:传递给子进程

make 默认**只把环境变量和命令行变量**传给子进程(命令里启动的 shell、子 make);Makefile 里定义的变量默认**不传**。

```makefile
FOO = bar
test:
	@echo "shell sees: [$$FOO]"       # 空
```

```makefile
export FOO = bar            # 定义同时导出
# 或
FOO = bar
export FOO                  # 先定义,再导出
export                      # 不带参数:导出所有变量(不推荐)
```

```makefile
unexport FOO                # 不导出
```

特殊变量:

- `.EXPORT_ALL_VARIABLES:` 特殊目标,导出所有变量。
- `MAKEFLAGS`、`MAKELEVEL`、`MAKEOVERRIDES`:make 自动管理,用于递归 make(第 8 章)。

**递归 make 与命令行变量**:

```bash
make CC=clang       # 命令行变量会通过 MAKEFLAGS 自动传给子 make
```

### 4.4.3 常见用法示例

给编译器的环境变量:

```makefile
export CCACHE_DIR := $(CURDIR)/.ccache
export PATH := $(CURDIR)/tools:$(PATH)
```

## 4.5 目标特定变量与模式特定变量

### 4.5.1 目标特定变量(Target-specific)

语法:

```makefile
目标 ... : 变量赋值
```

只在**构建该目标及其所有依赖**时生效:

```makefile
CFLAGS = -O2

debug: CFLAGS = -O0 -g
debug: app

release: CFLAGS += -DNDEBUG
release: app

app: main.o mathutils.o
	$(CC) $^ -o $@

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@
```

```bash
make debug       # 用 -O0 -g 构建 app 与所有 .o
make release     # 用 -O2 -DNDEBUG
```

**特点**:

- 作用域:该目标**以及它的先决条件(递归)**。
- 不影响其他目标。
- 支持所有赋值运算符(`=`、`:=`、`?=`、`+=`)与 `override`、`export`。

**陷阱**:`app` 已存在时,先 `make debug` 再 `make release`,因文件时间戳没变,**不会重新构建**(make 不知道 CFLAGS 变了)。解决:使用不同输出目录,或在切换时 `make clean`。这也是 CMake/Ninja 支持"命令行变化重编"的优势。

### 4.5.2 模式特定变量(Pattern-specific)

对匹配某模式的所有目标生效:

```makefile
%.o: CFLAGS += -fPIC            # 所有 .o 都加 -fPIC
lib/%.o: CFLAGS += -fvisibility=hidden
test_%: LDLIBS += -lcheck
```

语法:`模式 ... : 变量赋值`。

### 4.5.3 优先级

目标特定 > 模式特定 > 全局(同一类型间的优先级与 `override` 关系类似全局)。命令行变量仍然覆盖它们(除非用了 `override`)。

## 4.6 多行变量:`define ... endef`

### 4.6.1 基本语法

```makefile
define VAR
第一行
第二行
...
endef
```

等价于变量值里含换行符。默认风味为**递归展开**(与 `=` 相同),也可写:

```makefile
define VAR :=
...
endef
```

### 4.6.2 用途一:命令序列(命令包)

```makefile
define run_tests
	@echo "Running tests..."
	./test1
	./test2
endef

test: app
	$(run_tests)
```

展开后相当于直接把多行命令放在规则里;**每一行仍是独立的 shell**,仍可用 `@`、`-` 前缀。

### 4.6.3 用途二:带参数的"函数"(配合 `call`,第 7 章详解)

```makefile
define compile
@echo "  CC   $(2)"
@$(CC) $(CFLAGS) -c $(1) -o $(2)
endef

main.o: src/main.c
	$(call compile,$<,$@)
```

### 4.6.4 用途三:生成规则(配合 `eval`,第 7 章)

```makefile
define PROGRAM_template
$(1): $$($(1)_OBJS)
	$$(CC) $$^ -o $$@
endef
$(eval $(call PROGRAM_template,app))
```

### 4.6.5 用途四:多行文本变量

```makefile
define USAGE
Usage:
  make          build
  make clean    remove files
endef
export USAGE

help:
	@echo "$$USAGE"
```

(用 `export` + `$$USAGE` 让 shell 原样输出,避免换行与引号被 make 破坏。)

### 4.6.6 `define` 的注意点

- 命令行(以 Tab 开头)出现在 `define` 内,**只有被放进规则时才作为命令**,否则只是文本。
- 在 `define` 中的 `$` 展开遵循变量的风味规则;自动变量要靠递归展开推迟到规则里。
- 4.4+ 版本支持 `define VAR ::=` 等运算符。

## 4.7 约定变量与内置变量

### 4.7.1 编译相关的约定变量

GNU 约定(也是 make 内置隐含规则所使用的变量)。**自己写 Makefile 时遵守这些命名,能与隐含规则、用户习惯、Autotools 风格兼容。**

| 变量 | 含义 | 内置默认 | 典型值 |
|---|---|---|---|
| `CC` | C 编译器 | `cc` | `gcc` / `clang` |
| `CXX` | C++ 编译器 | `g++` | `g++` / `clang++` |
| `CPP` | C 预处理器 | `$(CC) -E` | |
| `AS` | 汇编器 | `as` | |
| `LD` | 链接器 | `ld` | |
| `AR` | 归档工具 | `ar` | |
| `ARFLAGS` | `ar` 的参数 | `rv` | 常改为 `rcs` |
| `RM` | 删除命令 | `rm -f` | |
| `CPPFLAGS` | **预处理**参数 | 空 | `-Iinclude -DNDEBUG` |
| `CFLAGS` | C 编译参数 | 空 | `-Wall -O2 -g` |
| `CXXFLAGS` | C++ 编译参数 | 空 | `-std=c++17 -Wall` |
| `LDFLAGS` | 链接器参数(库路径等) | 空 | `-L./lib -Wl,-rpath,...` |
| `LDLIBS` | 要链接的库(`-l`) | 空 | `-lm -lpthread` |
| `LIBS` | 老式写法,同 `LDLIBS` | | |
| `MAKE` | make 自身的命令名 | `make` | 递归 make 用 `$(MAKE)` |
| `MAKEFLAGS` | 传给子 make 的选项 | | |
| `MAKECMDGOALS` | 命令行指定的目标列表 | | 可用来做条件判断 |
| `CURDIR` | 当前工作目录 | | |
| `MAKEFILE_LIST` | 已读取的所有 Makefile 路径 | | |
| `SHELL` | 使用的 shell | `/bin/sh` | |
| `.VARIABLES` | 所有已定义变量名 | | 调试用 |
| `.DEFAULT_GOAL` | 默认目标 | | |
| `.RECIPEPREFIX` | 命令前缀字符 | Tab | |

**GNU 目录变量**(安装用,第 8 章详解):`prefix`、`exec_prefix`、`bindir`、`sbindir`、`libdir`、`includedir`、`datadir`、`mandir`、`DESTDIR` 等。

### 4.7.2 CPPFLAGS / CFLAGS / LDFLAGS / LDLIBS 的分工与实际写法

```makefile
CC       := gcc
CPPFLAGS := -Iinclude -DVERSION=\"1.0\"
CFLAGS   := -std=c11 -Wall -Wextra -O2
LDFLAGS  := -L./lib
LDLIBS   := -lm

%.o: %.c
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@

app: main.o mathutils.o
	$(CC) $(LDFLAGS) $^ $(LDLIBS) -o $@
```

> **链接命令里 `LDLIBS` 必须放在目标文件之后**,否则可能 `undefined reference`(第 1 章的链接顺序问题)。

### 4.7.3 内置变量的查看与关闭

```bash
make -p -f /dev/null | grep -E '^(CC|CXX|AR|RM|ARFLAGS|COMPILE\.c|LINK\.c) '
make -R                # 关闭所有内置变量
```

例如内置的 `COMPILE.c` 与 `LINK.c`:

```
COMPILE.c = $(CC) $(CFLAGS) $(CPPFLAGS) $(TARGET_ARCH) -c
LINK.c    = $(CC) $(CFLAGS) $(CPPFLAGS) $(LDFLAGS) $(TARGET_ARCH)
```

隐含规则用它们生成命令(第 5 章)。

### 4.7.4 用户习惯:CFLAGS 的"尊重原则"

在发行版或 CI 里,用户常常通过命令行/环境变量传 `CFLAGS`:

```bash
make CFLAGS="-O3 -march=native"
```

好的 Makefile 应当:**不丢掉用户给的值,同时追加项目必须的选项**:

```makefile
CFLAGS ?= -O2 -g                        # 用户没给才用默认
override CFLAGS += -std=c11 -Wall       # 无论如何都要加的
override CPPFLAGS += -Iinclude
```

## 4.8 变量替换引用

### 4.8.1 后缀替换

```makefile
$(VAR:a=b)        # 把 VAR 中每个单词末尾的 a 替换为 b
```

```makefile
SRCS := main.c mathutils.c
OBJS := $(SRCS:.c=.o)          # main.o mathutils.o
```

等价于 `$(patsubst %.c,%.o,$(SRCS))`(第 7 章)。

### 4.8.2 模式替换(含 `%`)

```makefile
SRCS := src/main.c src/mathutils.c
OBJS := $(SRCS:src/%.c=build/%.o)      # build/main.o build/mathutils.o
```

`%` 匹配任意非空字符串,等价于 `$(patsubst src/%.c,build/%.o,$(SRCS))`。这是**构建目录与源码目录分离**的常用写法。

### 4.8.3 与依赖文件配合

```makefile
DEPS := $(OBJS:.o=.d)
-include $(DEPS)
```

### 4.8.4 局限

替换引用只能做"后缀替换"或"一个 `%` 的模式替换";更复杂的字符串处理需要用第 7 章的函数。

## 4.9 其他细节与常见陷阱

### 4.9.1 末尾空格

```makefile
DIR = build 
OUT = $(DIR)/app          # 变成 "build /app" !
```

`DIR` 的值是 `build␣`(含末尾空格)。**避免**:不要在行尾留空格,尤其不要在值之后写行内注释(`DIR = build # comment` 同样带空格)。排查:

```makefile
$(info [$(DIR)])          # 输出 [build ]
```

### 4.9.2 引号不是 make 语法

```makefile
NAME = "hello"            # 变量值包含引号字符本身
```

make 不特殊处理引号,会原样保留。需要传给 shell 的引号写在命令里。

### 4.9.3 路径含空格

make 以空白分隔单词,路径含空格非常麻烦,**避免使用含空格的路径**。

### 4.9.4 宏定义里的引号转义

```makefile
CPPFLAGS += -DVERSION=\"1.0\"        # 传给编译器 -DVERSION="1.0",使 C 里 VERSION 为字符串
CPPFLAGS += -DNAME='"demo"'
```

### 4.9.5 变量展开的时机总结

| 位置 | 展开时机 |
|---|---|
| `:=` 右侧 | 定义时 |
| `=` 右侧 | 使用时 |
| 规则的**目标与依赖** | 读取 Makefile 时(立即) |
| 规则的**命令** | 命令**执行**时才展开 |
| `ifeq`、`include`、`ifdef` | 读取时(立即) |

**由此产生的坑:**依赖列表里的变量必须在规则出现**之前**定义好,否则展开为空:

```makefile
app: $(OBJS)              # 此时 OBJS 尚未定义 → 依赖为空
	...
OBJS = main.o             # 太晚了
```

而命令里的变量即使定义在规则之后也能被看到(因为命令执行时已读完整个 Makefile)。

### 4.9.6 make 变量与 shell 变量混淆

```makefile
bad:
	for i in 1 2 3; do echo $i; done      # $i 被 make 当作变量 i(空)
good:
	for i in 1 2 3; do echo $$i; done
```

反之,想在命令里用 make 变量,用 `$(VAR)`:

```makefile
	echo $(CC)           # make 展开
	echo $$HOME          # shell 展开
```

### 4.9.7 list 的处理

make 变量中的"列表"就是以空格分隔的单词,配合 `foreach`、`filter`、`patsubst`(第 7 章)等。

### 4.9.8 `MAKECMDGOALS`:根据目标做条件判断

```makefile
ifneq ($(MAKECMDGOALS),clean)
  -include $(DEPS)          # 执行 make clean 时不必加载依赖文件
endif
```

### 4.9.9 目录相关变量

```makefile
ROOT := $(dir $(abspath $(lastword $(MAKEFILE_LIST))))    # 当前 Makefile 所在目录
```

(用到函数,第 7 章详解。)

### 4.9.10 综合示例

```makefile
# ---------------- 可覆盖的配置 ----------------
CC       ?= gcc
BUILD    ?= release
BUILD_DIR ?= build
PREFIX   ?= /usr/local

# ---------------- 项目必须选项 ----------------
override CPPFLAGS += -Iinclude
override CFLAGS   += -std=c11 -Wall -Wextra

ifeq ($(BUILD),debug)
  override CFLAGS += -O0 -g
else
  override CFLAGS += -O2 -DNDEBUG
endif

# ---------------- 文件列表 ----------------
SRCS := $(wildcard src/*.c)
OBJS := $(SRCS:src/%.c=$(BUILD_DIR)/%.o)
TARGET := $(BUILD_DIR)/app

# ---------------- 规则 ----------------
.PHONY: all clean
all: $(TARGET)

$(TARGET): $(OBJS)
	$(CC) $(LDFLAGS) $^ $(LDLIBS) -o $@

$(BUILD_DIR)/%.o: src/%.c | $(BUILD_DIR)
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@

$(BUILD_DIR):
	mkdir -p $@

clean:
	$(RM) -r $(BUILD_DIR)
```

用法:

```bash
make                       # release
make BUILD=debug           # debug
make BUILD_DIR=out/arm CC=arm-linux-gnueabihf-gcc
```

## 4.10 本章小结

1. 变量引用 `$(VAR)`;命令里传给 shell 的 `$` 写 `$$`。
2. 赋值五种:`=` 延迟展开、`:=`(`::=`)立即展开、`?=` 未定义才赋值、`+=` 追加(保持原风味)、`!=` shell 赋值。**默认推荐 `:=`**,自动变量相关与"要被后续覆盖"的用 `=`。
3. 优先级:`override` > 命令行 > Makefile > 环境变量 > 内置默认;用 `?=` 做默认值、`override` 做强制追加。
4. `CC` 等有内置默认值,`?=` 对它们无效,用 `origin` 判断。
5. 子进程只继承环境变量与命令行变量,其他需 `export`。
6. 目标特定变量(`debug: CFLAGS=-g`)与模式特定变量(`%.o: CFLAGS+=-fPIC`)用于局部差异。
7. `define ... endef` 定义多行变量/命令包/模板;`$(VAR:.c=.o)` 做后缀与模式替换。
8. 约定变量:`CC CXX CPPFLAGS CFLAGS CXXFLAGS LDFLAGS LDLIBS AR RM`,遵守它们能与隐含规则和用户习惯协同。
9. 展开时机决定行为:目标/依赖立即展开,命令执行时展开;小心末尾空格与变量未定义。

## 4.12 速查卡

```makefile
VAR  = v        # 递归展开(用时求值)
VAR := v        # 立即展开(定义时求值)  ← 默认首选
VAR ::= v       # 同 :=  (POSIX)
VAR ?= v        # 未定义才赋值
VAR += v        # 追加
VAR != cmd      # shell 结果赋值
override VAR = v        # 压过命令行
export VAR / unexport VAR
target: VAR = v         # 目标特定变量
%.o:    VAR += v        # 模式特定变量
$(VAR:.c=.o)            # 后缀替换
$(VAR:src/%.c=obj/%.o)  # 模式替换
define X ... endef      # 多行变量
$(origin V)  $(flavor V)  $(info ...)
```

优先级:`override` > 命令行 > Makefile > 环境 > 默认
