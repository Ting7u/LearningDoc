## 1. C 语言简介
### 1.1 简史

| 年份        | 事件                                                                    |
| --------- | --------------------------------------------------------------------- |
| 1969–1972 | Dennis Ritchie 在贝尔实验室，基于 B 语言设计出 C 语言，用来重写 UNIX 操作系统                  |
| 1978      | Kernighan 与 Ritchie 出版《The C Programming Language》，其描述的语言称为 **K&R C** |
| 1989/1990 | ANSI / ISO 先后发布标准，即 **C89 / C90**                                     |
| 1999      | **C99**                                                               |
| 2011      | **C11**                                                               |
| 2018      | **C17**（对 C11 的缺陷修订，没有新特性）                                            |
| 2024      | **C23**                                                               |

### 1.2 语言特点
- **高效**：接近硬件，生成的机器码体积小、速度快。
- **可移植**：同一份标准 C 代码，经不同平台编译器编译后可在多种平台运行。
- **灵活**：可直接操作内存（指针）、位、硬件寄存器。
- **简洁**：关键字少（C99 共 37 个），语法规则精炼。
- **标准库小**：只提供最基础的功能，其余靠自己或第三方库。
- **代价**：**几乎不做安全检查**——数组越界、野指针、内存泄漏都需要程序员自己负责。
### 1.3 应用领域

| 领域           | 典型代表                                   |
| ------------ | -------------------------------------- |
| 操作系统         | Linux 内核、Windows 内核部分、macOS/iOS 内核 XNU |
| 嵌入式 / 单片机    | STM32、51 单片机、各类 RTOS                   |
| 数据库          | SQLite、Redis、MySQL（部分）                 |
| 编译器 / 解释器    | GCC、Lua、Python（CPython）解释器             |
| 网络服务         | Nginx、curl                             |
| 驱动、图形、游戏引擎底层 | 显卡驱动、各类底层库                             |

### 1.4 C 与其他语言的关系
```
B → C → C++ / Objective-C / C#（受影响）
          ↘ Java、Go、Rust 等语法深受 C 影响
```

学好 C，对理解内存、指针、系统调用、计算机原理有直接帮助，是后续学习其他语言的底层基础。

## 2. C 语言标准的演进

| 标准            | 主要新增特性（够用即可，后续章节会逐一讲到）                                                                                      |
| ------------- | ----------------------------------------------------------------------------------------------------------- |
| **K&R C**     | 最早的形式，函数参数声明风格与今天不同                                                                                         |
| **C89 / C90** | 第一个正式标准；函数原型、`void`、`const`、`volatile`、标准库                                                                  |
| **C99**       | `//` 单行注释；`long long`；`_Bool`；变长数组（VLA）；`inline`；指定初始化器；可在代码中间声明变量；`<stdint.h>`；`restrict`                  |
| **C11**       | `_Static_assert`；`_Generic`；`_Alignas/_Alignof`；匿名结构体/联合体；`<threads.h>`、`<stdatomic.h>`；`_Noreturn`         |
| **C17**       | 缺陷修订版，无新语法                                                                                                  |
| **C23**       | `bool/true/false/nullptr` 成为关键字；`constexpr`；`typeof`；`#embed`；二进制字面量 `0b101`；数字分隔符 `1'000'000`；`auto` 类型推导等 |

### 如何指定编译使用的标准
```bash
gcc -std=c11 hello.c -o hello      # 按 C11 编译
gcc -std=c99 -pedantic hello.c     # 按 C99，并严格检查是否符合标准
gcc -std=gnu17 hello.c             # C17 + GNU 扩展（GCC 的默认模式之一）
```

> **建议**：学习阶段统一使用 `-std=c11`（或 `c17`），兼顾通用性与现代特性。

## 4. 第一个程序：Hello, World
```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n");
    return 0;
}
```
### 4.1 逐行解释

| 代码                           | 含义                                              |
| ---------------------------- | ----------------------------------------------- |
| `#include <stdio.h>`         | **预处理指令**：把标准输入输出库的头文件内容"粘贴"到此处，这样才能使用 `printf` |
| `int main(void)`             | **主函数**，程序入口。`int` 表示返回整数；`void` 表示不接收参数        |
| `{ ... }`                    | 函数体的起止                                          |
| `printf("Hello, World!\n");` | 调用库函数输出字符串；`\n` 是换行符；语句以 `;` 结尾                 |
| `return 0;`                  | 返回 0 给操作系统，**约定 0 表示成功**，非 0 表示出错               |

### 4.2 编译与运行
```bash
gcc hello.c -o hello       # 编译：hello.c → 可执行文件 hello
./hello                    # 运行
echo $?                    # 查看上一个程序的返回值（Linux/macOS），输出 0
```

> 不加 `-o` 时，GCC 默认生成 `a.out`（Windows 下为 `a.exe`）。

### 4.3 几个常见疑问

**Q1：`main` 可以写成 `void main()` 吗？**
不规范。标准只规定两种形式：
```c
int main(void)
int main(int argc, char *argv[])
```
C99 起，若 `main` 执行到末尾没写 `return`，等价于 `return 0;`，但**建议始终显式写出**。

**Q2：`int main()` 和 `int main(void)` 有区别吗？**
在 C 中有：`()` 表示"参数未指定"（旧式风格），`(void)` 明确表示"无参数"。**推荐用 `(void)`**。（C23 起二者等价。）

**Q3：`\n` 不写会怎样？**
```c
printf("Hello");
printf("World");
```
输出 `HelloWorld`——两者连在同一行，且程序结束后终端提示符会紧跟其后。
### 4.4 稍复杂一点的例子
```c
#include <stdio.h>

int main(void)
{
    int a = 3;
    int b = 4;
    int sum = a + b;

    printf("a = %d, b = %d\n", a, b);
    printf("%d + %d = %d\n", a, b, sum);
    return 0;
}
```

输出：
```
a = 3, b = 4
3 + 4 = 7
```

`%d` 是占位符，按顺序被后面的整数值替换（详见第 4 章）。

## 5. 程序的基本结构与注释
### 5.1 一个典型 C 源文件的结构
```c
/* ---------- 1. 文件头注释 ---------- */
/* 文件：demo.c   功能：演示程序结构 */

/* ---------- 2. 预处理指令 ---------- */
#include <stdio.h>
#define PI 3.14159

/* ---------- 3. 全局声明 ---------- */
int g_count = 0;                 /* 全局变量 */
double area(double r);           /* 函数声明 */

/* ---------- 4. main 函数 ---------- */
int main(void)
{
    double r = 2.0;
    printf("area = %f\n", area(r));
    return 0;
}

/* ---------- 5. 其他函数定义 ---------- */
double area(double r)
{
    return PI * r * r;
}
```
### 5.2 注释
```c
// 单行注释（C99 起支持）

/* 多行注释
   可以跨越多行 */

int x = 10;   // 行尾注释
```

**注意事项**：

```c
/* 块注释不能嵌套 */
/* 外层 /* 内层 */ 这里会导致编译错误 */
```

想临时"注释掉"一大段代码，推荐使用条件编译：
```c
#if 0
    这里的代码不会被编译，可包含任意注释
#endif
```

**好注释的原则**：解释"**为什么**这样做"，而不是重复"做了什么"。

```c
i++;                       // 让 i 加 1          ← 无意义
i++;                       // 跳过分隔符，指向下一个字段  ← 有意义
```
### 5.3 语句、空白与分号
- C 语言**自由格式**：空格、缩进、换行不影响语义（但影响可读性）。
- 每条语句以 `;` 结束；`{}` 包起来的是**复合语句（块）**。
- 区分大小写：`Main` ≠ `main`，`Printf` ≠ `printf`。

```c
// 这样也能编译通过，但没人愿意看
#include <stdio.h>
int main(void){printf("hi\n");return 0;}
```

## 6. 编译的四个阶段
执行 `gcc hello.c -o hello` 时，GCC 在背后依次做了四件事：

```
 hello.c ──预处理──▶ hello.i ──编译──▶ hello.s ──汇编──▶ hello.o ──链接──▶ hello
 (源文件)  cpp      (展开后的C)  cc1   (汇编代码)   as     (目标文件)   ld   (可执行文件)
```

### 6.1 分步演示

```bash
gcc -E hello.c -o hello.i     # ① 预处理
gcc -S hello.i -o hello.s     # ② 编译成汇编
gcc -c hello.s -o hello.o     # ③ 汇编成目标文件
gcc hello.o   -o hello        # ④ 链接成可执行文件
```

一次性保留所有中间文件：
```bash
gcc -save-temps hello.c -o hello
```

### 6.2 ① 预处理（Preprocessing）

主要工作：
- 展开 `#include`（把头文件内容原样插入）
- 展开 `#define` 宏
- 处理条件编译 `#if / #ifdef`
- **删除注释**

示例 `pre.c`：
```c
#include <stdio.h>
#define N 10

int main(void)
{
    // 这是注释
    printf("%d\n", N * 2);
    return 0;
}
```

查看预处理结果 `gcc -E pre.c`，末尾部分形如：
```c
int main(void)
{
    printf("%d\n", 10 * 2);
    return 0;
}
```
前面还会有几百行来自 `stdio.h` 的声明。可见：**注释没了，`N` 被替换成了 `10`，宏替换只是"文本替换"，不做计算**。

### 6.3 ② 编译（Compilation）

把预处理后的 C 代码进行**词法分析 → 语法分析 → 语义分析 → 优化 → 生成汇编**。
**语法错误在这一步报告**。

```bash
gcc -S -O0 hello.c         # 生成 hello.s
```

`hello.s` 片段（x86-64，示意）：
```asm
main:
    pushq   %rbp
    movq    %rsp, %rbp
    leaq    .LC0(%rip), %rdi
    call    puts@PLT
    movl    $0, %eax
    popq    %rbp
    ret
```

> 小发现：`printf("Hello, World!\n")` 只有纯字符串且以换行结尾时，编译器会优化为 `puts`。

### 6.4 ③ 汇编（Assembly）

把汇编代码翻译成机器码，生成**目标文件**（Linux 为 ELF 格式，`.o`；Windows 为 `.obj`）。目标文件是二进制，已含机器指令，但**还不能运行**，因为 `printf` 的实现地址还不知道。

```bash
file hello.o          # hello.o: ELF 64-bit LSB relocatable
objdump -d hello.o    # 反汇编查看机器指令
nm hello.o            # 查看符号表，会看到 U printf/puts（Undefined，未定义）
```

### 6.5 ④ 链接（Linking）

链接器把：
- 你的目标文件（`.o`）
- 标准库（如 libc）
- 其他库

**合并**，解析符号引用（把 `printf` 调用指向真正的函数地址），生成最终可执行文件。

**链接错误**典型长这样：
```
undefined reference to `foo'
```

### 6.6 四阶段对应的错误类型（重要）

| 阶段 | 典型错误 | 示例 |
|---|---|---|
| 预处理 | 头文件找不到 | `fatal error: xxx.h: No such file or directory` |
| 编译 | 语法错误、类型不匹配 | `expected ';' before 'return'` |
| 汇编 | 极少出现 | — |
| 链接 | 符号未定义/重复定义 | `undefined reference to 'func'` |
| 运行 | 段错误、逻辑错误 | `Segmentation fault` |

### 6.7 多文件编译预览（第 15 章详述）

```c
// add.c
int add(int a, int b) { return a + b; }
```
```c
// main.c
#include <stdio.h>
int add(int a, int b);          // 声明
int main(void)
{
    printf("%d\n", add(2, 3));
    return 0;
}
```
```bash
gcc main.c add.c -o app         # 一次性编译
# 或分开编译再链接：
gcc -c main.c
gcc -c add.c
gcc main.o add.o -o app
```
分开编译的好处：**只改了一个文件时，只需重新编译它**，这正是 Makefile 要解决的问题。

## 7. 编译警告与常用编译选项

### 7.1 为什么要开警告

编译器的警告往往指向**真正的 bug**。初学者最常犯的错误是"只要能运行就不管警告"。

```c
#include <stdio.h>

int main(void)
{
    int x;
    printf("%d\n", x);       // 使用了未初始化的变量
    return 0;
}
```

```bash
gcc demo.c -o demo              # 默认：静默通过
gcc -Wall -Wextra demo.c -o demo
```
输出：
```
warning: 'x' is used uninitialized [-Wuninitialized]
```
不开警告时，程序会输出一个随机值，难以察觉。

再看一个例子：
```c
int main(void)
{
    printf("hi\n");          // 忘了 #include <stdio.h>
    return 0;
}
```
- 老版本 GCC：警告 `implicit declaration of function 'printf'`
- GCC 14+ 与 C99 以后严格模式：**直接报错**（隐式函数声明已不允许）

### 7.2 必记的编译选项

| 选项 | 作用 |
|---|---|
| `-o 文件名` | 指定输出文件名 |
| `-std=c11` | 指定语言标准 |
| `-Wall` | 开启常用警告 |
| `-Wextra` | 开启额外警告 |
| `-Werror` | **把警告当错误**，有警告就编译失败 |
| `-pedantic` | 严格遵守标准，对扩展给出警告 |
| `-g` | 生成调试信息（gdb 需要） |
| `-O0 / -O1 / -O2 / -O3` | 优化级别（调试用 `-O0`，发布用 `-O2`） |
| `-c` | 只编译不链接 |
| `-E` / `-S` | 只预处理 / 只编译到汇编 |
| `-I目录` | 指定头文件搜索路径 |
| `-L目录` `-l库名` | 指定库搜索路径 / 链接某个库（如 `-lm` 链接数学库） |
| `-D宏名[=值]` | 命令行定义宏，如 `-DDEBUG` |
| `-fsanitize=address,undefined` | 开启运行时内存/未定义行为检测 |

### 7.3 推荐的"学习期"标准编译命令

```bash
gcc -std=c11 -Wall -Wextra -pedantic -g -O0 \
    -fsanitize=address,undefined \
    main.c -o main
```

可以把它写进 shell 别名或 Makefile，每次都使用。

## 8. gdb 调试入门

### 8.1 为什么要用调试器

`printf` 调试虽然简单，但改代码、重新编译、再看输出效率低。gdb 可以：**暂停程序、单步执行、查看任意变量与内存、查看调用栈**。

### 8.2 示例程序

`sum.c`：
```c
#include <stdio.h>

int sum(int n)
{
    int s = 0;
    for (int i = 1; i <= n; i++) {
        s += i;
    }
    return s;
}

int main(void)
{
    int n = 5;
    int r = sum(n);
    printf("sum(%d) = %d\n", n, r);
    return 0;
}
```

必须带 `-g` 编译：
```bash
gcc -g -O0 sum.c -o sum
gdb ./sum
```

### 8.3 常用命令

| 命令（简写） | 作用 |
|---|---|
| `break main`（`b main`） | 在 `main` 处设断点；也可 `b sum.c:7`（文件:行号） |
| `run`（`r`） | 开始运行 |
| `next`（`n`） | 单步执行，**不进入**函数 |
| `step`（`s`） | 单步执行，**进入**函数 |
| `continue`（`c`） | 继续运行到下一个断点 |
| `print 表达式`（`p s`） | 打印变量或表达式的值 |
| `info locals` | 显示当前函数所有局部变量 |
| `backtrace`（`bt`） | 查看调用栈 |
| `watch 变量` | 变量被修改时暂停 |
| `display 表达式` | 每次暂停都自动显示 |
| `info breakpoints`（`i b`） | 查看断点列表 |
| `delete 编号` | 删除断点 |
| `list`（`l`） | 显示源码 |
| `finish` | 运行到当前函数返回 |
| `quit`（`q`） | 退出 |

## 9. 常见错误与排查

### 9.1 初学者高频错误清单

| 错误现象 | 原因 | 修复 |
|---|---|---|
| `expected ';' before ...` | 上一行漏了分号 | 看报错行的**上一行** |
| `'x' undeclared` | 变量未声明或拼写错误 | 检查拼写、作用域 |
| `implicit declaration of function` | 忘了 `#include` | 补头文件 |
| `undefined reference to 'sqrt'` | 用了 `math.h` 函数但没链接数学库 | 加 `-lm`（且放在命令末尾） |
| `undefined reference to 'main'` | 没有 `main` 函数，或文件名错 | 检查 |
| `multiple definition of ...` | 同一函数/全局变量在多个 `.c` 中被定义 | 头文件只放声明 |
| 中文乱码 | 源文件编码与终端编码不一致 | 统一用 UTF-8 |
| 窗口一闪而过（Windows） | 程序结束窗口自动关闭 | 在命令行运行，或末尾加 `getchar();` |
| 输出不出现 | 缓冲未刷新或忘了 `\n` | 加 `\n` 或 `fflush(stdout)` |

### 9.2 读编译错误信息的方法

```
main.c: In function 'main':
main.c:6:5: error: expected ';' before 'return'
    6 |     return 0;
      |     ^~~~~~
```

- 格式：`文件:行:列: 级别: 描述`
- **从第一条错误开始修**，后面的错误常是连锁反应。
- 报错行的**上一行**也值得检查（缺分号、缺括号常如此）。

### 9.3 经典：`printf` 参数个数不匹配

```c
printf("%d %d\n", 10);        // 缺一个参数
```
开启 `-Wall` 后会提示 `format '%d' expects a matching 'int' argument`。不开警告则输出垃圾值——这就是为什么**一定要开警告**。

## 10. 本章小结与练习

### 10.1 知识要点回顾

- C 诞生于 1972 年，标准经历 C89 → C99 → C11 → C17 → C23。
- C 的优势：高效、贴近硬件、可移植；代价：安全检查靠程序员。
- 编译四阶段：**预处理 → 编译 → 汇编 → 链接**，各有各的典型错误。
- `main` 是程序入口，`return 0` 表示成功。
- 开发时始终使用 `-Wall -Wextra`，调试时使用 `-g -O0`。
- gdb 常用：`b / r / n / s / p / bt / c / watch`。

### 10.2 练习题

**基础**
1. 编写程序，输出你的姓名和学校，每项占一行。
2. 用 `printf` 输出下面的图案：
   ```
      *
     ***
    *****
   ```
3. 分别使用 `-E`、`-S`、`-c` 选项编译 `hello.c`，用文本编辑器查看 `.i`、`.s` 文件，找到 `main` 函数相关的内容。

**理解**
4. 故意删掉 `#include <stdio.h>`，分别用 `-std=c89` 和 `-std=c11 -Wall` 编译，观察信息差异。
5. 故意制造三类错误：语法错误、链接错误（声明了函数但不定义并调用）、运行时错误（空指针解引用），说明它们分别在哪个阶段被发现。

**进阶**
6. 将 `add` 函数放在 `add.c`，`main` 放在 `main.c`，分步编译并链接；然后只修改 `add.c`，思考只需重新做哪几步。
7. 对 8.2 节中的 `sum.c`，用 gdb 设置 `watch s`，记录 `s` 每次变化的值。
8. 查阅资料：为什么 `printf("Hello\n")` 会被编译成 `puts`？在 `-O0` 下与 `-fno-builtin` 下的汇编有什么不同？
