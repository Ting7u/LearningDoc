# 第 0 章 准备工作

> 目标：知道 C++ 有哪些标准、代码是怎么变成可执行文件的、该用什么工具，并且能在自己电脑上把第一个程序跑起来。

---

## 0.1 C++ 标准的演进

C++ 由 ISO 标准委员会制定标准，大约每三年发布一个新版本。

| 标准 | 年份 | 关键词 |
|------|------|--------|
| C++98 | 1998 | 第一个 ISO 标准：模板、STL、异常、RTTI、命名空间 |
| C++03 | 2003 | 对 C++98 的缺陷修订，几乎没有新特性 |
| **C++11** | 2011 | **现代 C++ 的起点**：`auto`、lambda、右值引用/移动语义、智能指针、`nullptr`、范围 `for`、线程库 |
| C++14 | 2014 | C++11 的"补完"：泛型 lambda、返回类型推导、`make_unique` |
| **C++17** | 2017 | 结构化绑定、`if constexpr`、`optional`/`variant`/`string_view`、`filesystem` |
| **C++20** | 2020 | Concepts、Ranges、协程、Modules、`<=>` |
| C++23 | 2023 | `std::expected`、`std::print`、`std::mdspan` 等 |
| C++26 | 制定中 | 最终内容我不确定，请以 ISO / cppreference 为准 |

**学习建议**

- 以 **C++17** 作为起点标准，既足够现代，主流编译器支持也很完整。
- 看到 2011 年以前的教程、博客时要留意：那是 "旧 C++"，很多写法现在已有更好的替代（比如手写 `new/delete`、`NULL`、迭代器循环等）。
- 各编译器对 C++20/23 的支持程度不同，具体某个特性能不能用，查 cppreference 的 "Compiler support" 页面。

## 0.2 从源码到可执行文件：编译流程

### 第一个程序

新建 `hello.cpp`：

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, C++!" << '\n';
    return 0;
}
```

逐行解释：

| 代码 | 含义 |
|------|------|
| `#include <iostream>` | 预处理指令，把标准库输入输出流的声明"复制"进来 |
| `int main()` | 程序入口，返回 `int` 作为退出码 |
| `std::cout` | 标准输出流对象，`std::` 表示它在标准命名空间里 |
| `<<` | 流插入运算符，把右边的内容送进左边的流 |
| `'\n'` | 换行字符 |
| `return 0;` | 表示正常退出。**`main` 里可以省略这句**，编译器会默认返回 0（仅限 `main`） |

编译并运行（Linux / macOS，使用 g++）：

```bash
g++ -std=c++17 -Wall -Wextra hello.cpp -o hello
./hello
```

### 四个阶段

和 C 一样，一次编译实际包含四个阶段：

```
hello.cpp ──预处理──▶ hello.ii ──编译──▶ hello.s ──汇编──▶ hello.o ──链接──▶ hello
```

用 g++ 可以逐步观察：

```bash
g++ -E hello.cpp -o hello.ii     # 1. 预处理：展开 #include、宏，删注释
g++ -S hello.cpp -o hello.s      # 2. 编译：生成汇编代码
g++ -c hello.cpp -o hello.o      # 3. 汇编：生成目标文件（机器码，但未链接）
g++ hello.o -o hello             # 4. 链接：合并目标文件和库，生成可执行文件
```

可以试试 `wc -l hello.ii`：只有 `#include <iostream>` 的程序，预处理后通常有几万行，因为标准库头文件被整个展开了。这也是 C++ 编译比 C 慢的原因之一（Modules 想解决这个问题，见第 14 章）。

> 用 `g++` 而不是 `gcc` 编译 C++ 的原因：`g++` 在链接时会自动加上 C++ 标准库（`libstdc++`）。

### 多文件项目示例

真实项目都是多文件。这里有三个文件：

**`math_utils.h`**（声明）

```cpp
#pragma once              // 防止头文件被重复包含

int add(int a, int b);
int square(int x);
```

**`math_utils.cpp`**（定义）

```cpp
#include "math_utils.h"

int add(int a, int b) {
    return a + b;
}

int square(int x) {
    return x * x;
}
```

**`main.cpp`**（使用）

```cpp
#include <iostream>
#include "math_utils.h"

int main() {
    std::cout << add(3, 4) << '\n';       // 7
    std::cout << square(5) << '\n';       // 25
    return 0;
}
```

分开编译，再链接：

```bash
g++ -std=c++17 -c math_utils.cpp -o math_utils.o
g++ -std=c++17 -c main.cpp -o main.o
g++ main.o math_utils.o -o app
./app
```

或者一条命令：

```bash
g++ -std=c++17 main.cpp math_utils.cpp -o app
```

**核心理解**：每个 `.cpp` 文件是一个独立的**编译单元**（translation unit），单独编译成 `.o`；`main.cpp` 只需要看到 `add` 的**声明**就能通过编译，真正的地址由**链接器**去找。

### 两个最常见的链接错误

**① `undefined reference to 'add(int, int)'`**
声明了、用了，但链接时没找到定义。通常是忘了把 `math_utils.cpp`（或对应的 `.o`/库）加进编译命令。

**② `multiple definition of ...`**
同一个函数在多个编译单元里被定义了。典型原因：在头文件里写了函数**定义**，又被多个 `.cpp` 包含。

```cpp
// bad.h
int helper() { return 1; }          // 定义放在头文件，被两个 .cpp 包含 → 链接时重复定义

// 解决办法之一：加 inline
inline int helper() { return 1; }   // OK，inline 允许在多个编译单元有相同定义
```

### 名字改编（name mangling）

C 里函数名就是符号名；C++ 支持**函数重载**，同名函数需要区分，所以编译器会把参数类型编码进符号名：

```bash
nm math_utils.o
# 在 Linux/macOS（Itanium ABI）上大致会看到：
# T _Z3addii        ← add(int, int)
# T _Z6squarei      ← square(int)

nm -C math_utils.o  # -C 会还原成可读名字
```

这也是 C 和 C++ 混合编程需要 `extern "C"` 的原因（第 1 章）。不同编译器的改编规则不同，MSVC 与 GCC/Clang 的符号格式不一样。

## 0.3 编译器与工具链

| 编译器 | 平台 | 说明 |
|--------|------|------|
| **g++**（GCC） | Linux 为主，Windows 上有 MinGW / MSYS2 | 开源，最常见 |
| **clang++**（LLVM） | macOS 默认，全平台可用 | 错误信息友好，配套工具丰富（clang-tidy、clangd、sanitizers） |
| **MSVC**（`cl.exe`） | Windows | Visual Studio 自带 |

**安装参考**

```bash
# Ubuntu / Debian
sudo apt install build-essential

# macOS
xcode-select --install

# Windows：安装 Visual Studio（勾选"使用 C++ 的桌面开发"），
#          或安装 MSYS2 后获取 g++
```

**检查版本**

```bash
g++ --version
clang++ --version
```

版本太旧会不支持新标准。如果 `-std=c++17` 报错或有特性不可用，先看编译器版本。

## 0.4 常用编译选项

### g++ / clang++

| 选项                             | 作用                                |
| ------------------------------ | --------------------------------- |
| `-std=c++17`                   | 指定语言标准（也可用 `c++20`、`c++23`）       |
| `-Wall -Wextra`                | 打开大部分常用警告，**学习阶段务必开启**            |
| `-Wpedantic`                   | 严格按标准检查，提示非标准扩展                   |
| `-O0` / `-O2`                  | 优化级别：`-O0` 不优化（调试用），`-O2` 常用的发布级别 |
| `-g`                           | 生成调试信息（gdb/lldb 用）                |
| `-c`                           | 只编译不链接，输出 `.o`                    |
| `-o 名字`                        | 指定输出文件名                           |
| `-I 目录`                        | 添加头文件搜索路径                         |
| `-L 目录` `-l库名`                 | 添加库搜索路径 / 链接某个库（`-lm` 链接 `libm`）  |
| `-D 宏名[=值]`                    | 命令行定义宏，如 `-DDEBUG`                |
| `-fsanitize=address,undefined` | 开启运行时检查（内存错误、未定义行为），第 18 章详述      |

**推荐的"学习期标准命令"**：

```bash
g++ -std=c++17 -Wall -Wextra -g -O0 -fsanitize=address,undefined main.cpp -o main
```

警告要当回事。下面这段代码能通过编译，但 `-Wall` 会提示你：

```cpp
int main() {
    int x;                       // 未初始化
    return x;                    // 使用未初始化的值 → 未定义行为
}
```

### MSVC（命令行）

| 选项 | 作用 |
|------|------|
| `/std:c++17` | 指定标准 |
| `/W4` | 警告级别（最高常用级别） |
| `/EHsc` | 启用标准 C++ 异常处理 |
| `/Zi` | 生成调试信息 |

在 Visual Studio 里一般通过项目属性设置，不用手敲。

## 0.6 调试器入门（gdb / lldb）

编译时加 `-g -O0`。准备一个有 bug 的小程序 `bug.cpp`：

```cpp
#include <iostream>

int sum_to(int n) {
    int total = 0;
    for (int i = 1; i <= n; ++i) {
        total += i;
    }
    return total;
}

int main() {
    int result = sum_to(10);
    std::cout << result << '\n';
    return 0;
}
```

```bash
g++ -std=c++17 -g -O0 bug.cpp -o bug
gdb ./bug
```

| gdb 命令 | 作用 |
|----------|------|
| `break sum_to`（或 `b sum_to`） | 在函数入口下断点 |
| `run`（`r`） | 运行程序 |
| `next`（`n`） | 单步执行，不进入函数 |
| `step`（`s`） | 单步执行，进入函数 |
| `print total`（`p total`） | 打印变量 |
| `backtrace`（`bt`） | 查看调用栈 |
| `continue`（`c`） | 继续运行到下一个断点 |
| `quit`（`q`） | 退出 |

lldb（macOS/clang 常用）命令略有不同，如 `breakpoint set -n sum_to`、`run`、`next`、`step`、`print total`、`bt`。

## 0.7 构建系统预览：CMake 最小示例

手敲 g++ 命令在项目变大后会很痛苦，业界主流是 **CMake**（第 18 章详细讲）。先看最小例子，项目结构：

```
hello/
├── CMakeLists.txt
└── main.cpp
```

`CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.16)
project(hello CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_executable(hello main.cpp)
```

构建与运行：

```bash
cmake -S . -B build          # 配置：生成构建文件到 build/
cmake --build build          # 编译
./build/hello                # 运行（Windows 上路径可能在 build/Debug/ 下）
```

## 0.8 小结

- C++ 标准每 3 年一版，**C++11 是分水岭**，学习以 C++17 起步。
- 编译流程：预处理 → 编译 → 汇编 → 链接；每个 `.cpp` 是独立编译单元。
- 头文件放**声明**，`.cpp` 放**定义**；头文件里的函数定义要加 `inline`。
- `undefined reference` = 缺定义；`multiple definition` = 定义重复。
- 学习期必开 `-Wall -Wextra`，建议同时开 sanitizers。
- 先用命令行搞懂流程，再用 IDE / CMake 提效。

## 练习

1. 写一个 `hello.cpp`，分别执行 `-E`、`-S`、`-c`，用 `wc -l` 对比 `.ii`、`.s`、`.o` 文件，体会各阶段产物。
2. 把 0.2 节的三文件示例敲一遍，分别故意制造 **undefined reference** 和 **multiple definition** 两种错误，再修复。
3. 在 `bug.cpp` 里用 gdb 下断点，单步观察 `total` 在每次循环后的变化。
4. 用 CMake 构建 0.2 节的三文件项目（提示：`add_executable(app main.cpp math_utils.cpp)`）。
