# 第 16 节　文件 I/O

## 16.1 两套接口

| | 简单模式 | 完整模式（推荐） |
|---|---------|----------------|
| 做法 | `io.read` / `io.write` / `io.lines`，操作“默认输入/输出文件” | `io.open` 得到**文件句柄**，用 `f:read` / `f:write` |
| 适合 | 命令行交互、简单脚本 | 读写具体文件，需要精细控制 |

本节以**完整模式**为主，因为它更清晰、更不容易出错。

## 16.2 打开与关闭文件

```lua
local f, err, code = io.open("not_exist.txt", "r")
print(f, err, code)
--> nil   not_exist.txt: No such file or directory   2
```

`io.open(path, mode)` 成功返回文件句柄，失败返回 `nil, 错误信息, 错误码`。**每次打开都要检查是否成功。**

| 模式 | 含义 |
|------|------|
| `"r"` | 只读（默认），文件必须存在 |
| `"w"` | 只写，**清空**原内容；不存在则创建 |
| `"a"` | 追加到末尾；不存在则创建 |
| `"r+"` | 读写，文件必须存在 |
| `"w+"` | 读写，清空原内容 |
| `"a+"` | 读写，写入总是追加到末尾 |
| 加 `b` | 二进制模式（如 `"rb"` `"wb"`）；Windows 下会影响换行转换，处理图片、压缩包等务必加 `b` |

常见写法：

```lua
-- ① assert：失败就直接报错（脚本类程序最省事）
local f = assert(io.open("demo.txt", "w"))
f:write("Hello\n", "Lua\n", "42 3.14\n")
f:close()                                 -- 用完要关闭，保证数据落盘

-- ② 手动判断：需要自己处理失败
local f2, err = io.open("demo.txt", "r")
if not f2 then
    print("打开失败: " .. err)
else
    -- ...使用...
    f2:close()
end

-- ③ Lua 5.4：<close> 离开作用域自动关闭
do
    local f3 <close> = assert(io.open("demo.txt", "r"))
    print(f3:read("l"))                   --> Hello
end                                       -- 自动关闭
```

## 16.3 读取

`f:read(格式...)`，常用格式：

| 格式 | 含义 | 到达文件末尾时 |
|------|------|--------------|
| `"l"`（默认） | 读一行，**不含**换行符 | 返回 `nil` |
| `"L"` | 读一行，**保留**换行符 | 返回 `nil` |
| `"n"` | 读一个数字 | 失败返回 `nil` |
| `"a"` | 读取**全部**剩余内容 | 返回 `""`（空串，不是 nil） |
| 数字 `k` | 读取 k 个字节 | 返回 `nil` |

（Lua 5.3 起格式前的 `*` 可省略，写 `"*l"` 也仍然兼容。）

```lua
-- 先准备文件 demo.txt，内容为：
-- Hello
-- Lua
-- 42 3.14

local f = assert(io.open("demo.txt", "r"))
print(f:read())               --> Hello                  读一行
print(f:read("L"))            --> Lua（并带一个换行，所以会多出一个空行）
print(f:read("n", "n"))       --> 42   3.14              一次读两个数字
print(f:read("a"))            --> （只剩最后的换行符，所以显示为一个空行）
print(f:read("l"))            --> nil                    已到末尾
f:close()
```

### 一次读完整个文件

```lua
local f = assert(io.open("demo.txt", "rb"))
local content = f:read("a")
f:close()
print(#content)               --> 18        字节数
```

### 逐行读取：`lines`

```lua
for line in io.lines("demo.txt") do       -- io.lines 会在读完后自动关闭文件
    print(#line, line)
end
--> 5   Hello
--> 3   Lua
--> 7   42 3.14

-- 已经有句柄时，用 f:lines()（不会自动关闭）
local f = assert(io.open("demo.txt"))
for line in f:lines("L") do io.write(line) end   -- "L" 保留换行
f:close()
```

> `io.lines(文件名)` 在文件打不开时会直接**抛出错误**，而不是返回 `nil`。

### 按块读取（大文件，二进制）

```lua
local function copyFile(src, dst)
    local fin  = assert(io.open(src, "rb"))
    local fout = assert(io.open(dst, "wb"))
    while true do
        local block = fin:read(4096)          -- 每次最多读 4096 字节
        if not block then break end
        fout:write(block)
    end
    fin:close()
    fout:close()
end

copyFile("demo.txt", "demo_copy.txt")
```

## 16.4 写入

```lua
local f = assert(io.open("out.txt", "w"))
f:write("第一行\n")
f:write("数字: ", 42, " ", 3.5, "\n")        -- 可传多个参数；只接受字符串和数字
f:write(string.format("%5.2f\n", 3.14159))
f:write("链式"):write("调用\n")               -- write 成功时返回文件本身，可以链式调用
f:close()

-- 追加
local g = assert(io.open("out.txt", "a"))
g:write("追加一行\n")
g:close()
```

### 缓冲：flush 与 setvbuf

写入通常有缓冲，数据可能还没真正写到磁盘：

```lua
f:flush()                  -- 立刻把缓冲区写出
f:setvbuf("no")            -- 关闭缓冲（"no"）；也可 "line"（行缓冲）、"full"（全缓冲）
io.stdout:setvbuf("no")    -- 调试时让 print/io.write 立刻显示
```

### 检查写入是否成功

```lua
local ok, err = f:write("data")
if not ok then print("写入失败: " .. err) end
```

## 16.5 定位：seek

`f:seek(whence, offset)`，返回当前位置（从文件开头算起的字节数）：

| whence | 含义 |
|--------|------|
| `"set"` | 从文件开头 |
| `"cur"` | 从当前位置（默认） |
| `"end"` | 从文件末尾 |

```lua
local f = assert(io.open("demo.txt", "rb"))
local size = f:seek("end")            -- 移到末尾，返回位置 = 文件大小
print(size)                           --> 18
f:seek("set", 6)                      -- 跳过 "Hello\n"（6 字节）
print(f:read(3))                      --> Lua
print(f:seek("cur"))                  --> 9
f:seek("set")                         -- 回到开头
f:close()
```

## 16.6 实用工具函数

```lua
local function readFile(path)
    local f, err = io.open(path, "rb")
    if not f then return nil, err end
    local content = f:read("a")
    f:close()
    return content
end

local function writeFile(path, content)
    local f, err = io.open(path, "wb")
    if not f then return nil, err end
    local ok, werr = f:write(content)
    f:close()
    if not ok then return nil, werr end
    return true
end

local function fileExists(path)
    local f = io.open(path, "r")
    if f then f:close() return true end
    return false
end

print(writeFile("t.txt", "abc"))      --> true
print(readFile("t.txt"))              --> abc
print(fileExists("t.txt"), fileExists("nope.txt"))   --> true   false
print(readFile("nope.txt"))           --> nil   nope.txt: No such file or directory
```

> 在类 Unix 系统上，对**目录**执行 `io.open(path, "r")` 也可能成功，所以 `fileExists` 并不能区分文件和目录。

## 16.7 标准输入输出

```lua
io.stdout:write("普通输出\n")            -- 等价于 io.write
io.stderr:write("错误信息\n")            -- 标准错误，不会被重定向混入普通输出

-- 读取标准输入的每一行（Ctrl+D / Ctrl+Z 结束）
for line in io.lines() do
    print("你输入了: " .. line)
end

-- 读取多个数字
io.write("输入两个数: ")
local a, b = io.read("n", "n")
print(a + b)
```

默认输入/输出的切换（简单模式）：

```lua
io.output("log.txt")      -- 之后 io.write 写到 log.txt
io.write("写入日志\n")
io.close()                -- 关闭默认输出文件
io.output(io.stdout)      -- 切回标准输出
```

## 16.8 目录与文件系统操作

**Lua 标准库没有“列目录、建目录、查文件属性”的函数**，只有：

```lua
os.remove("a.txt")              -- 删除文件（或空目录）；失败返回 nil, 错误信息
os.rename("a.txt", "b.txt")     -- 重命名/移动
local tmp = os.tmpname()        -- 生成临时文件名
os.execute("mkdir mydir")       -- 执行系统命令（可移植性差）
```

**① 用 `io.popen` 调用系统命令**（注意各平台命令不同，并且**绝不要把用户输入直接拼进命令**，会有命令注入风险）：

```lua
-- Linux / macOS
local p = io.popen("ls -1")
for name in p:lines() do print(name) end
p:close()

-- Windows 则用： io.popen("dir /b")
```

**② 使用第三方库 LuaFileSystem（lfs）**，跨平台且更安全（需要用 LuaRocks 安装）：

```lua
local lfs = require("lfs")

for name in lfs.dir(".") do
    if name ~= "." and name ~= ".." then
        local attr = lfs.attributes(name)
        print(name, attr.mode, attr.size)     -- mode 是 "file" 或 "directory"
    end
end

lfs.mkdir("newdir")
lfs.chdir("newdir")
```

## 16.9 实战：把表保存到文件

### 一个简单的序列化函数

把 Lua 表转成“Lua 源代码”文本，保存后可以用 `load` 读回来：

```lua
local function serialize(v, indent)
    indent = indent or ""
    local t = type(v)
    if t == "string" then
        return string.format("%q", v)                 -- %q 生成可被 Lua 读回的字符串字面量
    elseif t == "number" or t == "boolean" or t == "nil" then
        return tostring(v)
    elseif t == "table" then
        local keys = {}
        for k in pairs(v) do keys[#keys + 1] = k end
        table.sort(keys, function(a, b) return tostring(a) < tostring(b) end)

        local lines = {}
        for _, k in ipairs(keys) do
            local ks
            if type(k) == "string" and k:match("^[%a_][%w_]*$") then
                ks = k                                 -- 合法标识符：直接写 name =
            else
                ks = "[" .. serialize(k) .. "]"        -- 其他：写成 [key] =
            end
            lines[#lines + 1] = indent .. "  " .. ks .. " = " .. serialize(v[k], indent .. "  ") .. ","
        end
        return "{\n" .. table.concat(lines, "\n") .. "\n" .. indent .. "}"
    end
    error("不支持的类型: " .. t)
end

local data = {name = "Tom", scores = {90, 85}, active = true}
print(serialize(data))
--> {
-->   active = true,
-->   name = "Tom",
-->   scores = {
-->     [1] = 90,
-->     [2] = 85,
-->   },
--> }
```

保存与读取：

```lua
-- 保存
local f = assert(io.open("save.lua", "w"))
f:write("return ", serialize(data), "\n")
f:close()

-- 读取
local loaded = dofile("save.lua")
print(loaded.name, loaded.scores[2], loaded.active)   --> Tom   85   true
```

> ⚠️ 这个简易版**不处理循环引用**，也不处理“键恰好是关键字（如 `end`）”的美观问题；`inf` / `nan` 也无法正确还原。
> ⚠️ **加载不可信的数据时不要直接 `dofile` / `load`**（里面可能含恶意代码）。至少使用空环境：
>
> ```lua
> local fn = load(text, "data", "t", {})   -- 只允许文本，环境为空表，访问不到 os、io 等
> ```
>
> 需要和其他系统交换数据时，用 JSON 等通用格式（通过第三方库，如 `dkjson`、`lua-cjson`）。

## 16.10 小结与练习

**小结：**

- `io.open` 必须检查返回值；用完 `close`（或用 `<close>`）
- 读：`"l"` `"L"` `"n"` `"a"` `数字`；写：`write`，可链式；二进制加 `b`
- `io.lines(path)` 逐行读，自动关闭；`seek` 定位；`flush` / `setvbuf` 控制缓冲
- 标准库没有目录操作，用 `io.popen`（慎用）或 `lfs`
- 保存表：序列化成 Lua 代码或 JSON

**练习 1：** 写函数 `wc(path)`，返回文件的行数、单词数、字节数（类似 `wc` 命令）。

```lua
local function wc(path)
    local f = assert(io.open(path, "rb"))
    local content = f:read("a")
    f:close()

    local _, lines = content:gsub("\n", "\n")     -- 统计换行符个数
    if #content > 0 and content:sub(-1) ~= "\n" then
        lines = lines + 1                         -- 最后一行没有换行符
    end

    local words = 0
    for _ in content:gmatch("%S+") do words = words + 1 end

    return lines, words, #content
end
```

# 第 17 节　垃圾回收与性能优化

## 17.1 Lua 的内存管理

Lua 是**自动内存管理**的：你创建 table、字符串、函数、闭包时不需要手动释放。**垃圾回收器（GC）** 会定期找出“不再被任何地方引用”的对象并回收。

核心规则：**对象只要还能从“根”（全局表、栈上的局部变量、registry 等）访问到，就不会被回收；不可达了才会被回收。**

```lua
local t = {1, 2, 3}      -- 创建一个表
t = nil                  -- 表不再被引用 → 以后某次 GC 会回收它
```

Lua 5.4 的 GC 有两种模式：

- **增量式（incremental，默认）**：把回收工作拆成小步，穿插在程序运行中，减少卡顿
- **分代式（generational）**：假设“大多数对象寿命很短”，主要回收新对象，适合产生大量短命对象的程序

## 17.2 `collectgarbage`：控制与观察 GC

```lua
collectgarbage()                     -- 等价于 collectgarbage("collect")：执行一次完整回收
print(collectgarbage("count"))       -- 当前 Lua 使用的内存（单位 KB，浮点数）
collectgarbage("stop")               -- 暂停 GC
collectgarbage("restart")            -- 恢复 GC
print(collectgarbage("isrunning"))   --> true
collectgarbage("step")               -- 手动执行一小步
collectgarbage("incremental")        -- 切换到增量模式
collectgarbage("generational")       -- 切换到分代模式
```

观察内存变化：

```lua
local function mem() return collectgarbage("count") end

local before = mem()
local t = {}
for i = 1, 100000 do t[i] = {i} end          -- 创建 10 万个小表
local mid = mem()

t = nil
collectgarbage()                              -- 完整回收
local after = mem()

print(string.format("前: %.0f KB, 中: %.0f KB, 后: %.0f KB", before, mid, after))
print(mid > before, after < mid)              --> true   true
```

> 一般情况下**不需要手动调用 GC**。典型的合理使用：关卡/场景切换时 `collectgarbage()` 一次；测量内存占用前先回收一次；对延迟敏感的程序在合适时机手动 `step`。

## 17.3 弱表（Weak Table）

普通表对它的键和值是“强引用”，会阻止对象被回收。**弱表**中的引用不会阻止回收。通过元表的 `__mode` 字段设置：

| `__mode` | 含义 |
|----------|------|
| `"k"` | **弱键**：键只被这个表引用时，可被回收（整个键值对消失） |
| `"v"` | **弱值**：值只被这个表引用时，可被回收 |
| `"kv"` | 键、值都是弱引用 |

### 弱值：做缓存

```lua
local cache = setmetatable({}, {__mode = "v"})

cache.a = {1, 2, 3}          -- 只有 cache 引用它
local keep = {4, 5}
cache.b = keep               -- keep 还有别的引用

collectgarbage()
print(cache.a)               --> nil      已被回收
print(cache.b == keep)       --> true     仍存在
```

### 弱键：给对象附加“外部数据”而不阻止它被回收

```lua
local metadata = setmetatable({}, {__mode = "k"})

local obj = {}
metadata[obj] = "附加信息"
print(metadata[obj])         --> 附加信息

obj = nil
collectgarbage()
print(next(metadata))        --> nil      obj 被回收，条目自动消失
```

> 注意：**字符串、数字、布尔值是“值”而不是“对象”**，它们不会从弱表中被移除。只有 table、函数、userdata、线程这类对象才会被回收。

## 17.4 终结器 `__gc`

对象被回收之前调用 `__gc` 元方法，常用于释放外部资源（C 对象、文件句柄等）：

```lua
local obj = setmetatable({}, {
    __gc = function(o) print("对象被回收了") end
})
obj = nil
collectgarbage()             --> 对象被回收了
```

注意：

- **`__gc` 必须在 `setmetatable` 时就存在于元表里**，之后再往元表里加是不生效的
- 终结器的调用时机不确定，**不要依赖它做关键逻辑**；程序退出时，尚未回收的对象的终结器也会被调用
- 资源管理优先用显式 `close()` 或 `<close>` 变量，`__gc` 只作为兜底

## 17.5 常见的“内存泄漏”

Lua 有 GC，但仍会因为**“还被引用着”**而“泄漏”：

| 原因 | 说明 |
|------|------|
| 全局表 / 缓存只增不减 | 缓存没有淘汰策略；解决：限制大小或用弱表 |
| 事件监听器不取消 | 回调闭包一直被事件表引用，连带它捕获的对象 |
| 闭包捕获了大对象 | upvalue 让大对象一直活着 |
| 数组中 `nil` 掉元素却未处理 | 元素没清掉，仍被引用 |
| 循环引用 | Lua 的 GC 能正确回收**纯 Lua** 对象间的循环引用，不是问题；但涉及 C 资源要小心 |

## 17.6 性能优化

> 🔑 **先让程序正确，再测量，最后才优化。** 没有测量数据的“优化”往往是浪费时间。**算法和数据结构的选择远比微优化重要。**

### 测量工具

```lua
local function bench(name, f, ...)
    collectgarbage()                       -- 尽量排除上一个测试的影响
    local start = os.clock()
    f(...)
    print(string.format("%-14s %.3f 秒", name, os.clock() - start))
end
```

### 技巧 ①：多用 `local`，缓存全局函数

访问全局变量要在 `_ENV` 表里查找，局部变量直接在寄存器 / upvalue 里取，更快：

```lua
local function useGlobal(n)
    local s = 0
    for i = 1, n do s = s + math.sin(i) end     -- 每次都查 math，再查 sin
    return s
end

local function useLocal(n)
    local sin = math.sin                        -- 缓存到局部变量
    local s = 0
    for i = 1, n do s = s + sin(i) end
    return s
end

bench("全局访问", useGlobal, 5000000)
bench("局部缓存", useLocal, 5000000)
-- 通常 useLocal 更快；具体差距因机器与版本而异
```

### 技巧 ②：字符串拼接用 `table.concat`

```lua
local function concatLoop(n)
    local s = ""
    for i = 1, n do s = s .. i .. "," end       -- 每次创建新字符串：O(n²)
    return s
end

local function concatTable(n)
    local t = {}
    for i = 1, n do t[#t + 1] = i end
    return table.concat(t, ",")                 -- 一次性拼接：O(n)
end

bench("循环 ..", concatLoop, 50000)
bench("table.concat", concatTable, 50000)
-- n 越大，两者差距越明显
```

### 技巧 ③：避免在热点循环里创建临时对象

```lua
-- ❌ 每次循环都创建新表 / 新闭包，产生大量垃圾
for i = 1, 1000000 do
    local p = {x = i, y = i}
    -- ...
end

-- ✅ 复用对象
local p = {x = 0, y = 0}
for i = 1, 1000000 do
    p.x, p.y = i, i
    -- ...
end
```

需要大量同类对象时，可以用**对象池**：

```lua
local Pool = {}
Pool.__index = Pool

function Pool.new(create)
    return setmetatable({free = {}, create = create}, Pool)
end
function Pool:get()
    return table.remove(self.free) or self.create()   -- 有空闲就复用，否则新建
end
function Pool:release(obj)
    self.free[#self.free + 1] = obj
end

local bullets = Pool.new(function() return {x = 0, y = 0} end)
local b = bullets:get()
-- ...使用...
bullets:release(b)
```

### 技巧 ④：表的使用

- 数组尽量使用**从 1 开始的连续整数下标**，Lua 会把它们存在更紧凑、更快的“数组部分”；中间留空洞会退化成哈希
- 删除数组头部元素 `table.remove(t, 1)` 是 O(n)；频繁这样做请改用头尾下标（见第 8 节的队列）
- 循环里反复用的 `#t` 可以先存到局部变量
- 数值 `for i = 1, #t` 通常比 `ipairs` 略快（但差距不大，可读性优先）

### 技巧 ⑤：整数运算

```lua
local a, b = 17, 5
print(a // b)              --> 3     整数整除
print(math.floor(a / b))   --> 3     先转浮点再取整，更慢
```

### 技巧 ⑥：选对数据结构

```lua
-- ❌ 在数组里线性查找，O(n)
local function contains(list, x)
    for _, v in ipairs(list) do if v == x then return true end end
    return false
end

-- ✅ 要频繁判断“是否存在”，用集合（哈希），O(1)
local set = {}
for _, v in ipairs({"a", "b", "c"}) do set[v] = true end
print(set["b"])            --> true
```

### 技巧 ⑦：GC 调优

```lua
-- 5.4：增量模式的参数（pause：多久启动下一轮；stepmul：回收速度）
collectgarbage("incremental", 200, 100)

-- 大量短命对象的程序可尝试分代模式，并用实际数据对比
collectgarbage("generational")
```

> 对 5.4 的分代模式，建议使用较新的 5.4.x 小版本，并用自己的程序实测，不要想当然。

### 定位性能问题

1. 用 `os.clock()` 给可疑代码段计时
2. 用 `collectgarbage("count")` 观察内存增长
3. 采样分析：可用 `debug.sethook` 自己写简易分析器，或使用第三方 profiler（如 LuaJIT 的内置 profiler）
4. 用 `debug.traceback()` 查看调用栈

## 17.7 小结与练习

**小结：**

- GC 自动回收“不可达”对象；`collectgarbage("count")` 看内存，`collectgarbage()` 完整回收
- 弱表（`__mode`）适合缓存与外部元数据；`__gc` 是兜底的终结器
- 泄漏通常是“还被引用着”：全局缓存、事件监听、闭包捕获
- 优化顺序：**测量 → 换算法/数据结构 → 局部化 → 少创建对象 → 少拼接字符串**

```lua
weak[1] = {}
weak[2] = "text"
local keep = {}
weak[3] = keep
collectgarbage()

```

# 第 18 节　C 与 Lua 交互

Lua 的设计目标之一就是**易嵌入、易扩展**。交互分两个方向：

| 方向 | 说明 | 例子 |
|------|------|------|
| **嵌入** | C/C++ 程序（宿主）内嵌 Lua 解释器，用 Lua 写配置、脚本、逻辑 | 游戏引擎、Nginx、Redis |
| **扩展** | 用 C 写函数/库，给 Lua 调用（C 模块） | `lfs`、`lpeg`、`luasocket` |

> 本节需要 C 编译器和 Lua 开发头文件（Debian/Ubuntu 可安装 `liblua5.4-dev`；macOS 可 `brew install lua`）。

## 18.1 核心概念：虚拟栈

C 与 Lua 之间**所有数据交换都通过一个“虚拟栈”**：

- C 把值压入栈 → Lua 取用
- Lua 把结果放到栈上 → C 读取

栈索引：

- **正数**从栈底开始：`1` 是最先压入的，`2` 是第二个……
- **负数**从栈顶开始：`-1` 是栈顶，`-2` 是栈顶下面一个……

```
索引：   正    负
         3    -1   ← 栈顶
         2    -2
         1    -3   ← 栈底
```

主要操作：

| 类别 | 常用函数 |
|------|---------|
| 压栈 | `lua_pushnil` `lua_pushboolean` `lua_pushinteger` `lua_pushnumber` `lua_pushstring` `lua_pushcfunction` |
| 取值 | `lua_tointeger` `lua_tonumber` `lua_tostring` `lua_toboolean` |
| 检查类型 | `lua_isnumber` `lua_isstring` `lua_istable` `lua_type` |
| 栈管理 | `lua_gettop` `lua_settop` `lua_pop(L, n)` `lua_pushvalue` |
| 全局变量 | `lua_getglobal(L, name)` `lua_setglobal(L, name)` |
| 表 | `lua_newtable` `lua_getfield` `lua_setfield` `lua_geti` `lua_seti` |
| 调用 | `lua_call` / **`lua_pcall`**（推荐，能捕获错误） |
| 参数检查（辅助库 `luaL_`） | `luaL_checkinteger` `luaL_checknumber` `luaL_checkstring` `luaL_optinteger` `luaL_error` |

## 18.2 嵌入 Lua：最小宿主程序

```c
// main.c
#include <stdio.h>
#include <lua.h>
#include <lauxlib.h>
#include <lualib.h>

int main(void) {
    lua_State *L = luaL_newstate();     // 创建 Lua 状态机（相当于一个独立的 Lua 虚拟机）
    luaL_openlibs(L);                   // 打开标准库

    // 执行一段 Lua 代码；返回 0（LUA_OK）表示成功
    if (luaL_dostring(L, "print('Hello from Lua!')") != LUA_OK) {
        fprintf(stderr, "错误: %s\n", lua_tostring(L, -1));   // 错误信息在栈顶
        lua_pop(L, 1);
    }

    lua_close(L);                       // 关闭，释放资源
    return 0;
}
```

编译与运行（Linux，包名因发行版而异，如 `lua5.4` 或 `lua`）：

```bash
gcc main.c -o demo $(pkg-config --cflags --libs lua5.4)
./demo
# 输出：Hello from Lua!
```

执行 Lua 文件：`luaL_dofile(L, "script.lua")`。

## 18.3 C 读取 Lua 的数据

先让 Lua 定义一个配置表，再用 C 读取：

```c
luaL_dostring(L, "config = {width = 800, title = 'Demo'}");

lua_getglobal(L, "config");               // 把全局变量 config 压栈  [config]

lua_getfield(L, -1, "width");             // 取 config.width 压栈     [config, 800]
int width = (int)lua_tointeger(L, -1);
lua_pop(L, 1);                            // 弹出                     [config]

lua_getfield(L, -1, "title");             //                          [config, "Demo"]
const char *title = lua_tostring(L, -1);
printf("width=%d, title=%s\n", width, title);   // 字符串指针只在它还在栈上时有效！
lua_pop(L, 1);                            //                          [config]

lua_pop(L, 1);                            // 弹出 config              []
// 输出：width=800, title=Demo
```

> ⚠️ **栈要保持平衡**：每压入的值用完要弹出，否则栈会越来越大。
> ⚠️ `lua_tostring` 返回的指针由 Lua 管理，**值被弹出后就不要再用**，需要长期保存请自己拷贝。

## 18.4 C 调用 Lua 函数

```c
luaL_dostring(L, "function add(a, b) return a + b end");

lua_getglobal(L, "add");                  // 函数
lua_pushinteger(L, 3);                    // 参数 1
lua_pushinteger(L, 4);                    // 参数 2

// lua_pcall(L, 参数个数, 返回值个数, 错误处理函数位置)
if (lua_pcall(L, 2, 1, 0) != LUA_OK) {
    fprintf(stderr, "调用失败: %s\n", lua_tostring(L, -1));
    lua_pop(L, 1);
} else {
    printf("add(3, 4) = %lld\n", (long long)lua_tointeger(L, -1));   // 7
    lua_pop(L, 1);                        // 弹出返回值
}
```

**务必用 `lua_pcall`**：Lua 脚本出错时，`lua_call` 会触发非局部跳转，宿主程序可能直接崩溃；`lua_pcall` 会把错误安全地交给你处理。

## 18.5 让 Lua 调用 C 函数

C 函数的固定签名：`int func(lua_State *L)`。

- 参数从栈上取（索引 1 开始）
- 把返回值压栈，函数的 `return` 值是**返回值个数**

```c
static int l_add(lua_State *L) {
    lua_Number a = luaL_checknumber(L, 1);    // 检查并取第 1 个参数，类型不对会自动报错
    lua_Number b = luaL_checknumber(L, 2);
    lua_pushnumber(L, a + b);                 // 压入结果
    return 1;                                 // 返回 1 个值
}

// 在 main 里注册
lua_register(L, "c_add", l_add);
luaL_dostring(L, "print(c_add(1.5, 2))");    // 输出：3.5
```

## 18.6 编写 C 模块（共享库）

把一组 C 函数打包成库，让 Lua 用 `require` 加载：

```c
// mylib.c
#include <lua.h>
#include <lauxlib.h>

static int l_square(lua_State *L) {
    lua_Number x = luaL_checknumber(L, 1);
    lua_pushnumber(L, x * x);
    return 1;
}

static int l_hello(lua_State *L) {
    const char *name = luaL_checkstring(L, 1);
    lua_pushfstring(L, "Hello, %s!", name);   // 类似 sprintf 的压栈函数
    return 1;
}

static const luaL_Reg funcs[] = {
    {"square", l_square},
    {"hello",  l_hello},
    {NULL, NULL}                              // 结束标记
};

// 入口函数：名字必须是 luaopen_ + 模块名
int luaopen_mylib(lua_State *L) {
    luaL_newlib(L, funcs);                    // 创建模块表并注册函数
    return 1;                                 // 返回模块表
}
```

编译成共享库：

```bash
# Linux
gcc -O2 -shared -fPIC -o mylib.so mylib.c $(pkg-config --cflags lua5.4)

# macOS
gcc -O2 -bundle -undefined dynamic_lookup -o mylib.so mylib.c $(pkg-config --cflags lua5.4)
```

在 Lua 中使用（`mylib.so` 放在当前目录；C 库的搜索路径是 `package.cpath`）：

```lua
local mylib = require("mylib")
print(mylib.square(5))       --> 25.0
print(mylib.hello("Lua"))    --> Hello, Lua!
```

## 18.7 userdata 与元表：把 C 数据暴露给 Lua

**userdata** 是一块由 Lua 管理的原始内存，配上元表就能像对象一样使用：

```c
// counter.c
#include <lua.h>
#include <lauxlib.h>

typedef struct { int value; } Counter;

static int counter_new(lua_State *L) {
    Counter *c = (Counter *)lua_newuserdatauv(L, sizeof(Counter), 0);
    c->value = (int)luaL_optinteger(L, 1, 0);     // 第 1 个参数可选，默认 0
    luaL_setmetatable(L, "Counter");              // 绑定元表
    return 1;
}

static int counter_inc(lua_State *L) {
    Counter *c = (Counter *)luaL_checkudata(L, 1, "Counter");   // 校验类型，防止传错对象
    c->value++;
    lua_pushinteger(L, c->value);
    return 1;
}

static const luaL_Reg methods[] = {
    {"inc", counter_inc},
    {NULL, NULL}
};

static const luaL_Reg module_funcs[] = {
    {"new", counter_new},
    {NULL, NULL}
};

int luaopen_counter(lua_State *L) {
    luaL_newmetatable(L, "Counter");     // 创建元表并登记到注册表
    lua_pushvalue(L, -1);
    lua_setfield(L, -2, "__index");      // 元表.__index = 元表自己
    luaL_setfuncs(L, methods, 0);        // 把方法放进元表
    lua_pop(L, 1);

    luaL_newlib(L, module_funcs);        // 返回的模块表里只有 new
    return 1;
}
```

```lua
local counter = require("counter")
local c = counter.new(10)
print(c:inc(), c:inc())      --> 11   12
```

## 18.8 注意事项与替代方案

**注意事项：**

- **API 随版本变化**：5.1 的 `luaL_register`、`lua_objlen` 在 5.2+ 中分别变为 `luaL_newlib` / `luaL_setfuncs`、`lua_rawlen`；5.4 的 `lua_newuserdatauv` 支持多个 user value。写库时注意目标版本
- **错误处理**：宿主调用 Lua 用 `lua_pcall`；C 函数里报错用 `luaL_error`（它不会返回）
- **内存**：Lua 字符串指针的生命周期、userdata 里的 C 资源释放（用 `__gc`）
- **沙箱**：给不可信脚本运行时，不要打开 `os`、`io` 等库，只注册需要的函数

**不想写 C 胶水代码的替代方案：**

- **LuaJIT FFI**：直接在 Lua 里声明并调用 C 函数（见第 19 节）
- **C++ 绑定库**：如 sol2、LuaBridge 等，用 C++ 模板简化绑定
- **代码生成器**：如 SWIG

## 18.9 纯 Lua 的“沙箱”

不借助 C，也可以用 `load` 的第四个参数限制脚本能访问的全局环境：

```lua
local env = {print = print, math = math}       -- 只暴露这两个

local code = [[
    print(math.sqrt(16))
    os.exit()          -- 沙箱里没有 os
]]

local f = load(code, "sandbox", "t", env)      -- "t"：只接受文本；env：脚本的全局环境
local ok, err = pcall(f)
print(ok, err)
--> 4.0
--> false   [string "sandbox"]:3: attempt to index a nil value (global 'os')
```

> 这只能限制**能调用什么**，无法限制死循环或耗尽内存，不能当作完整的安全方案。

## 18.10 小结与练习

**小结：**

- C 与 Lua 通过**虚拟栈**通信；索引正数从栈底、负数从栈顶
- 嵌入：`luaL_newstate` → `luaL_openlibs` → `luaL_dostring/dofile` → `lua_close`
- C 读 Lua 数据：`lua_getglobal` / `lua_getfield` + `lua_to*` + `lua_pop`
- C 调 Lua 函数：压入函数和参数后 `lua_pcall`
- Lua 调 C 函数：`int f(lua_State *L)`，参数在栈上，返回值个数作为 `return`
- 模块入口名 `luaopen_模块名`；userdata + 元表可封装 C 对象

**练习：** 阅读下面的 C 函数，说明它在 Lua 里怎么调用、返回什么：

```c
static int l_swap(lua_State *L) {
    lua_Number a = luaL_checknumber(L, 1);
    lua_Number b = luaL_checknumber(L, 2);
    lua_pushnumber(L, b);
    lua_pushnumber(L, a);
    return 2;
}
```

<details>
<summary>答案</summary>

注册为 `swap` 后，`local x, y = swap(1, 2)` 得到 `x = 2.0, y = 1.0`：它按顺序压入 `b`、`a` 两个值并返回 2 个返回值（数字以浮点数形式返回，所以是 `2.0` 和 `1.0`）。若传入非数字参数，`luaL_checknumber` 会自动抛出参数类型错误。

</details>

# 第 19 节　Lua 5.x 版本差异与 LuaJIT

## 19.1 版本时间线

| 版本 | 发布 | 特点（概述） |
|------|------|-------------|
| 5.0 | 2003 | 协程、元表、闭包等基础成型 |
| **5.1** | 2006 | 长期的“事实标准”，大量平台沿用（魔兽世界插件、Redis 脚本、LuaJIT 等） |
| 5.2 | 2011 | `goto`、`_ENV`、`bit32` |
| 5.3 | 2015 | **整数类型**、位运算符、`utf8` 库 |
| **5.4** | 2020 | 分代 GC、`<const>` / `<close>`，当前使用最广的新版本之一 |
| **5.5** | 2025-12 | 全局变量声明、`for` 循环变量只读、浮点数输出更精确等 |

> ⚠️ 官方每个**大版本之间都不保证完全兼容**，字节码也互不通用。

## 19.2 各版本新增 / 变化

### 5.1 → 5.2

- 新增 `goto` 和标签
- 新增 `_ENV`：取代 5.1 的 `setfenv` / `getfenv`
- `load` 可以接受字符串（取代 `loadstring`），并有 `env` 参数
- `unpack` 移到 `table.unpack`；新增 `table.pack`
- `module()` 被弃用，推荐“局部表 + return”写法
- 可以在 `pcall` 中 `yield`
- 新增 `bit32` 库（5.3 起弃用）
- 新增 `\z`、`\x`、十六进制浮点字面量

### 5.2 → 5.3

- **number 分为整数（integer）和浮点（float）两种子类型**，整数是 64 位
- 新增整除 `//`
- 新增**位运算符**：`& | ~ << >> ~`（`~` 一元为取反）
- 新增 `utf8` 库
- 新增 `table.move`、`string.pack/unpack/packsize`、`math.tointeger`、`math.type`、`math.ult`
- 数值转字符串：`3.0` 现在显示为 `3.0`（5.2 及以前显示 `3`）
- `table` 库函数遵循元方法；`__ipairs` 弃用

### 5.3 → 5.4

- 新增**分代 GC**（`collectgarbage("generational")`）
- 新增 **`<const>` 和 `<close>`** 变量属性
- 新增 `coroutine.close`、`warn` 函数
- 新的伪随机数算法（xoshiro256**），`math.random` 启动时自动随机播种
- `for` 数值循环的整数溢出处理更安全
- **字符串到数字的自动转换**移到字符串库的元方法里实现
- `__lt` 不再模拟 `__le`（需要 `<=` 就得定义 `__le`）
- C API：`lua_newuserdatauv` 等

### 5.4 → 5.5（2025 年 12 月发布）

官方列出的主要变化包括：

- **全局变量声明**：新增 `global` 声明语法，可以要求全局变量必须先声明（常见用法如 `global x, y`、`global <const> *`）。为了兼容旧代码，`global` 在默认配置下仍可作为普通名字使用
- **`for` 循环变量只读**：在循环体里给循环控制变量赋值，会变成编译错误
- **浮点数打印**：浮点数会用足够的位数输出，保证能被无损读回（例如 `0.1 + 0.2` 会显示 `0.30000000000000004`，而不是 5.4 里的 `0.3`）
- 新增 **`table.create`**（预分配表空间）
- `utf8.offset` 额外返回字符的结束位置
- GC：主要（major）回收改为**增量式**完成
- 大数组更省内存（官方称大数组约省 60%）
- 支持外部字符串（C API）、新增 `luaL_openselectedlibs`、`luaL_makeseed` 等

**对前面几份文档的影响（在 5.5 下运行时）：**

| 前文写法 | 5.5 下的情况 |
|---------|-------------|
| `for i = 1, 3 do i = i * 10 ... end`（第 5 节） | **编译错误**：不能给循环变量赋值。需要时改用 `local j = i * 10` |
| `print(0.1 + 0.2)` 输出 `0.3`（第 3 节） | 输出 `0.30000000000000004` |
| 以 `global` 作变量名 | 默认兼容，但建议避免 |

> 如果你的环境是 5.4，前面的文档完全适用；想让代码在 5.4 与 5.5 上都能跑，**不要修改 `for` 循环变量**，也不要依赖浮点数的具体打印位数。

## 19.3 功能对照表

| 功能 | 5.1 | LuaJIT | 5.2 | 5.3 | 5.4 | 5.5 |
|------|:---:|:------:|:---:|:---:|:---:|:---:|
| `goto` | ❌ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 整数子类型 | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ |
| `//` 整除 | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ |
| 位运算符 | ❌ | ❌（有 `bit` 库） | ❌（有 `bit32`） | ✅ | ✅ | ✅ |
| `utf8` 库 | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ |
| `table.unpack` | ❌（全局 `unpack`） | ❌（全局 `unpack`） | ✅ | ✅ | ✅ | ✅ |
| `_ENV` | ❌ | ❌ | ✅ | ✅ | ✅ | ✅ |
| `<const>` / `<close>` | ❌ | ❌ | ❌ | ❌ | ✅ | ✅ |
| `global` 声明 | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ |
| FFI | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ |

## 19.4 写兼容多个版本的代码

```lua
-- 常用“兼容垫片”
local unpack  = table.unpack or unpack                 -- 5.1/LuaJIT 用全局 unpack
local loadstr = loadstring or load                     -- 5.1 用 loadstring
local pack    = table.pack or function(...)           -- 5.1 没有 table.pack
    return {n = select("#", ...), ...}
end

-- 判断运行环境
print(_VERSION)                         --> Lua 5.4（LuaJIT 里是 Lua 5.1）
print(type(jit) == "table")             --> 在 LuaJIT 中为 true
print(math.type ~= nil)                 --> 5.3 及以上为 true（有整数子类型）

-- 语法层面的差异不能用 if 判断（5.1 里写 // 会直接编译失败），
-- 需要用 load 探测：
local hasIntDiv = load("return 1 // 1") ~= nil
print(hasIntDiv)                        --> 5.3+ 为 true
```

**5.1 → 新版本的常见替换：**

| 5.1 写法 | 新版本写法 |
|---------|-----------|
| `unpack(t)` | `table.unpack(t)` |
| `loadstring(s)` | `load(s)` |
| `setfenv` / `getfenv` | `_ENV` 或 `load(chunk, name, mode, env)` |
| `module(...)` | 局部表 + `return` |
| `table.getn(t)` | `#t` |
| `math.pow(x, y)` | `x ^ y` |

## 19.5 LuaJIT

**LuaJIT** 是 Lua 的一个**独立实现**，主要特点：

- **即时编译（JIT）**：把热点代码编译成机器码，速度通常远超标准 Lua 解释器
- 语言层面兼容 **Lua 5.1**，并带少量 5.2 / 5.3 的扩展；与 5.1 的 C API / ABI 兼容
- 内置 **FFI**：不写 C 胶水代码就能调用 C 函数、操作 C 数据结构
- 采用**滚动发布**：官方当前以 v2.1 分支作为生产使用的分支，版本号由最新提交的时间戳生成

**常见使用场景：** OpenResty / Nginx 脚本、LÖVE 游戏框架、Neovim 配置、需要高性能的嵌入式脚本。

### 与标准 Lua 的主要差异

- 没有整数子类型：所有数字都是双精度浮点，**整数精度范围到 2^53**
- 没有 `//`、位运算符、`utf8` 库（位运算用内置的 `bit` 库）
- 没有 `<const>` / `<close>`、`global`
- 数字等行为跟 5.1 一致，因此第 3、4 节中“整数/浮点”的内容在 LuaJIT 下不适用

### 示例：FFI

```lua
local ffi = require("ffi")

ffi.cdef[[
    size_t strlen(const char *s);
    typedef struct { double x, y; } point_t;
]]

print(tonumber(ffi.C.strlen("hello")))   --> 5        调用 C 标准库函数

local p = ffi.new("point_t", 3, 4)       -- 创建 C 结构体
print(p.x, p.y)                          --> 3   4
p.x = p.x * 2
print(p.x)                               --> 6

local arr = ffi.new("int[5]")            -- C 数组，下标从 0 开始
for i = 0, 4 do arr[i] = i * i end
print(arr[4])                            --> 16
```

### 示例：`bit` 库

```lua
local bit = require("bit")
print(bit.band(5, 3), bit.bor(5, 3), bit.bxor(5, 3))   --> 1   7   6
print(bit.lshift(1, 4), bit.rshift(256, 4))            --> 16   16
```

### 示例：检测与控制 JIT

```lua
if jit then
    print(jit.version)           --> 例如 LuaJIT 2.1.xxxxxxxxxx
    print(jit.status())          --> true 以及启用的优化选项
    -- jit.off()                 -- 关闭 JIT（调试时可用）
end
```

> 注意：LuaJIT 并非所有操作都能被编译，遇到不能编译的情况会退回解释器执行，速度会下降。写热点代码时：多用 `local`、避免在循环里创建闭包、用数组式 table，并用它自带的 profiler 实测。

## 19.8 小结与练习

**小结：**

- 5.2 加 `goto`/`_ENV`；5.3 加整数、位运算、`utf8`；5.4 加 `<const>`/`<close>` 与分代 GC；5.5 加 `global` 声明、只读循环变量等

## 20.2 项目二：INI 配置解析器

**目标**：解析形如下面的 INI 文本，得到嵌套表；支持注释、节（section）、类型自动转换，并能把结果再输出成 INI 文本。

```ini
; 示例配置

host = 127.0.0.1
port = 8080
timeout = 2.5

[user]
title = "Hello World"
```

```lua
-- ini.lua
local Ini = {}

-- 把字符串转换成合适的 Lua 类型
local function convert(v)
    if v == "true"  then return true  end
    if v == "false" then return false end
    local n = tonumber(v)
    if n then return n end
    return (v:gsub('^"(.*)"$', "%1"))           -- 去掉两端的双引号
end

-- 解析：成功返回表；失败返回 nil, 错误信息
function Ini.parse(text)
    local result, section = {}, nil
    local lineNo = 0

    for rawLine in (text .. "\n"):gmatch("(.-)\r?\n") do
        lineNo = lineNo + 1
        local line = rawLine:match("^%s*(.-)%s*$")          -- 去掉首尾空白

        local first = line:sub(1, 1)
        if line == "" or first == ";" or first == "#" then
            -- 空行或注释：跳过
        else
            local name = line:match("^%[([^%]]+)%]$")       -- [section]
            if name then
                section = name
                result[section] = result[section] or {}
            else
                local k, v = line:match("^([%w_%.]+)%s*=%s*(.-)$")   -- key = value
                if not k then
                    return nil, string.format("第 %d 行格式错误: %s", lineNo, line)
                end
                if section then
                    result[section][k] = convert(v)
                else
                    result[k] = convert(v)
                end
            end
        end
    end
    return result
end

-- 序列化：表 → INI 文本（顶层键在前，节按名字排序）
function Ini.dump(t)
    local lines, keys, sections = {}, {}, {}
    for k, v in pairs(t) do
        if type(v) == "table" then sections[#sections + 1] = k
        else keys[#keys + 1] = k end
    end
    table.sort(keys)
    table.sort(sections)

    for _, k in ipairs(keys) do
        lines[#lines + 1] = k .. " = " .. tostring(t[k])
    end
    for _, s in ipairs(sections) do
        lines[#lines + 1] = ""
        lines[#lines + 1] = "[" .. s .. "]"
        local ks = {}
        for k in pairs(t[s]) do ks[#ks + 1] = k end
        table.sort(ks)
        for _, k in ipairs(ks) do
            lines[#lines + 1] = k .. " = " .. tostring(t[s][k])
        end
    end
    return table.concat(lines, "\n")
end

return Ini
```

## 20.3 项目三：游戏脚本——事件系统 + 协程调度

游戏里经常需要：①**事件**（“Boss 死了”通知给关心它的模块）；②**剧情脚本**（“说话 → 等 1 秒 → 再说话”）。用闭包 + 协程可以写得非常自然。

```lua
-- 1. 事件系统（面向对象 + 闭包）
local Events = {}
Events.__index = Events

function Events.new()
    return setmetatable({handlers = {}}, Events)
end

-- 订阅：返回一个“取消订阅”的函数
function Events:on(name, fn)
    local list = self.handlers[name]
    if not list then
        list = {}
        self.handlers[name] = list
    end
    list[#list + 1] = fn

    return function()
        for i, f in ipairs(list) do
            if f == fn then table.remove(list, i) break end
        end
    end
end

-- 触发：先复制一份列表，避免处理函数里取消订阅影响遍历
function Events:emit(name, ...)
    local list = self.handlers[name]
    if not list then return end
    local copy = table.move(list, 1, #list, 1, {})
    for _, fn in ipairs(copy) do fn(...) end
end

-- 2. 协程调度器
local Scheduler = {tasks = {}, time = 0}

function Scheduler.spawn(fn)
    Scheduler.tasks[#Scheduler.tasks + 1] = {co = coroutine.create(fn), wake = 0}
end

local function wait(seconds)                       -- 在任务里调用：让出执行权，等待若干秒
    coroutine.yield(seconds)
end

function Scheduler.update(dt)                      -- 每帧调用一次
    Scheduler.time = Scheduler.time + dt
    local alive = {}
    for _, t in ipairs(Scheduler.tasks) do
        if Scheduler.time >= t.wake then
            local ok, delay = coroutine.resume(t.co)
            if not ok then print("任务出错: " .. tostring(delay)) end
            if coroutine.status(t.co) ~= "dead" then
                t.wake = Scheduler.time + (delay or 0)
                alive[#alive + 1] = t
            end
        else
            alive[#alive + 1] = t
        end
    end
    Scheduler.tasks = alive
end

local function stamp() return string.format("[t=%d]", Scheduler.time) end

-- 3. 使用
local events = Events.new()
events:on("boss_dead", function(name)
    print("事件: " .. name .. " 被击败！")
end)

Scheduler.spawn(function()                         -- 剧情任务
    print(stamp() .. " NPC: 欢迎来到村庄")
    wait(1)
    print(stamp() .. " NPC: 前方有怪物")
    wait(2)
    events:emit("boss_dead", "史莱姆王")
end)

Scheduler.spawn(function()                         -- 巡逻任务
    for i = 1, 3 do
        print(stamp() .. " 巡逻 " .. i)
        wait(1)
    end
end)

for tick = 1, 5 do                                 -- 模拟 5 帧，每帧过 1 秒
    Scheduler.update(1)
end
--> [t=1] NPC: 欢迎来到村庄
--> [t=1] 巡逻 1
--> [t=2] NPC: 前方有怪物
--> [t=2] 巡逻 2
--> [t=3] 巡逻 3
--> 事件: 史莱姆王 被击败！
```

**设计要点：**

- 事件的 `on` 返回“取消订阅函数”，利用**闭包**保存了 `list` 和 `fn`
- 剧情脚本写成**顺序代码**，`wait(n)` 内部 `yield`，由调度器在合适的时间 `resume`——比“状态机 + 计时器变量”清晰得多
- `emit` 遍历前复制列表，是常见的防御性写法

**可以继续扩展的方向：**

- 在任务里等待某个事件：`waitForEvent("boss_dead")`（订阅时记录协程，事件触发时 `resume`）
- 任务取消、任务优先级
- 接入真实游戏循环（LÖVE 的 `love.update(dt)` 里直接调用 `Scheduler.update(dt)`）

## 20.4 综合练习

1. **文字冒险**：增加 `drop` 命令，以及“只有拿着火把才能进入图书馆”的规则。
2. **INI 解析器**：支持行尾注释（`port = 8080 ; 备注`）和用逗号分隔的数组值。
3. **调度器**：实现 `waitForEvent(events, name)`，让任务等待某个事件再继续。

<details>
<summary>练习 3 参考思路</summary>

关键点：事件回调**不要直接 `resume`** 等待中的协程（否则它之后再 `wait` 产生的等待时间会被回调吞掉，调度器就不知道何时再唤醒它）。更稳妥的做法是：回调只把任务标记为“可运行”，由调度器下一帧统一 `resume`。

先在 `Scheduler.update` 里，`resume` 之前记录当前任务：

```lua
Scheduler.current = t                              -- 加在 coroutine.resume(t.co) 之前
local ok, delay = coroutine.resume(t.co)
```

然后实现 `waitForEvent`：

```lua
local function waitForEvent(events, name)
    local task = Scheduler.current                 -- 当前正在运行的任务
    local result
    local cancel
    cancel = events:on(name, function(...)
        cancel()                                   -- 只响应一次
        result = table.pack(...)                   -- 保存事件参数
        task.wake = 0                              -- 标记为可运行，下一次 update 会被唤醒
    end)
    coroutine.yield(math.huge)                     -- 让出，并且“无限期”等待（不会被计时唤醒）
    return table.unpack(result, 1, result.n)       -- 被唤醒后，返回事件参数
end
```

用法：

```lua
Scheduler.spawn(function()
    print("等待 boss_dead...")
    local name = waitForEvent(events, "boss_dead")
    print("收到事件，击败者:", name)
end)
```
