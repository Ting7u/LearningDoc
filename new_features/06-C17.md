# C17（ISO/IEC 9899:2018，又称 C18）

> 2017 年完成技术工作，2018 年发布，所以称 C17 或 C18。`__STDC_VERSION__ == 201710L`。

## 要点：**没有新的语言特性**

C17 是 C11 的**缺陷修复版（Technical Corrigendum）**，只做：

- 修正 C11 标准文本中的缺陷、歧义和矛盾
- 澄清措辞（例如原子操作、对齐、`aligned_alloc` 等边界行为）
- 更新 `__STDC_VERSION__` 为 `201710L`

因此 **你写的 C11 代码在 C17 下完全一样**，编译器的 `-std=c17` 与 `-std=c11` 差异极小。

## 对开发者的实际意义

```c
#if __STDC_VERSION__ >= 201710L
    // C17 及以上
#elif __STDC_VERSION__ >= 201112L
    // C11
#endif
```

```bash
gcc  -std=c17 main.c
clang -std=c18 main.c    # c17 与 c18 是同义词
```

### 例子：C11 代码在 C17 下无变化

```c
#include <stdio.h>

int main(void) {
    printf("%ld\n", __STDC_VERSION__);   // 201710
    return 0;
}
```

## 一些被明确/修正的小点（了解即可）

- 一些原子初始化相关宏（如 `ATOMIC_VAR_INIT`）后来在 C23 中被正式废弃/移除
- 对 DR（Defect Report）的汇总处理，使行为更明确，不改变良好代码的含义

## 小结

| 项目 | C11 | C17 |
|---|---|---|
| 新语法 | 大量 | 无 |
| 目的 | 增加功能 | 修 bug、澄清文本 |
| 迁移成本 | — | 几乎为零 |
