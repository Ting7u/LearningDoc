# C 语言中 `const` 与 `static` 的区别

> 一句话总结：
> - **`const`** 是**类型限定符**（type qualifier），回答的是"这个变量**能不能被修改**"。
> - **`static`** 是**存储类说明符**（storage-class specifier），回答的是"这个变量/函数**活多久、谁能看见**"。
>
> 两者管的是**不同维度**的事情，所以它们可以**同时使用**（`static const int x = 1;`）。

---

## 0. 先建立几个基本概念

学 `const` 和 `static` 之前，先分清 C 语言里描述一个变量的几个"维度"：

| 维度 | 含义 | 常见取值 |
|---|---|---|
| **作用域 (scope)** | 名字在源码的哪一段能被看见 | 块作用域、文件作用域 |
| **存储期 (storage duration)** | 对象的生命周期（什么时候创建、什么时候销毁） | 自动 (automatic)、静态 (static)、动态 (allocated) |
| **链接性 (linkage)** | 不同 `.c` 文件里的同名标识符是不是同一个东西 | 外部链接 (external)、内部链接 (internal)、无链接 (none) |
| **可变性** | 能不能通过这个名字修改值 | 可修改 / `const` 只读 |

`static` 主要影响 **存储期** 和 **链接性**；`const` 只影响 **可变性**。

> ⚠️ 关于"内存位置"的说明：C 语言标准**只规定了存储期，没有规定** `.data` / `.bss` / `.rodata` 这些"段"。本文讲的内存位置，是 **GCC / Clang + Linux (ELF)** 这类主流环境下的**典型实现**，其他平台（例如某些嵌入式平台）可能不同，编译器优化也可能改变实际结果。

## 1. `const`：只读限定

### 1.1 基本用法

```c
const int a = 10;
a = 20;          // ❌ 编译错误：不能给只读变量赋值
```

`const` 修饰的变量**必须在定义时初始化**（局部变量不初始化则值不确定，之后又无法赋值，没有意义）。

### 1.2 `const` 与指针（最容易混淆的地方）

**技巧：从右往左读，`*` 读作 "指向……的指针"。**

```c
int x = 1, y = 2;

const int *p1 = &x;        // p1 是"指向 const int 的指针"
int const *p2 = &x;        // 同上，写法不同，意思一样
int *const p3 = &x;        // p3 是"const 指针，指向 int"
const int *const p4 = &x;  // p4 是"const 指针，指向 const int"

*p1 = 5;   // ❌ 不能通过 p1 改 x 的值
p1 = &y;   // ✅ p1 可以改指向

*p3 = 5;   // ✅ 可以改 x 的值
p3 = &y;   // ❌ p3 不能改指向

*p4 = 5;   // ❌
p4 = &y;   // ❌
```

记忆口诀：**`const` 在 `*` 左边 → 锁住"指向的内容"；`const` 在 `*` 右边 → 锁住"指针本身"。**

```
const int *p        int *const p        const int *const p
┌───┐  ┌───┐        ┌───┐  ┌───┐        ┌───┐  ┌───┐
│ p │─▶│ x │        │ p │─▶│ x │        │ p │─▶│ x │
└───┘  └───┘        └───┘  └───┘        └───┘  └───┘
 可改   只读          只读    可改          只读    只读
(p可换) (*p不可改)   (p不可换)(*p可改)
```

### 1.3 `const` 用在函数参数上（最常见的实战用法）

```c
// 承诺：这个函数不会修改 s 指向的字符串
size_t my_strlen(const char *s) {
    size_t n = 0;
    while (s[n] != '\0') n++;
    return n;
}
```

好处：
1. 给调用者一个**承诺**，看函数签名就知道它不会改你的数据；
2. 编译器帮你检查，误写 `s[0] = 'x';` 会直接报错；
3. 可以传入 `const` 数据（如字符串字面量）而不产生警告。

### 1.4 `const` 与字符串字面量

```c
const char *s1 = "hello";   // ✅ 推荐：字面量存放在只读区
char       *s2 = "hello";   // 语法上 C 允许，但不推荐
char        s3[] = "hello"; // 把 "hello" 拷贝一份到数组 s3（在栈上）

s3[0] = 'H';   // ✅ 数组是自己的副本，可以改
s2[0] = 'H';   // ⚠️ 未定义行为 (UB)，常见表现是段错误
```

### 1.5 `const` 的生命周期、作用域、位置：**由声明的位置决定，`const` 本身不改变它们**

| 写法 | 存储期 | 典型位置 |
|---|---|---|
| 函数内 `const int c = 1;` | 自动（函数返回即销毁） | 栈（可能被优化掉或放进寄存器） |
| 文件作用域 `const int c = 1;` | 静态（整个程序运行期间） | 通常在 `.rodata`（只读数据段） |

也就是说：**局部的 `const` 变量仍然是"每次调用都重新创建的栈变量"**，只是编译器不让你改它。

### 1.6 ⚠️ C 里的 `const` ≠ 编译期常量（和 C++ 不同！）

如果你以后看 C++ 的资料，要特别留意这一点。在 C 里，`const int N = 10;` 定义的是一个"**只读的变量**"，**不是常量表达式**：

```c
const int N = 10;

int arr1[N];            // 文件作用域：❌ 编译错误
void f(void) {
    int arr2[N];        // 块作用域：C99 起被当作变长数组 (VLA)，不是普通数组
}

switch (x) {
    case N: break;      // ❌ 编译错误：case 标签必须是常量表达式
}
```

想要真正的编译期常量，C 里传统的做法是：

```c
#define N 10            // 宏
enum { N = 10 };        // 枚举常量（只能是整数）
```

> C23 标准引入了 `constexpr`，但具体支持情况取决于你的编译器版本，请自行查阅编译器文档确认。

### 1.7 ⚠️ 别用强制类型转换去改 `const`

```c
const int x = 10;
int *p = (int *)&x;   // 强转去掉 const
*p = 20;              // ❌ 未定义行为 (UB)
```

修改一个"本来就定义为 `const` 的对象"是**未定义行为**：
- 如果 `x` 是全局 `const`，放在只读段 `.rodata`，写入通常会**段错误**；
- 如果 `x` 是局部 `const`，可能"看起来改成功了"，也可能因为编译器优化，后面读到的仍是 10。

**结论：不要这么做。**

## 2. `static`：改变"存活时间"和"可见范围"

`static` 在 C 里有 **3 种主要用法**，作用各不相同，这是初学者最容易搞混的地方。

### 2.1 用法一：`static` 局部变量（改变**生命周期**）

```c
#include <stdio.h>

int counter_auto(void) {
    int n = 0;          // 自动变量：每次调用都重新创建、重新初始化
    n++;
    return n;
}

int counter_static(void) {
    static int n = 0;   // 静态局部变量：只初始化一次，函数返回后也不销毁
    n++;
    return n;
}

int main(void) {
    for (int i = 0; i < 3; i++)
        printf("auto=%d  static=%d\n", counter_auto(), counter_static());
    return 0;
}
```

输出：

```
auto=1  static=1
auto=1  static=2
auto=1  static=3
```

**要点：**

| 特性 | 说明 |
|---|---|
| 作用域 | **仍然是块作用域**——只有定义它的函数内部能用这个名字 |
| 生命周期 | **整个程序运行期间**（静态存储期） |
| 初始化 | 初始化值必须是**常量表达式**；只初始化**一次**（概念上在程序启动前完成，**不是**第一次调用时） |
| 默认值 | 不显式初始化则自动**清零**（整数为 0，指针为 `NULL`） |
| 位置 | 显式初始化为非 0 → 通常在 `.data`；未初始化或初始化为 0 → 通常在 `.bss` |

生命周期对比图：

```
时间轴 ──────────────────────────────────────────────▶

程序启动                                             程序结束
   │                                                    │
   │  static int n  ═══════════════════════════════════ │  一直存在
   │
   │      调用1        调用2        调用3
   │     ┌──────┐     ┌──────┐     ┌──────┐
   │     │int n │     │int n │     │int n │              每次调用才创建
   │     └──────┘     └──────┘     └──────┘              返回即销毁 (栈)
```

**典型用途：** 需要"记住上一次调用状态"的函数（计数器、ID 生成器、缓存等）。

> ⚠️ 注意：静态局部变量整个程序只有一份，所以函数变得**不可重入**，多线程下如果没有同步措施也**不是线程安全**的。

### 2.2 用法二：`static` 全局变量（改变**链接性**）

```c
// a.c
int  g_public = 1;          // 外部链接：其他 .c 文件可以用 extern 访问
static int g_private = 2;   // 内部链接：只有 a.c 自己能访问
```

```c
// b.c
extern int g_public;        // ✅ 可以
extern int g_private;       // ❌ 链接时报错：undefined reference
```

**要点：**

| 特性 | 说明 |
|---|---|
| 作用域 | 文件作用域（从声明处到文件末尾） |
| 生命周期 | 整个程序运行期间（全局变量本来就是，`static` 没有改变这点） |
| 链接性 | 由**外部链接**变为**内部链接**（这是 `static` 在此处的唯一作用） |
| 位置 | `.data` 或 `.bss` |

**典型用途：** 把"只属于这个源文件的实现细节"藏起来，避免不同文件里的同名全局变量冲突（相当于"文件级私有"）。

### 2.3 用法三：`static` 函数（改变**链接性**）

```c
// util.c
static int helper(int x) {   // 只在 util.c 内部可见
    return x * 2;
}

int api_double(int x) {      // 对外公开的接口
    return helper(x);
}
```

其他文件即使写了 `int helper(int);` 声明再调用，链接时也会报 `undefined reference`。

**典型用途：** 把内部辅助函数隐藏起来，只暴露真正的接口。这是 C 语言里实现"模块封装"的基本手段。

> 💡 `static` 函数/变量若写在**头文件**里，每个包含它的 `.c` 文件都会得到**各自独立的一份拷贝**，不是共享的。头文件中共享的全局变量应该是"头文件 `extern` 声明 + 某个 `.c` 里定义一次"。

## 3. 综合示例：各种变量分别放在哪

```c
#include <stdio.h>

int         g_init   = 10;      // ① 全局，已初始化
int         g_uninit;           // ② 全局，未初始化
static int  s_global = 20;      // ③ 静态全局
const int   c_global = 30;      // ④ 全局 const
static const int sc_global = 40;// ⑤ 静态全局 const

void func(void) {
    int        a       = 1;     // ⑥ 局部变量
    const int  c_local = 2;     // ⑦ 局部 const
    static int s_local = 3;     // ⑧ 静态局部（非 0 初值）
    static int s_zero;          // ⑨ 静态局部（未初始化）
    const char *p = "hello";    // ⑩ 指针 p 是局部变量，"hello" 是字面量
    (void)a; (void)c_local; (void)s_local; (void)s_zero; (void)p;
}
```

### 3.1 内存分布图（典型 Linux + GCC 环境）

```
高地址
┌─────────────────────────────────────────┐
│               栈  Stack                 │
│   ⑥ a          (自动，函数返回即销毁)    │
│   ⑦ c_local    (只读，但仍在栈上)        │
│   ⑩ p          (指针变量本身)            │
│                   ↓  向下增长            │
│                                         │
│                 ······                  │
│                                         │
│                   ↑  向上增长            │
│               堆  Heap                  │
│   (malloc / free 管理)                   │
├─────────────────────────────────────────┤
│           .bss  (未初始化/初值为0)        │
│   ② g_uninit                            │
│   ⑨ s_zero      (static 局部)            │
├─────────────────────────────────────────┤
│           .data (已初始化，可读写)         │
│   ① g_init                              │
│   ③ s_global    (static 全局)            │
│   ⑧ s_local     (static 局部)            │
├─────────────────────────────────────────┤
│           .rodata (只读数据)              │
│   ④ c_global                            │
│   ⑤ sc_global                           │
│   ⑩ "hello"     (字符串字面量)           │
├─────────────────────────────────────────┤
│           .text (代码段，只读可执行)       │
│   main(), func() 等函数机器码             │
└─────────────────────────────────────────┘
低地址
```

### 3.2 汇总对比表

| 编号 | 变量 | 作用域 | 存储期（生命周期） | 链接性 | 典型段 | 能否修改 |
|---|---|---|---|---|---|---|
| ① | `int g_init = 10;` | 文件 | 整个程序 | 外部 | `.data` | ✅ |
| ② | `int g_uninit;` | 文件 | 整个程序 | 外部 | `.bss` | ✅ |
| ③ | `static int s_global = 20;` | 文件 | 整个程序 | **内部** | `.data` | ✅ |
| ④ | `const int c_global = 30;` | 文件 | 整个程序 | 外部（⚠️ C 与 C++ 不同） | `.rodata` | ❌ |
| ⑤ | `static const int sc_global = 40;` | 文件 | 整个程序 | 内部 | `.rodata` | ❌ |
| ⑥ | `int a = 1;`（函数内） | 块 | **自动**（到函数返回） | 无 | 栈 | ✅ |
| ⑦ | `const int c_local = 2;`（函数内） | 块 | **自动** | 无 | 栈 | ❌ |
| ⑧ | `static int s_local = 3;`（函数内） | 块 | **整个程序** | 无 | `.data` | ✅ |
| ⑨ | `static int s_zero;`（函数内） | 块 | **整个程序** | 无 | `.bss` | ✅ |

> 说明：表中"典型段"是常见实现的行为，不是标准保证。开启优化后，编译器可能把某些 `const` 变量直接替换成立即数，甚至完全不生成存储空间。

## 4. `const` 与 `static` 的核心对比

| 对比项 | `const` | `static` |
|---|---|---|
| 语法类别 | 类型限定符 | 存储类说明符 |
| 解决什么问题 | **可变性**：让变量只读 | **生命周期 + 可见性**：延长存活时间 / 限制链接范围 |
| 是否改变生命周期 | ❌ 不改变（由声明位置决定） | ✅ 局部变量：自动 → 静态 |
| 是否改变作用域 | ❌ 不改变 | ❌ 不改变（局部依然是块作用域） |
| 是否改变链接性 | ❌ 不改变 | ✅ 全局变量/函数：外部 → 内部 |
| 是否影响内存位置 | 间接：文件作用域的 `const` 通常进 `.rodata` | 直接：局部变量从栈移到 `.data`/`.bss` |
| 能修饰什么 | 变量、指针、参数、返回值类型…… | 变量、函数（**不能**修饰参数、类型） |
| 默认初始化 | 无 | 静态存储期对象默认清零 |
| 能一起用吗 | ✅ `static const int x = 1;` | |

## 5. 组合用法

### 5.1 `static const`：文件私有的只读常量表

```c
// 只在本文件使用的查找表，既不能被修改，也不会污染全局命名空间
static const char *const WEEKDAY[] = {
    "Sun", "Mon", "Tue", "Wed", "Thu", "Fri", "Sat"
};
```

- `static`：内部链接，其他文件看不见；
- 第一个 `const`：字符串内容只读；
- 第二个 `const`（`*` 右边）：数组元素（指针）不可改。

### 5.2 函数内的 `static const`：避免每次调用都重新构造

```c
int day_of_month(int month) {
    // 数组存放在静态存储区，只有一份；
    // 若去掉 static，每次调用都要在栈上重新构造这个数组
    static const int days[12] = {31,28,31,30,31,30,31,31,30,31,30,31};
    return days[month - 1];
}
```

### 5.3 `const` 返回值 / `static` 返回值指针

```c
// ✅ 返回静态局部变量的地址是安全的（它不会随函数返回而销毁）
const char *get_name(void) {
    static const char name[] = "Alice";
    return name;
}

// ❌ 返回自动局部变量的地址：悬空指针 (dangling pointer)
const char *bad_name(void) {
    const char name[] = "Alice";   // 在栈上
    return name;                    // 函数返回后栈帧失效，未定义行为
}
```

### 5.4 `volatile` 补充（了解即可）

`const` 常与 `volatile` 搭配出现在嵌入式开发中：

```c
// 只读的硬件状态寄存器：程序不能写它，但硬件会随时改变它的值
volatile const uint32_t *STATUS_REG = (volatile const uint32_t *)0x40000000;
```

（地址仅为示意。）"只读"不等于"值不会变"，这是 `const` 很容易被误解的地方。

## 6. 常见误区汇总

| 误区 | 正确理解 |
|---|---|
| "`const` 变量就是常量，可以当数组长度用" | 在 C 里 `const` 变量**不是常量表达式**（C++ 才是），用 `#define` / `enum` 代替 |
| "`const` 变量一定放在只读内存" | 不一定。局部 `const` 在栈上；且存放位置是实现细节 |
| "`static` 修饰全局变量会让它变成静态存储" | 全局变量**本来就是**静态存储期，`static` 只是把它改成**内部链接** |
| "`static` 局部变量是第一次调用时才初始化" | C 里是**程序启动前**就完成初始化（C++ 才有"第一次执行到时初始化"的语义），所以初值必须是常量表达式 |
| "`static` 局部变量的作用域变成全局了" | 作用域**仍是块作用域**，只是**生命周期**变长 |
| "`const` 修饰的东西怎么都改不了" | 通过指针强转可以"绕过"编译检查，但修改真正的 `const` 对象是**未定义行为** |
| "`static` 函数只是不能被调用" | 是**不能被其他源文件链接到**；本文件内当然能调用 |

## 7. 动手验证：自己用工具看一眼

把上面 3 节的示例保存为 `demo.c`（补一个 `main` 调用 `func()` 即可），用下面的命令观察：

```bash
# 编译（先关闭优化，避免变量被优化掉）
gcc -O0 -c demo.c -o demo.o

# 查看符号表及其所在段
nm demo.o

# 查看各段大小 (text / data / bss)
size demo.o

# 查看只读数据段内容
objdump -s -j .rodata demo.o
```

`nm` 输出中每行的字母含义（典型值）：

| 字母 | 含义 |
|---|---|
| `T` / `t` | `.text` 代码段 |
| `D` / `d` | `.data` 已初始化数据 |
| `B` / `b` | `.bss` 未初始化数据 |
| `R` / `r` | `.rodata` 只读数据 |

**大写 = 外部链接（全局可见），小写 = 内部链接（`static`，本文件私有）。** 你能直观看到 `static` 对链接性的影响：`g_init` 显示为大写 `D`，而 `s_global` 显示为小写 `d`。

静态局部变量在符号表中通常会带一个编号后缀（形如 `s_local.0`，具体命名依编译器而定）。

```
const  → 管"改不改"    → 只读；不改变生命周期/作用域
static → 管"活多久、给谁看"
          ├─ 局部变量：生命周期 = 整个程序，作用域仍是块
          ├─ 全局变量：外部链接 → 内部链接（文件私有）
          └─ 函数    ：外部链接 → 内部链接（文件私有）

两者可组合：static const → 文件私有 + 只读
```

**选用建议：**
1. 函数不修改传入的数据 → 参数加 `const`（指针参数尤其重要）；
2. 只在本文件使用的全局变量/函数 → 加 `static`；
3. 需要跨调用保存状态 → `static` 局部变量（注意线程安全和可重入问题）；
4. 需要编译期常量（数组长度、`case` 标签）→ 用 `#define` 或 `enum`，不要用 `const` 变量。
