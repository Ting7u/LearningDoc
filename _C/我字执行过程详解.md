# 输入"我"字时，函数内部的完整执行过程

"我"这个汉字在 UTF-8 编码下对应三个字节：`E6 88 91`。下面把 `read_one_char_correctly()` 函数从进入到返回的每一步都拆开讲。

---

## 准备阶段：进入函数

```c
int nbytes = 0;
mbstate_t state;
memset(&state, 0, sizeof(state));
```

- `nbytes` 置为 0，用来累计"为了拼出这一个字符，已经读了几个字节"。
- `state` 是解析状态的"记账本"，类型是 `mbstate_t`。它的内部结构不透明（由具体的 C 库实现决定），但功能上可以理解成：**记住"当前正在解析的字符，目前已经收到了几个字节、根据引导字节判断还差几个字节"**。
- `memset` 把它清零，代表"从一个全新字符的开头开始解析"。

此时状态如下：

```
nbytes = 0
state  = { 空，尚未开始任何字符的解析 }
```

进入 `while (1)` 循环。

---

## 第 1 轮循环：读到 0xE6

### 读取字节

```c
int c = getchar();   // c = 0xE6
nbytes++;             // nbytes 变成 1
char one_byte = (char)c;
```

### 调用 mbrtowc

```c
size_t result = mbrtowc(&wc, &one_byte, 1, &state);
```

**mbrtowc 内部在做什么**（概念层面）：

1. 因为 `state` 是空的，`mbrtowc` 知道"这是一个新字符的第一个字节"。
2. 把 `0xE6` 拆成二进制：`1110 0110`。
3. 最高几位是 `1110`，这在 UTF-8 编码规则里代表：**"这是一个三字节字符的引导字节（lead byte），后面还应该跟 2 个续接字节"**。
4. `mbrtowc` 把这个判断结果记录进 `state` 里：**"已收到 1 个字节，判定为三字节字符的开头，还差 2 个字节"**。
5. 因为字符还没拼完，函数返回一个表示"不完整"的特殊值。

### 线框图

```
┌─────────────────────────────────────────────┐
│ c = getchar()  →  c = 0xE6                   │
│ nbytes = 1                                   │
│                                               │
│ one_byte = 0xE6                              │
│ mbrtowc(&wc, &one_byte, 1, &state)           │
│                                               │
│   state 内部逻辑：                             │
│   0xE6 的二进制是 1110 0110                     │
│   最高位是 "1110" → 这是三字节字符的"引导字节"      │
│   state 记住："我还差 2 个字节才能拼完"           │
│                                               │
│ 返回值 result = -2                            │
└─────────────────────────────────────────────┘
                    │
                    ▼
     result == -2 → 打印提示，continue，回到循环开头
```

### 返回值判断

```c
result == (size_t)-2   // 成立
```

对应代码分支：

```c
if (result == (size_t)-2)
{
    printf("  已读第 %d 个字节 (0x%02X)，还不够拼成一个完整字符，继续读...\n",
           nbytes, (unsigned char)c);
    continue;
}
```

**打印输出**：
```
  已读第 1 个字节 (0xE6)，还不够拼成一个完整字符，继续读...
```

`continue` 让程序跳过本轮循环剩下的代码，回到 `while (1)` 开头，**但 `state` 不会被清零**——这是整个机制的关键：进度被保留了下来。

此时状态：

```
nbytes = 1
state  = { 已收到 1/3 个字节，属于某个三字节字符 }
```

---

## 第 2 轮循环：读到 0x88

### 读取字节

```c
int c = getchar();   // c = 0x88
nbytes++;             // nbytes 变成 2
char one_byte = (char)c;
```

### 调用 mbrtowc

```c
size_t result = mbrtowc(&wc, &one_byte, 1, &state);
```

**mbrtowc 内部在做什么**：

1. 这次 `state` 不是空的，它记得"上一步已经收到了三字节字符的第 1 个字节"。
2. 把 `0x88` 拆成二进制：`1000 1000`。
3. 最高两位是 `10`，这在 UTF-8 规则里代表：**"这是一个合法的续接字节（continuation byte）"**。
4. `mbrtowc` 更新 `state`：**"已收到 2 个字节，还差最后 1 个"**。
5. 字符依然没拼完，继续返回"不完整"。

### 线框图

```
┌─────────────────────────────────────────────┐
│ c = getchar()  →  c = 0x88                   │
│ nbytes = 2                                   │
│                                               │
│ one_byte = 0x88                              │
│ mbrtowc(&wc, &one_byte, 1, &state)           │
│                                               │
│   state 内部逻辑：                             │
│   0x88 的二进制是 1000 1000                     │
│   最高两位是 "10" → 这是"续接字节"，合法           │
│   state 更新："已经收了 2 个字节，还差 1 个"       │
│                                               │
│ 返回值 result = -2                            │
└─────────────────────────────────────────────┘
                    │
                    ▼
     result == -2 → 打印提示，continue，再回到循环开头
```

### 返回值判断

同样 `result == (size_t)-2`，走同一个分支：

**打印输出**：
```
  已读第 2 个字节 (0x88)，还不够拼成一个完整字符，继续读...
```

此时状态：

```
nbytes = 2
state  = { 已收到 2/3 个字节，属于同一个三字节字符 }
```

---

## 第 3 轮循环：读到 0x91，字符终于拼完整

### 读取字节

```c
int c = getchar();   // c = 0x91
nbytes++;             // nbytes 变成 3
char one_byte = (char)c;
```

### 调用 mbrtowc

```c
size_t result = mbrtowc(&wc, &one_byte, 1, &state);
```

**mbrtowc 内部在做什么**：

1. `state` 记得"已经收到 2 个字节，还差 1 个"。
2. 把 `0x91` 拆成二进制：`1001 0001`。
3. 最高两位是 `10`，同样是合法的续接字节，而且**正好是期待中的最后一个字节**。
4. 到这里，三个字节全部凑齐：`E6 88 91`。`mbrtowc` 把这三个字节按 UTF-8 解码规则还原成一个 Unicode 码点：

   ```
   E6 = 1110 0110   →  取后 4 位：0110
   88 = 1000 1000   →  取后 6 位：001000
   91 = 1001 0001   →  取后 6 位：010001

   拼接：0110 001000 010001
       = 0110 0010 0001 0001
       = 0x6211
   ```

5. 把解出来的码点 `0x6211` 写入 `wc`。
6. 因为这次调用**只消费了 1 个字节**（我们每次只喂 1 个字节进去），所以返回值是 `1`，而不是 `3`——这个返回值代表的是"本次调用吃掉了几个新字节"，不是"整个字符总共几个字节"。

### 线框图

```
┌─────────────────────────────────────────────┐
│ c = getchar()  →  c = 0x91                   │
│ nbytes = 3                                   │
│                                               │
│ one_byte = 0x91                              │
│ mbrtowc(&wc, &one_byte, 1, &state)           │
│                                               │
│   state 内部逻辑：                             │
│   0x91 的二进制是 1001 0001                     │
│   也是"续接字节"，而且正好是第 3 个                 │
│   三个字节合起来解码出：                          │
│     0xE6 0x88 0x91  →  Unicode U+6211        │
│                                               │
│ 返回值 result = 1   （表示这次调用消费了1个字节）    │
│ wc = 0x6211                                  │
└─────────────────────────────────────────────┘
                    │
                    ▼
     result 既不是 -2 也不是 -1
     → 走到最后的 printf 分支，函数返回
```

### 返回值判断

```c
result == 1   // 既不是 -2 也不是 -1
```

两个 `if` 分支都不成立，代码往下走，进入最后的处理逻辑。

---

## 最后一步：把码点转换成可读字符并打印

```c
char mb_buf[MB_LEN_MAX + 1];
mbstate_t out_state;
memset(&out_state, 0, sizeof(out_state));

size_t mb_len = wcrtomb(mb_buf, wc, &out_state);
```

- `wc` 目前的值是 `0x6211`（十进制 25105），这只是一个数字，还不能直接当字符串打印。
- `wcrtomb` 做的是**相反方向的转换**：把宽字符 `wc` 按当前 locale（UTF-8）重新编码成多字节序列，写回 `mb_buf`。
- 这里特意用了一个**全新的、独立的** `out_state`，而不是复用前面解码用的 `state`——因为"从多字节转宽字符"和"从宽字符转多字节"是两个方向相反的操作，各自的状态含义不同，不能混用。
- `wcrtomb` 返回写入的字节数，这里是 `3`（因为"我"字重新编码回 UTF-8 还是 3 个字节：`E6 88 91`）。

```c
mb_buf[mb_len] = '\0';   // 手动补上字符串结尾
```

`wcrtomb` 只负责写入字节内容，不会自动加 `'\0'`，所以必须手动补上，否则后面 `%s` 打印时会越界读到脏数据。

```c
printf("成功识别一个完整字符！共占用 %d 个字节，字符是: %s，码点值 = %d (0x%X)\n",
       nbytes, mb_buf, (int)wc, (int)wc);
```

**最终打印输出**：
```
成功识别一个完整字符！共占用 3 个字节，字符是: 我，码点值 = 25105 (0x6211)
```

函数 `return`，整个执行过程结束。

---

## 整个过程的时间线汇总

| 轮次 | 读到的字节 | mbrtowc 返回值 | state 的变化 | 走的分支 |
|---|---|---|---|---|
| 第1轮 | 0xE6 | -2 | 从"空"变成"已收1/3" | 打印提示，continue |
| 第2轮 | 0x88 | -2 | 从"已收1/3"变成"已收2/3" | 打印提示，continue |
| 第3轮 | 0x91 | 1  | 拼完整，state 完成使命 | 走到最后，转换并打印 |

**贯穿始终的关键点**：三轮循环里调用的是**同一句代码**、**同一个 `state` 变量**，`mbrtowc` 每次都只被喂进去当前这一个新字节。之所以不需要把前面读过的字节重新传一遍，是因为 `state` 在三次调用之间没有被清零，它自己悄悄记住了"进度条走到哪了"。这就是这段代码能够同时正确处理 1 字节的英文字符和 3 字节的中文字符的根本原因。
