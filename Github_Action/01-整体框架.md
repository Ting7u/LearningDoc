# 第 1 节：GitHub Actions 整体框架
> 本节目标：不写新代码，只建立一张"全景图"。看完后你应该能回答：
> **一个 workflow 文件里，到底有哪几块东西？它们是什么关系？**

---
## 1. 一句话理解
> 当仓库里发生某件事（事件），GitHub 自动开一台临时机器（Runner），
> 按你写的清单（Workflow）执行任务。

类比：**外卖订单自动化**

| 现实世界 | GitHub Actions |
|---|---|
| 顾客下单（触发） | Event：你 push 了代码 |
| 订单处理流程（一份菜谱） | Workflow：一个 `.yml` 文件 |
| 厨房里的工作台 | Runner：GitHub 提供的虚拟机 |
| 切菜、炒菜、装盘（几大工序） | Job：一组任务 |
| 每道工序里的具体动作 | Step：一条命令或一个 Action |

---
## 2. 全景图（本节最重要的一张图）
```
 你做了某件事（push / 提 PR / 定时 / 手动点按钮）
                    │
                    ▼
        ┌─────────────────────┐
        │   Event（事件）      │   ← 回答：什么时候运行？
        └──────────┬──────────┘
                   │ 触发
                   ▼
┌───────────────────────────────────────────┐
│  Workflow（工作流）= 一个 .yml 文件          │
│                                           │
│  ┌──────────────┐    ┌──────────────┐     │
│  │   Job A      │    │   Job B      │     │  ← 回答：做哪些大任务？
│  │ (一台机器)    │    │ (另一台机器)  │     │     （默认并行）
│  │              │    │              │     │
│  │  Step 1      │    │  Step 1      │     │  ← 回答：每个任务具体做什么？
│  │  Step 2      │    │  Step 2      │     │     （按顺序执行）
│  │  Step 3      │    │              │     │
│  └──────────────┘    └──────────────┘     │
└───────────────────────────────────────────┘
```

**三个关键问题，对应三层结构：**

```
什么时候跑？  →  on        (Event)
在哪里跑？    →  runs-on   (Runner)
跑什么？      →  jobs → steps
```

---
## 3. 包含关系（从大到小）
```
仓库 (Repository)
 └── .github/workflows/          ← 固定目录，GitHub 只认这里
      ├── hello.yml              ← Workflow 1
      ├── test.yml               ← Workflow 2（一个仓库可以有很多个）
      └── deploy.yml             ← Workflow 3
           │
           ├── on:               ← 触发条件
           └── jobs:             ← 任务集合
                ├── job-1:
                │    ├── runs-on: ...   ← 用哪台机器
                │    └── steps:         ← 步骤列表
                │         ├── - step 1
                │         └── - step 2
                └── job-2:
                     └── ...
```

**记住这个规律：每往里一层，范围就更小。**

| 层级       | 数量关系                        |
| -------- | --------------------------- |
| 仓库       | 1 个仓库 → 多个 workflow         |
| Workflow | 1 个 workflow → 多个 job       |
| Job      | 1 个 job → 多个 step           |
| Step     | 1 个 step → 一条命令 或 一个 Action |

---
## 4. 用你刚跑通的 hello.yml 对照全景图
```yaml
name: Hello World                  # ① Workflow 的名字

on: push                           # ② Event：什么时候跑

jobs:                              # ③ 所有 Job 的容器
  say-hello:                       # ④ 一个 Job（名字自己起）
    runs-on: ubuntu-latest         # ⑤ Runner：在哪跑
    steps:                         # ⑥ 这个 Job 的步骤列表
      - name: 打印问候              # ⑦ Step 1
        run: echo "Hello!"

      - name: 查看当前环境          # ⑧ Step 2
        run: |
          uname -a
          date
```

对应关系：

```
① name      →  给 workflow 起名（显示在 Actions 页面）
② on        →  【事件】
③ jobs      →  【任务集合】
④ say-hello →  【一个 Job】
⑤ runs-on   →  【Runner】
⑥ steps     →  【步骤列表】
⑦ ⑧         →  【两个 Step】
```

**整个文件其实就 3 块：`on` + `jobs`（里面是 `runs-on` + `steps`）。**
其他一切（环境变量、密钥、缓存、矩阵……）都是在这个骨架上"加料"。

---
## 5. 运行时发生了什么（时间线）

```
你                         GitHub
│                            │
│  git push                  │
├───────────────────────────►│
│                            │ ① 发现 push 事件
│                            │ ② 扫描 .github/workflows/ 下所有 yml
│                            │ ③ 找到 on: push 的 workflow，触发
│                            │ ④ 为每个 Job 分配一台全新的虚拟机
│                            │ ⑤ 虚拟机里依次执行每个 Step
│                            │ ⑥ 运行结束，虚拟机销毁
│                            │
│  Actions 页面看结果  ◄──────┤ ⑦ 展示日志：成功 ✅ / 失败 ❌
```

两个要点：
1. **Runner 是临时的**：每次运行都是一台干净的新机器，用完即销毁。所以每次都要重新拉代码、装依赖。
2. **每个 Job 独占一台机器**：Job A 和 Job B 默认互不干扰、同时运行。

## 6. 还有一个角色：Action（插件）
在 Step 里，你有两种写法：

```yaml
steps:
  # 写法一：run —— 自己写命令
  - run: echo "Hello"

  # 写法二：uses —— 直接用别人写好的现成功能
  - uses: actions/checkout@v4
```

```
Step 的两种形态
 ├── run:   你自己写 shell 命令
 └── uses:  调用 Action（别人封装好的"插件"）
```

> `actions/checkout` 的作用是"把仓库代码下载到虚拟机里"。
> 因为虚拟机是干净的，默认里面没有你的代码，所以几乎每个 workflow 的第一步都是它。
> 这里先混个眼熟，后面会专门讲。

## 7. 术语速查表

| 术语       | 一句话         | 对应 yml 里的      |
| -------- | ----------- | -------------- |
| Workflow | 一个自动化流程     | 整个 `.yml` 文件   |
| Event    | 触发条件        | `on:`          |
| Job      | 一组任务，占用一台机器 | `jobs:` 下的每一项  |
| Runner   | 执行任务的虚拟机    | `runs-on:`     |
| Step     | 最小执行单元      | `steps:` 下的每一项 |
| Action   | 可复用的现成插件    | `uses:`        |

---
## 8. 本节小结
1. GitHub Actions = **事件触发 → 临时机器 → 执行步骤**
2. 一个 workflow 文件只有三块核心：**`on`（何时）、`runs-on`（哪里）、`steps`（做什么）**
3. 层级关系：**Workflow ⊃ Job ⊃ Step**
4. Step 有两种：`run`（命令）和 `uses`（现成 Action）
