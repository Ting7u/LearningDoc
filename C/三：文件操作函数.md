# C 语言文件操作完全指南：`<stdio.h>` vs `<unistd.h>`

> 覆盖范围：`<stdio.h>`（带缓冲的高层 I/O）+ `<unistd.h>`/`<fcntl.h>`（无缓冲的系统调用级 I/O）。
> 每个函数：原型 → 参数 → 返回值 → 例子 → 细节 → 坑点 → 内存/内核流向图。

---

## 0. 先建立一个全局图景：数据到底经过了几层

这是理解本文档所有内容的前提。C 程序读写文件，数据实际上要经过 3 层：
![[Pasted image 20260924233211.png]]![[Pasted image 20260924233320.png]]
**核心结论（后面反复用到）：**
- `<unistd.h>` 里的 `read()`/`write()` 是系统调用，直接和内核的 page cache 打交道，没有用户态缓冲区——每调用一次就是一次用户态到内核态的切换（开销大）。
- `<stdio.h>` 里的 `fread()`/`fwrite()`/`fprintf()`/`fgetc()` 等函数，在 `read()`/`write()` 之上包了一层用户态缓冲区（`FILE` 结构体内部的 `buf`），目的就是减少系统调用次数——攒够一块（默认通常 4KB/8KB）再真正调用一次 `read`/`write`。
- 所以"数据从磁盘到你的变量"完整链路是：磁盘 → 内核 page cache → (read 系统调用) → stdio 用户态缓冲区 → (fread 内存拷贝) → 你的变量。

---
## Part 1：`<unistd.h>` + `<fcntl.h>`（无缓冲、系统调用级）

这一层函数的特点：**每次调用都是一次真正的系统调用**，返回值几乎都用 `int`/`ssize_t`，出错统一通过全局变量 `errno` 表达（返回 -1）。

## 1.1 `open()` —— 真正头文件是 `<fcntl.h>`

```c
#include <fcntl.h>
int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);
```

**参数：**
- `pathname`：文件路径。
- `flags`：位掩码，必须包含以下三者之一：`O_RDONLY`（只读）、`O_WRONLY`（只写）、`O_RDWR`（读写）。可以用 `|` 叠加：
  - `O_CREAT`：不存在则创建（这时必须传第三个参数 `mode`）。
  - `O_EXCL`：配合 `O_CREAT`，若文件已存在则报错（常用于实现"原子创建锁文件"）。
  - `O_TRUNC`：打开时把文件截断为 0 长度。
  - `O_APPEND`：每次 `write` 前自动把文件指针移到末尾（原子操作，多进程追加日志时比"先 lseek 再 write"安全）。
- `mode`：仅当 `O_CREAT` 时生效，八进制权限，如 `0644`，实际生效权限还要和进程的 `umask` 相与。

**返回值：** 成功返回**文件描述符**（一个非负整数，0/1/2 已被 stdin/stdout/stderr 占用，所以正常文件从 3 开始）；失败返回 `-1`，并设置 `errno`。

**例子：**
```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <errno.h>
#include <string.h>

int main() {
    int fd = open("test.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) {
        fprintf(stderr, "open failed: %s\n", strerror(errno));
        return 1;
    }
    // ... 使用 fd
    close(fd);
    return 0;
}
```

**坑点：**
1. **忘记检查返回值 -1**：`open` 失败最常见的原因是路径不存在、权限不足。不检查直接往 `fd=-1` 上 `read/write`，行为未定义（实际上会返回 -1 且 errno=EBADF，但很多人忽略这层判断导致后续逻辑错乱）。
2. **`O_CREAT` 时忘记传 `mode`**：C 语言变参函数不会报错，但传漏 `mode` 会读到栈上的垃圾值当作权限，属于典型的"编译能过、运行时行为随机"的坑。
3. **`umask` 影响实际权限**：你传 `0666` 不代表文件权限就是 `0666`，最终权限是 `mode & ~umask`

**内存/内核图：** `open()` 这一步**不传输任何文件内容**，只是让内核在"打开文件表"里建立一条记录，并返回一个索引号（fd）给用户进程。

```
用户进程                         内核
 fd = open(...)  ─────────────▶  在内核"打开文件表"新建一项
   │                              记录：文件偏移量=0, 访问模式, 指向该文件的 inode
   ▼
 拿到一个整数 fd（比如 3）
```

### 1.2 `read()`

```c
#include <unistd.h>
ssize_t read(int fd, void *buf, size_t count);
```

**参数：**
- `fd`：`open()` 返回的文件描述符。
- `buf`：**调用者提供**的内存地址，读到的数据直接拷贝到这里。
- `count`：最多读多少字节。

**返回值：**
- `> 0`：实际读到的字节数（**可能小于 count**，这是最容易踩的坑，见下）。
- `0`：已到文件末尾（EOF）。
- `-1`：出错，查 `errno`。

**例子：**
```c
char buf[128];
ssize_t n = read(fd, buf, sizeof(buf));
if (n == -1) {
    perror("read");
} else if (n == 0) {
    printf("到达文件末尾\n");
} else {
    printf("实际读到 %zd 字节\n", n);
}
```

**坑点：**
1. **"短读"（short read）**：`read` 返回值经常小于你请求的 `count`，即使文件还没读完（尤其读管道、socket 时非常常见，读普通磁盘文件相对少见但也可能发生，比如被信号中断）。正确做法是循环读，直到拿到你要的字节数或遇到 EOF：
   ```c
   size_t total = 0;
   while (total < count) {
       ssize_t n = read(fd, buf + total, count - total);
       if (n == 0) break;          // EOF
       if (n == -1) {
           if (errno == EINTR) continue; // 被信号中断，重试
           perror("read"); break;
       }
       total += n;
   }
   ```
2. **`buf` 空间不够**：`read` 不会帮你检查 `buf` 实际大小，`count` 传大了就是缓冲区溢出（栈溢出/堆溢出）。
3. **`errno == EINTR`**：被信号打断也会返回 -1，这不是真正的错误，应该重试而不是直接报错退出。

**内存/内核图（这是你问的"哪一步从内核读取到缓冲区"最核心的一张图）：**

```
                内核 page cache                    用户进程
磁盘 ──DMA──▶ ┌──────────────────┐   read()   ┌──────────────┐
             │ 该文件对应的页缓存 │ ─copy_to_user─▶ │ char buf[128] │
             │ (程序看不见这一层) │            │ (你申请的内存) │
             └──────────────────┘            └──────────────┘
```
第一次 `read` 某段数据时，内核可能需要真的从磁盘读到 page cache（较慢，涉及 I/O 中断），然后再从 page cache 拷贝到你的 `buf`（`copy_to_user`）。**如果同一段数据之前被读过，page cache 里还留着，第二次 `read` 就直接命中缓存**，不用碰磁盘，只做一次内核态到用户态的内存拷贝——这也是为什么"重复读同一个文件"通常第二次快很多。

### 1.3 `write()`

```c
#include <unistd.h>
ssize_t write(int fd, const void *buf, size_t count);
```

**参数**：与 `read` 对称，`buf` 是你要写出去的数据源地址，`count` 是想写多少字节。

**返回值**：成功返回**实际写入的字节数**（同样可能小于 `count`，即"短写"）；`-1` 出错。

**例子：**
```c
const char *msg = "hello, kernel\n";
ssize_t n = write(fd, msg, strlen(msg));
if (n == -1) perror("write");
```

**坑点：**
1. **"短写"同样存在**：磁盘文件短写相对少见，但管道/socket 非常常见，健壮代码要循环写：
   ```c
   size_t total = 0, len = strlen(msg);
   while (total < len) {
       ssize_t n = write(fd, msg + total, len - total);
       if (n == -1) { if (errno == EINTR) continue; perror("write"); break; }
       total += n;
   }
   ```
2. **`write` 成功返回 ≠ 数据已经落盘**：`write` 只是把数据拷贝进了内核 page cache，什么时候真正写到磁盘由内核决定（除非用 `O_SYNC` 打开，或者手动调 `fsync(fd)`）。断电场景下，`write` 已返回但数据可能还没落盘。
3. 和 `read` 一样要检查返回值，不能假设 `count == 实际写入字节数`。

**内存/内核图：**

```
用户进程                          内核 page cache                    磁盘
┌──────────────┐   write()      ┌──────────────────┐   稍后由内核    ┌──────┐
│ const char*   │ ─copy_from_user─▶│  标记为"脏页"      │ ─异步刷盘──▶  │      │
│ buf 里的数据   │                │ (dirty page)       │  (writeback)  │      │
└──────────────┘                └──────────────────┘                └──────┘
```
`write()` 系统调用返回时，数据只保证到了 page cache（打上"脏页"标记），**不保证到了磁盘**。想强制落盘要用 `fsync(fd)`（把某个 fd 对应的所有脏页刷盘并等待完成）。

### 1.4 `close()`

```c
#include <unistd.h>
int close(int fd);
```

**参数**：要关闭的文件描述符。
**返回值**：成功 `0`，失败 `-1`。

**例子：**
```c
if (close(fd) == -1) perror("close");
```

**坑点：**
1. **`close` 的返回值也可能是 -1**，很多人从来不检查。原因通常是：之前用 `O_SYNC`/网络文件系统时，`close` 阶段才真正把最后的缓冲刷盘，这时才报出 I/O 错误（比如磁盘满）。**对可靠性要求高的程序应该检查 `close` 的返回值**。
2. **不要对同一个 fd `close` 两次**：第二次会返回 -1（EBADF），如果这个 fd 数值恰好被系统重新分配给了别的文件，第二次 close 会误关到别的文件，这是并发程序里的经典 bug（"double close" / fd 复用问题）。
3. `close` 只是释放"打开文件表"里的这一项，不代表进程退出时不会自动关闭——进程正常退出时内核会自动关闭所有还开着的 fd，但**养成手动 close 的习惯**依然重要，因为 fd 是有限资源（`ulimit -n`），不关会耗尽。

### 1.5 `lseek()`

```c
#include <unistd.h>
off_t lseek(int fd, off_t offset, int whence);
```

**参数：**
- `offset`：偏移量（可正可负）。
- `whence`：基准点：
  - `SEEK_SET`：从文件开头算。
  - `SEEK_CUR`：从当前位置算。
  - `SEEK_END`：从文件末尾算。

**返回值**：成功返回**新的文件偏移量**（从文件开头算起的绝对字节数）；失败 `-1`。

**例子：**
```c
off_t pos = lseek(fd, 0, SEEK_END);   // 移到文件末尾，常用来获取文件大小
printf("文件大小 = %ld\n", (long)pos);

lseek(fd, 0, SEEK_SET);               // 回到开头
lseek(fd, -10, SEEK_CUR);             // 从当前位置往回退 10 字节
```

**坑点：**
1. `lseek` 只是**修改内核里"这个 fd 对应的当前偏移量"这个数字**，不会真的触碰磁盘或读写数据，代价很小。
2. **`lseek` 超过文件末尾再 `write`，中间会产生"空洞文件"（sparse file）**：空洞部分在文件系统层面并不占实际磁盘块，读出来是全 `\0`，但 `ls -l` 显示的文件大小是包含空洞的。这既是特性也是坑——如果你以为"seek 到 1GB 处写一个字节"会真的分配 1GB 磁盘，那就错了；但如果你用 `cp` 之类工具复制这种文件，某些工具会把空洞"实体化"，占用远大于预期的磁盘空间。
3. **管道（pipe）不支持 `lseek`**：对 pipe 的 fd 调用 `lseek` 会返回 -1，errno 是 `ESPIPE`
---
### 1.6 `unlink()`

```c
#include <unistd.h>
int unlink(const char *pathname);
```

**参数**：要删除的文件路径。
**返回值**：成功 `0`，失败 `-1`。

**例子：**
```c
if (unlink("temp.txt") == -1) perror("unlink");
```

**坑点（这是 Unix 文件系统里最经典的一个知识点）：**
- `unlink` 删除的是**目录项（把文件名和 inode 的关联断开）**，而不是直接删数据。inode 内部有一个"引用计数"（硬链接数 + 打开中的 fd 数），只有当**引用计数归零**（没有其他文件名指向它，也没有进程还开着它）时，磁盘空间才会被真正释放。
- 经典技巧：如果一个进程已经 `open()` 了某个文件，之后别的进程把这个文件 `unlink` 掉，**已经打开的那个 fd 仍然可以正常 `read`/`write`**，数据不会立刻消失，直到这个 fd 被 `close`。很多程序用这个特性创建"进程退出自动清理的临时文件"。
- 如果要删除目录，`unlink` 不行，要用 `rmdir()`（本文不展开，因为你问的是"文件"操作）。

## Part 2：`<stdio.h>`（带用户态缓冲区的高层 I/O）

这一层的特点：所有函数操作的是 `FILE*` 指针（不是裸 fd），内部维护了一块用户态缓冲区，**大部分函数不是每次调用就触发系统调用**。

### 2.1 `fopen()` / `fclose()`

```c
#include <stdio.h>
FILE *fopen(const char *pathname, const char *mode);
int fclose(FILE *stream);
```

**`mode` 常用值：**
| mode | 含义 |
|---|---|
| `"r"` | 只读，文件必须存在 |
| `"w"` | 只写，不存在则创建，存在则**清空** |
| `"a"` | 追加写，不存在则创建，写入总是到文件末尾 |
| `"r+"` | 读写，文件必须存在 |
| `"w+"` | 读写，清空或创建 |
| `"a+"` | 读 + 追加写 |
| 加 `"b"`，如 `"rb"` | 二进制模式（Linux 下其实和文本模式一样，但**Windows 下会影响换行符 `\n`↔`\r\n` 的自动转换**，跨平台代码建议总是显式加 `b`） |

**返回值**：成功返回 `FILE*` 指针；失败返回 `NULL`（**注意不是 -1**，这是和 `open()` 最直观的区别之一），同时设置 `errno`。

**例子：**
```c
FILE *fp = fopen("test.txt", "r");
if (fp == NULL) {
    perror("fopen");   // perror 会自动读 errno 并打印可读的错误信息
    return 1;
}
// ... 使用 fp
fclose(fp);
```

**坑点：**
1. **忘记判空**：新手最高频的错误，`fopen` 失败后继续用 `NULL` 指针调用 `fread` 等，直接段错误。
2. **`"w"` 模式会静默清空已有文件**：想追加要用 `"a"`，很多人误用 `"w"` 导致数据丢失。
3. **`fclose` 才会真正 `flush` 缓冲区**：如果程序 `fopen("w")` 写了数据但没调 `fclose`（比如中途 `exit(1)` 或者崩溃），**缓冲区里的数据可能根本没写到文件里**（除非用的是 `stderr` 这种无缓冲流，或者程序正常 `return` 从 `main` 退出触发了 libc 的清理）。这是"我明明写了 fprintf，文件里却是空的"这个经典问题的根源。

**内存图（`fopen` 内部做了什么）：**

```
fopen("test.txt", "r")
   │
   ├─▶ 内部调用 open("test.txt", O_RDONLY) 拿到一个裸 fd
   │
   └─▶ malloc 一个 FILE 结构体，大致包含：
        struct FILE {
            int fd;              // 底层真正的文件描述符
            char *buf;           // 用户态缓冲区指针（malloc 出来的，默认常见 4096 字节）
            size_t buf_size;
            size_t pos;          // 当前在 buf 里读到/写到哪个位置
            size_t data_len;     // buf 里当前有效数据长度
            int eof_flag, error_flag;
            ...
        }
   返回这个 FILE 结构体的地址给你
```

### 2.2 `fread()` / `fwrite()`

```c
size_t fread(void *ptr, size_t size, size_t nmemb, FILE *stream);
size_t fwrite(const void *ptr, size_t size, size_t nmemb, FILE *stream);
```

**参数：**
- `ptr`：数据存放/来源的内存地址。
- `size`：每个元素的大小（字节）。
- `nmemb`：元素个数。
- 实际最多读写 `size * nmemb` 字节。

**返回值**：**成功读/写的"完整元素"个数**（不是字节数！），如果 `size*nmemb` 不能整除，或者中途遇到 EOF/出错，返回值会小于 `nmemb`。想知道到底是 EOF 还是出错，要配合 `feof()`/`ferror()` 判断。

**例子：**
```c
struct Record { int id; char name[32]; };
struct Record recs[10];

size_t n = fread(recs, sizeof(struct Record), 10, fp);
printf("实际读到 %zu 条完整记录\n", n);
if (n < 10) {
    if (feof(fp))       printf("文件提前结束\n");
    else if (ferror(fp)) printf("读取出错\n");
}
```

**坑点：**
1. **返回值单位是"元素个数"不是字节数**，`fread(buf, 1, 100, fp)` 里因为 `size=1` 恰好数值等于字节数，很多人因此产生"fread 返回字节数"的错觉，一旦 `size` 传别的值就会算错。
2. **`fread` 返回值小于 `nmemb` 时不能立刻判定是 EOF**，必须再调 `feof`/`ferror` 才能区分"读完了"还是"读错了"。
3. **不要用 `fread` 的返回值直接和 `nmemb` 比较来判断"文件是不是至少这么长"**——如果文件长度不是 `size` 的整数倍，最后一个不完整的元素会被丢弃且不计入返回值，容易造成数据"莫名其妙丢了几个字节"的错觉。

**内存/内核图（这是你要的"哪一步是自己的缓冲区，哪一步是内核"最关键的一张图）：**

```
第一次 fread(buf, 1, 10, fp)，假设 stdio 缓冲区是空的：

  磁盘/page cache        FILE 内部 buf (4096字节)         你的变量 buf[10]
  ┌──────────┐  read()   ┌─────────────────────┐  memcpy  ┌────────┐
  │ 文件内容   │ ────────▶ │ 一次性读满 4096 字节   │ ───────▶ │ 前10字节 │
  └──────────┘ (1次系统调用)└─────────────────────┘         └────────┘
                            剩余 4086 字节留在这里
                            等下次 fread 用，不用再陷入内核！

第二次 fread(buf2, 1, 10, fp)：

  FILE 内部 buf                          你的变量 buf2[10]
  ┌─────────────────────┐   memcpy      ┌────────┐
  │ 还剩 4086 字节可用     │ ────────────▶ │        │
  └─────────────────────┘  (不发生系统调用！)└────────┘
```
这就是 stdio 缓冲区存在的意义：**第一次 `fread` 触发了一次 `read()` 系统调用，把 4096 字节整块搬进用户态的 `FILE->buf`；后续只要数据还在这块 buf 里，`fread` 只是简单的 `memcpy`，完全不用再进内核**，所以"小块多次读"用 `fread` 比直接用裸 `read()` 快得多。

### 2.3 `fgets()` / `fputs()`

```c
char *fgets(char *s, int size, FILE *stream);
int fputs(const char *s, FILE *stream);
```

**`fgets` 参数**：`s` 是存放地址，`size` 是**缓冲区总大小（包含结尾的 `\0`）**，最多读 `size-1` 个字符，遇到 `\n` 或 EOF 提前停止。`\n` 本身**会被保留**在结果里（这是和很多其他语言的 `readline` 不同的地方）。

**返回值**：成功返回 `s` 本身；**到达文件末尾且没读到任何字符**时返回 `NULL`。

**例子：**
```c
char line[256];
while (fgets(line, sizeof(line), fp) != NULL) {
    // 手动去掉末尾的换行符
    size_t len = strlen(line);
    if (len > 0 && line[len - 1] == '\n') line[len - 1] = '\0';
    printf("读到一行: %s\n", line);
}
```

**坑点：**
1. **`size` 传错会栈溢出**：`fgets` 内部不知道你的 `s` 实际能装多少，完全依赖你传的 `size` 参数，如果传大了（比如数组实际 10 字节你传了 256），就是经典缓冲区溢出。
2. **一行内容超过 `size-1` 会被截断**，剩下的部分留在 stdio 缓冲区里，**下一次 `fgets` 会继续读这一行剩下的部分**（不会自动跳到下一行），如果你没意识到这点，很容易把"超长的一行"错误地当成"两行"处理。
3. **末尾是否有 `\n`，取决于文件最后一行是不是以换行符结尾**：如果文件最后一行没有 `\n`（很多文本编辑器保存时会加，但不是100%），`fgets` 返回的最后一段就不带 `\n`，用固定逻辑"去掉最后一个字符"的代码在这里会误删有效字符，要先判断。

---

### 2.4 `fgetc()` / `fputc()` / `getc()` / `putc()`

```c
int fgetc(FILE *stream);
int fputc(int c, FILE *stream);
int getc(FILE *stream);   // 效果同 fgetc，常实现为宏，速度更快但可能多次求值 stream 参数
int putc(int c, FILE *stream);
```

**返回值细节（坑点本身）**：`fgetc` 返回类型是 `int` 而不是 `char`！**原因**：一次只能返回 0~255 的字符值，或者用 `EOF`（通常定义为 `-1`）表示结束/出错，如果返回类型是 `char`，在某些平台上 `char` 是有符号的，字符值 `0xFF`（对应 -1）会和 `EOF` 混淆，导致文件读到一半误判为结束。

**坑点例子（新手最常见的 bug 之一）：**
```c
// 错误写法：
char c;                      // ❌ 用 char 接收
while ((c = fgetc(fp)) != EOF) {  // 如果 c 是有符号 char，某字节恰好是 0xFF 时会被误判为 EOF
    putchar(c);
}

// 正确写法：
int c;                        // ✅ 必须用 int
while ((c = fgetc(fp)) != EOF) {
    putchar(c);
}
```

**逐字节读的性能坑**：每次 `fgetc` 虽然不一定触发系统调用（因为走的是 stdio 缓冲区），但函数调用本身+边界检查的开销，在处理大文件时循环几百万次会比 `fread` 整块读明显慢，追求性能应优先 `fread`。

---

### 2.5 `fprintf()` / `fscanf()`

```c
int fprintf(FILE *stream, const char *format, ...);
int fscanf(FILE *stream, const char *format, ...);
```

**返回值**：`fprintf` 成功返回**实际写出的字符数**；`fscanf` 返回**成功匹配并赋值的参数个数**（不是字符数！），如果一个都没匹配上或提前 EOF，返回 `EOF`。

**例子：**
```c
fprintf(fp, "%d,%s\n", 42, "hello");

int id; char name[32];
int matched = fscanf(fp, "%d,%31[^\n]", &id, name);
if (matched != 2) {
    printf("格式不匹配，只成功解析了 %d 个字段\n", matched);
}
```

**坑点：**
1. **`fscanf` 几乎是 C 里最容易被滥用出安全问题的函数之一**：`%s` 不限制长度会导致缓冲区溢出，一定要写成 `%31s`（配合数组大小减一）这种带宽度限制的形式。
2. **`fscanf` 返回值一定要检查**，实际项目里"读取格式和预期不一致"是非常常见的情况（比如文件损坏、编码错误），不检查返回值会导致后续用到未初始化的变量。
3. `%s`/`%d` 等会**自动跳过前导空白（包括换行符）**，但 `%c` 不会，这经常导致"明明 `fscanf` 读完一个数字，下一次读字符却读到了残留的换行符"这种迷惑 bug。

---

### 2.6 `fseek()` / `ftell()` / `rewind()` / `fgetpos()` / `fsetpos()`

```c
int fseek(FILE *stream, long offset, int whence);
long ftell(FILE *stream);
void rewind(FILE *stream);
int fgetpos(FILE *stream, fpos_t *pos);
int fsetpos(FILE *stream, const fpos_t *pos);
```

`fseek`/`ftell` 是 `lseek` 在 stdio 层的对应版本，`whence` 取值同样是 `SEEK_SET`/`SEEK_CUR`/`SEEK_END`。

**返回值**：`fseek` 成功 `0`，失败 `-1`；`ftell` 成功返回当前偏移量，失败返回 `-1L`；`rewind` 无返回值（内部等价于 `fseek(fp, 0, SEEK_SET)` 并清除 `error`/`eof` 标志，这一点 `fseek` 本身不会自动清除 `error` 标志，是个细节差异）。

**例子（常见的"获取文件大小"写法及其坑）：**
```c
fseek(fp, 0, SEEK_END);
long size = ftell(fp);
rewind(fp);   // 或 fseek(fp, 0, SEEK_SET)
printf("文件大小: %ld 字节\n", size);
```

**坑点：**
1. **`long` 在 32 位平台上通常只有 4 字节**，`ftell` 对超过 2GB 的大文件会溢出（返回错误的负数）。需要大文件支持要用 `ftello`/`fseeko`（返回类型是 `off_t`），或者直接用 `stat()` 拿文件大小。
2. **`fseek` 用在以 `"a"`（追加）模式打开的文件上效果有限**：无论怎么 `fseek`，下一次 `write` 总是会先跳到文件末尾（`O_APPEND` 语义），这是很多人以为"追加模式下 seek 到中间能改内容"结果发现改不了的原因。
3. **对文本模式文件（尤其 Windows 平台，`\r\n` 转换）`ftell` 返回值不能简单当作"字符个数"来做偏移量算术**，只应该原样传回 `fseek`，不要自己加减。

---

### 2.7 `feof()` / `ferror()` / `clearerr()`

```c
int feof(FILE *stream);
int ferror(FILE *stream);
void clearerr(FILE *stream);
```

**坑点（这是新手 while 循环最常见的错误来源）：**
```c
// ❌ 错误写法：feof 要在读操作"之后"检查，不能提前判断
while (!feof(fp)) {
    fgets(line, sizeof(line), fp);
    
    printf("%s", line);   
                           // 会被多打印一次！
}

// ✅ 正确写法：用读操作的返回值本身来控制循环
while (fgets(line, sizeof(line), fp) != NULL) {
    printf("%s", line);
}
```
原因：`feof()` 反映的是"**上一次**读操作是否遇到了 EOF"，而不是"预测下一次读会不会遇到 EOF"。用 `!feof(fp)` 做循环条件，会在真正读到 EOF 之前多循环一次（这一次读操作会失败，但循环体已经用了失败前的旧数据）。**正确姿势永远是直接判断读函数本身的返回值**（`fgets` 返回 `NULL`，`fread` 返回值不足，`fscanf` 返回 `EOF` 等）。

---

### 2.8 `setvbuf()` / `setbuf()` / `fflush()`

```c
int setvbuf(FILE *stream, char *buf, int mode, size_t size);
void setbuf(FILE *stream, char *buf);   // setvbuf 的简化版
int fflush(FILE *stream);
```

**`mode` 三种取值：**
- `_IOFBF`：全缓冲（默认，普通磁盘文件用这个，攒满一整块才真正 I/O）。
- `_IOLBF`：行缓冲（遇到 `\n` 就触发真正 I/O，终端交互场景常用，比如 `stdout` 连到终端时默认是这个）。
- `_IONBF`：无缓冲（每次调用立刻触发系统调用，`stderr` 默认就是这个，为了让错误信息不被缓冲延迟显示）。

**`fflush(stream)`**：把 stdio 用户态缓冲区里**还没写出去的数据强制推给内核**（本质上就是替你调用一次 `write()`），但注意——**`fflush` 只保证数据到了内核 page cache，并不保证到了磁盘**（想保证落盘还要 `fsync`，这一点和前面 `write()` 的坑是一致的）。

**例子：**
```c
setvbuf(fp, NULL, _IONBF, 0);   // 关闭缓冲，每次写立刻触发系统调用（调试时常用，方便崩溃前的日志不丢）

fprintf(fp, "important log\n");
fflush(fp);                      // 确保这条日志已经交给了内核，即使程序接下来崩溃
```

**坑点：**
1. **`fflush(stdin)` 是未定义行为**（C 标准只对输出流定义了 `fflush` 的行为），很多教程里用 `fflush(stdin)` 清空输入缓冲区（比如处理 `scanf` 残留的换行符），这在部分编译器上"恰好能用"，但**不可移植、不保证正确**，标准做法是用循环读掉残留字符，或者用 `fgets` 代替 `scanf`。
2. **`setvbuf` 必须在对这个 `FILE*`做任何读写操作之前调用**，一旦已经读写过再调用行为未定义。
3. **`printf` 系列默认是"行缓冲"还是"全缓冲"取决于是不是连接到终端**：直接在终端跑程序，`stdout` 是行缓冲，`\n` 就会刷新；但一旦你把输出重定向到文件（`./a.out > out.txt`），`stdout` 自动变成全缓冲，`printf` 不再实时刷新，这是"为什么直接运行能立刻看到输出、重定向到文件却要等程序结束才写入"的根本原因。

---

### 2.9 `remove()` / `rename()`

```c
int remove(const char *pathname);
int rename(const char *oldpath, const char *newpath);
```

- `remove`：删除文件（如果是普通文件，效果等价于 `unlink`；如果是空目录，等价于 `rmdir`——这一点实现依赖具体系统，但 POSIX 系统上通常如此）。
- `rename`：重命名/移动文件。

**坑点：**
- `rename` **在同一个文件系统内部是原子操作**（要么完全成功要么完全不变，不会出现"改了一半"的中间状态），这个特性常被用来实现"安全写文件"模式：先写到临时文件 `xxx.tmp`，写完并 `fsync` 后再 `rename` 成正式文件名，即使中途崩溃，正式文件名要么是旧内容要么是新内容，不会是写了一半的坏文件。
- 但**跨文件系统（比如 `/tmp` 和 `/home` 挂载在不同分区）时 `rename` 会失败**，返回 `-1`，errno 是 `EXDEV`，这时无法原子完成，只能退化成"复制+删除"。

---

### 2.10 `tmpfile()` / `tmpnam()`（简要，附安全提示）

```c
FILE *tmpfile(void);
char *tmpnam(char *s);   // 已被标记为不安全，不建议使用
```

- `tmpfile()`：创建一个**匿名临时文件**并以 `"wb+"` 模式打开，这个文件在 `fclose` 或程序退出时会被**自动删除**（内部原理正是前面 1.6 节讲的"unlink 后 fd 仍可用"的技巧：创建后立刻在内部 unlink 掉文件名，只留 fd）。
- `tmpnam()`：只生成一个"理论上不重复"的文件名字符串，**不负责创建文件**，存在明显的 TOCTOU（Time-Of-Check-To-Time-Of-Use）竞态漏洞——你拿到名字和你真正 `fopen` 它之间，别的进程可能已经抢先创建了同名文件（甚至是攻击者故意创建的符号链接），多个标准/编译器都已经标记它为不安全，**应该直接用 `tmpfile()` 或平台提供的 `mkstemp()`**。

## Part 3：混用 stdio 和裸 fd 的陷阱（`fileno` / `fdopen`）

```c
int fileno(FILE *stream);      // 从 FILE* 拿到底层的裸 fd
FILE *fdopen(int fd, const char *mode);  // 反过来，给裸 fd 套上一层 stdio 缓冲区
```

**最大的坑：混用会导致数据顺序错乱。**

```c
FILE *fp = fopen("test.txt", "w");
fprintf(fp, "AAAA");            // 这行只是写进了 stdio 用户态缓冲区，还没进内核！
int fd = fileno(fp);
write(fd, "BBBB", 4);           // write 是裸系统调用，直接绕过 stdio 缓冲区写进了内核
fclose(fp);                     // fclose 才把 "AAAA" 从缓冲区 flush 出去

// 实际文件内容很可能是: BBBBAAAA  ← 顺序和你代码里写的完全相反！
```

**原因图解：**
```
             stdio 用户态缓冲区                    内核
fprintf(fp,"AAAA")  ──写入──▶ [AAAA............]   （还没到这里）
write(fd,"BBBB")    ─────────────直接跳过缓冲区────▶ [BBBB]  （先到了内核）
fclose(fp) 触发flush ──写入──▶                    ──▶ [BBBB][AAAA]  （后到）
```

**规则**：**同一个文件，要么全程只用 `FILE*` 系列函数，要么全程只用裸 fd 系列函数，不要混用**；如果必须混用（比如某个库只给你 fd，你想用 `fprintf` 的便利性），每次切换前必须 `fflush(fp)`（stdio → 裸 fd 方向）或者对裸 fd 不做任何缓冲（fd → stdio 方向本身较安全，因为 `fdopen` 之后新的 stdio 层会重新开始管理缓冲）。

## Part 4：综合实战——用两种方式各写一个"复制文件"，并对比

### 4.1 用 `<unistd.h>` 裸系统调用实现

```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int copy_raw(const char *src, const char *dst) {
    int in = open(src, O_RDONLY);
    if (in == -1) { perror("open src"); return -1; }

    int out = open(dst, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (out == -1) { perror("open dst"); close(in); return -1; }

    char buf[4096];
    ssize_t n;
    while ((n = read(in, buf, sizeof(buf))) > 0) {
        ssize_t written = 0;
        while (written < n) {               // 处理短写
            ssize_t w = write(out, buf + written, n - written);
            if (w == -1) { perror("write"); goto fail; }
            written += w;
        }
    }
    if (n == -1) { perror("read"); goto fail; }

    close(in); close(out);
    return 0;
fail:
    close(in); close(out);
    return -1;
}
```
每一轮循环：`open` 建立两个"内核打开文件表"条目 → `read` 触发一次系统调用把最多 4096 字节从**内核 page cache**拷进 `buf` → `write` 触发一次系统调用把 `buf` 里的内容拷进**目标文件对应的 page cache**（标记为脏页，内核异步刷盘）。全程**没有用户态额外缓冲**，`buf` 本身就是唯一的中转站。

### 4.2 用 `<stdio.h>` 实现（更简洁）

```c
#include <stdio.h>

int copy_stdio(const char *src, const char *dst) {
    FILE *in = fopen(src, "rb");
    if (!in) { perror("fopen src"); return -1; }

    FILE *out = fopen(dst, "wb");
    if (!out) { perror("fopen dst"); fclose(in); return -1; }

    char buf[4096];
    size_t n;
    while ((n = fread(buf, 1, sizeof(buf), in)) > 0) {
        if (fwrite(buf, 1, n, out) != n) {
            perror("fwrite");
            fclose(in); fclose(out);
            return -1;
        }
    }
    if (ferror(in)) { perror("fread"); }

    fclose(in);   // 这里才真正 flush + close
    fclose(out);
    return 0;
}
```
`fread`/`fwrite` 底层其实也是调用 `read`/`write`，但多了一层"`FILE` 自己的 buf"：如果你把上面 `buf[4096]` 改成 `buf[16]`（每次只读写 16 字节），**裸系统调用版本性能会明显下降**（因为每 16 字节就要陷入一次内核），**而 stdio 版本几乎不受影响**（因为 `FILE` 内部还有一层默认 4096 字节左右的缓冲区在扛着，真正的 `read`/`write` 系统调用次数不受你传的 `n` 影响，只受内部缓冲区大小影响）——这正是 stdio 层存在的意义。

## 附：速查表

| 功能 | `<unistd.h>`/`<fcntl.h>`（无缓冲） | `<stdio.h>`（有缓冲） |
|---|---|---|
| 打开 | `open()` → 返回 `int fd`，失败 `-1` | `fopen()` → 返回 `FILE*`，失败 `NULL` |
| 读 | `read()` → 返回实际字节数，0=EOF，-1=错误 | `fread()`/`fgets()`/`fgetc()`/`fscanf()` |
| 写 | `write()` | `fwrite()`/`fputs()`/`fputc()`/`fprintf()` |
| 定位 | `lseek()` → `off_t` | `fseek()`/`ftell()` → `long`（大文件用 `fseeko`/`ftello`） |
| 关闭 | `close()` | `fclose()`（内部会先 flush） |
| 删除 | `unlink()` | `remove()` |
| 强制落盘 | `fsync(fd)`（真正等待写盘完成） | 先 `fflush(fp)`（到内核），再 `fsync(fileno(fp))`（到磁盘） |
| 出错查询 | 全局 `errno` + `perror()`/`strerror()` | `ferror(fp)`/`feof(fp)`，同样可配合 `errno` |
| 典型使用场景 | 需要精细控制、和 socket/pipe 一起用、写底层库 | 日常文本/二进制文件处理，追求开发效率 |
